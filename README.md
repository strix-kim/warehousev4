# ARGO Warehouse

Внутренняя система учёта AV-оборудования ARGO Media.

Главный сценарий один: сотрудник открывает систему, собирает список оборудования
на мероприятие, сохраняет его и выгружает Excel — и едет на выезд. Всё остальное
подчинено этому сценарию.

## Что умеет

- **Каталог оборудования** — поиск, фильтры, постраничная загрузка, превью модели.
- **Создание оборудования** — серийные единицы и количественные позиции.
- **Редактор списков** в двух режимах: «по единицам» (конкретные серийные номера)
  и «по количеству» (абстрактный план). Смешанный список сохраняет реальные позиции,
  а не сводится к плану.
- **Жизненный цикл списка** `черновик → подтверждён → выдан → возвращён` с историей
  этапов и движения оборудования. Переходы проверяет сервер, не интерфейс.
- **Экспорт в Excel** — файл собирается с нуля, без внешних библиотек.
- **Два языка интерфейса**: русский и узбекский.
- **Вход** через Supabase Auth; все маршруты за гейтом сессии.

## Стек

React 19 · TypeScript 5.9 · Vite 7 · Supabase (Postgres, RLS, Auth, Data API) ·
хостинг Vercel. Точные версии — [`docs/system/tooling.md`](docs/system/tooling.md).

Права, видимость и целостность данных живут в Postgres, а не в React: проверка
в интерфейсе здесь считается подсказкой пользователю, а не защитой.

## Локальный запуск

```bash
npm install
cp .env.example .env   # заполнить двумя публичными значениями Supabase
npm run dev            # http://localhost:5180/
```

Порт закреплён жёстко: занят — команда падает с ошибкой, а не переезжает на соседний.

В `.env` нужны адрес проекта и публичный ключ Supabase:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-publishable-or-anon-key
```

Всё, что начинается с `VITE_`, попадает в бандл и читается любым посетителем сайта.
Публикуемый ключ Supabase там уместен, `service_role` и любые пароли — никогда.
Реальный `.env` в git не попадает.

## Проверка

```bash
npm run check   # tsc -b — типы
npm run build   # tsc -b && vite build — сборка
```

Это все автоматические гейты, которые есть в проекте: линтера, тестов и CI пока нет.

## Структура

```
src/react/          весь код приложения (23 файла)
  app/              оболочка и маршрутизация
  features/         фичи: auth, equipment, lists, home
  components/       общие компоненты
  lib/              supabase, кэш, локализация, справочники
  generated/        сгенерированные данные (карта изображений)
supabase/migrations/  схема базы — единственный способ её менять
scripts/              SQL-скрипты и утилита загрузки изображений
docs/                 документация проекта
```

Всё, что лежит в `src/`, работает: предыдущая версия продукта на Vue удалена
из дерева и живёт только в истории git.

## Изображения

Каталог содержит 176 оптимизированных WebP для 217 моделей; для 41 неоднозначной
позиции используется категорийная пиктограмма — это осознанно лучше, чем показать
похожее, но неверное устройство. Источники — `public/equipment-images/manifest.json`,
пересборка — `npm run images:equipment` (на macOS нужны `sips` и `cwebp`).

## Кэш

Страницы оборудования и списков кэшируются в браузере на 10 минут, справочник
категорий — на 24 часа; после записи соответствующий кэш сбрасывается. При сетевой
ошибке отдаётся последнее успешное значение — это ускорение, а не офлайн-режим:
сохранять изменения без сети приложение не умеет.

## Чего в продукте нет

События, точки монтажа, отчёты, управление ролями и демонстрационный UI Kit были
в предыдущей Vue-версии и в новый продукт **не входят**. Отдельно стоит знать, что
автоматических тестов и CI нет, а настройки Auth рассчитаны на закрытый контур:
система внутренняя, внешних пользователей у неё нет.
