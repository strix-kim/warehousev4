## Грабли и решения

| Симптом | Причина | Решение |
|---|---|---|
| Scout «снял и вернул» строку, а `created_by` сменился | INSERT-политика требует `created_by = auth.uid()`, UPDATE-политики нет | в брифе на «снять и вернуть» сначала читать политики таблицы; строки с `created_by = null` через REST не восстановить — только `execute_sql` |
| `git push origin $H:refs/heads/main` → «src refspec …efs/heads/main» | zsh читает `$H:r` как модификатор | `"${H}:refs/heads/main"` |
| Scout проверяет этап, а кодеры уже правят дерево под следующий | `vite preview` и `npm run build` делят `dist` | копия сборки в scratchpad, `vite preview --outDir <копия>`; гейт слияния — сборка из `git archive` |
| Кодер для замера сделал `git stash` при живом соседе | файлы соседа исчезают из дерева | в брифе параллельным кодерам `git stash` запрещать явно |
| Слить этап в `main`, не трогая дерево под кодерами | `git switch main` унёс бы их правки | `git push origin "<sha>:refs/heads/main"` + `git branch -f main <sha>` (только fast-forward) |
