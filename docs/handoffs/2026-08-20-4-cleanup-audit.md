# Handoff: 2026-08-20 (сессия 4) — легаси вычищен, архитектура проаудирована

Сессия начиналась с предложения агента взять веху 2 («приложение перестаёт падать
молча»), но прораб перебил цель своей и задал порядок: **сначала вычистить весь
легаси-Vue, потом провести полноценный аудит архитектуры, и только после этого —
фиксы и фичи.** Обе задачи закрыты в одну сессию, обе выкачены в прод.

Порядок оказался правильным не по вкусу, а по механике: аудит по дереву, где 88%
файлов — мусор, читал бы этот мусор. Каждый `grep` вытаскивал бы Vue, каждый
счётчик строк врал, агенты жгли бы контекст на файлах, которых через час не будет.

границы модулей. Механизм отказа общий и коварный: правка одной копии не даёт ни
ошибки типов, ни падения сборки.

## Следующий шаг

**Починить HIGH из аудита: повторное «Сохранить» на `/lists/new` создаёт ВТОРОЙ
список вместо обновления первого.**

Механизм: `persistList` (`ListEditorPage.tsx:377`) ветвится по `listId` из
`useParams`, но маршрут `/lists/new` объявлен без параметра (`App.tsx:33`) — там
`listId` пуст навсегда. Единственное место, где оседает id созданной записи, —
`savedId` (`:378`), и он гасится при ЛЮБОЙ правке полей (девять мест) и состава
(четыре). Навигации после создания в файле нет.

Сценарий бытовой: сохранил → поправил букву в названии → сохранил → в базе два
списка. Три правки дают четыре. Удаление прибито к одной почте
(`equipment_lists_delete_for_default_account`), поэтому обычный сотрудник дубли не
уберёт.

Лечится `navigate('/lists/:id/edit', {replace: true})` после создания. **Тем же
коммитом обязательно править `02-features.md:499`**, где сохранение названо
«идемпотентным в пределах экрана»: документация утверждает исправность ровно там,
где дефект, а доке в этом проекте верят.

**Почему первым.** Дефект спит только потому, что в проде **ноль сохранённых
списков** — функцией ещё не пользовались. Он сработает на первом же реальном
выезде, то есть на главном сценарии продукта. Рядом в тех же двух файлах лежат три
medium-правки из шага 1 отчёта (отказ NOT NULL при очистке «Локации», показ числа
единиц из ответа RPC вместо клиентского, счётчик смешанного списка) — их разумно
взять тем же заходом.

Начинать с Plan Mode не обязательно: правка точечная, план — в отчёте.

**Перед кодом стоит наконец потратить пять минут на то, что не сделано третью
сессию подряд: прораб открывает приложение сам.** Живой прогон агента это не
заменяет — он проверяет, что код работает, а не что продуктом удобно пользоваться.

## Грабли и решения

| Симптом | Причина | Решение |
|---|---|---|
| `grep`/`find` внезапно отвечают «No such file or directory» на существующих путях | рабочий каталог Bash **сохраняется между вызовами**: предыдущая команда сделала `cd` в scratchpad | не полагаться на «текущий» каталог через несколько вызовов; либо `cd` в корень в той же команде, либо абсолютные пути. Хэндоф с3 предупреждал про `cd`, но про его липкость — нет |
| `perl -pi -e` по списку файлов: «Can't open <весь список>» | **zsh не разбивает переменную по словам** при подстановке, в отличие от bash: `$FILES` приехал одним аргументом | перечислять файлы явно либо `${=FILES}`; проверять результат, а не код возврата — первый прогон «отработал» без ошибки и не сделал ничего |
| Перенос файла с врезкой сломал 20 ссылок с номерами строк | врезка в начало сдвинула нумерацию; regex ловил только якоря вида `имя.md:NN` | сдвиг вычислен фактически (+16, не +15 «на глаз»), каждый якорь проверен по содержимому строки. **Голые якоря вида `` `:56` `` рядом со ссылкой шаблон не ловит** — искать отдельно, один такой пережил первую правку и нашёлся только на финальной сверке |
| Playwright «не смог войти», хотя пароль верный | селектор `form button` брал **кнопку-глаз** у поля пароля: кнопка «Войти» идёт позже и не имеет `type="submit"` | брать по роли и тексту (`getByRole('button', {name: /войти/i})`), а не по позиции в форме. Диагноз дал перечень всех кнопок с их `type` и `aria-label` |
| Ожидание «файл удалён» по коду 404 висит до таймаута | SPA-рерайт в `vercel.json` отдаёт `index.html` на любой путь — **404 в этом проекте не бывает** | проверять не код, а тип и размер ответа: `text/html` + 916 байт вместо `spreadsheetml` + 68 КБ. Это же и подтверждение известного долга про белый экран после выкатки |
| В roadmap записана как будущая идея функция, которая уже наполовину сделана | идеи переносились из аудита без сверки с текущей схемой | перед записью «надо сделать X» — `grep` по коду и выписка колонок из базы. `client_name` и `venue` уже существуют, поля есть в редакторе; в очереди осталась только привязка ответственного |
| Скилл предупреждает: `perl` портит кириллицу | `perl -CSD` даёт мохибейк на UTF-8 | проверено фактически: без `-CSD` и с ASCII-паттернами perl работает побайтово и кириллицу не трогает — все семь файлов остались UTF-8. Но правило разумное: для правки русского текста — только `Edit`/`Write`/`python3` |
