# Handoff: 2026-08-20 (сессия 1) — постановка харнесса

Первая сессия проекта. Цель поставлена прорабом: перенести на ARGO Warehouse систему
ведения работ, отлаженную за сто сессий на соседнем Roblox-проекте, адаптировав её под
React/Supabase. Сессия объявлена не входящей в счёт продуктовых сессий, но номер `1`
взят — с него начинается сквозная нумерация этого проекта.

## Находки в продукте

Побочный, но самый ценный результат сессии. Всё — с якорями в библии, всё — в backlog.

**Отказоустойчивость.** ErrorBoundary в проекте нет вообще, при этом все шесть страниц
грузятся лениво. Выкатка нового билда при открытой у пользователя вкладке → старые
чанки исчезли → SPA-рерайт отдаёт HTML вместо JS → отклонённый промис внутри `Suspense`
без границы → белый экран всего приложения. Плюс ни одного `console.*` во всём
`src/react` и нет сборщика ошибок: отказ у пользователя невидим.

**Фолбэк, который переписывает данные.** Загрузка списков уходит в legacy-ветку на
ЛЮБОЙ ошибке, без фильтра по коду — в отличие от соседних функций того же файла,
которые гейтятся по кодам отсутствия функции. Сетевой сбой или 401 → все списки
получают статус «черновик», выданные прячутся, **и это кэшируется на 10 минут.**
Две копии кода.

**Шесть дыр «клиенту не верим»**, из них две самые опасные:

- сервер вставляет brand/model позиции дословно из клиентского JSON, проверяя только
  существование `equipment_id`, а расчёт дефицита джойнит склад по этому же
  денормализованному тексту — расхождение в написании даёт фантомную нехватку;
- проверка уникальности серийного номера обёрнута в `try/catch`, где `catch` возвращает
  «дубля нет»: она отваливается не только в гонке двух вкладок, а при ЛЮБОМ сбое запроса.

Отдельно зафиксировано, что переходы статусов списка — **НЕ дыра**: клиентские гварды
там честно дублируются серверными проверками. Это записано явно, чтобы пункт не ушёл
в «не проверено».

**Схемы нет в репозитории.** DDL базовых таблиц (`users`, `equipment`, `equipment_lists`
и остальные) отсутствует — прод-схема из git не восстанавливается. Вся библия по
колонкам честно помечена как реконструкция по TypeScript-типам, а не выписка из базы.
Плюс два независимых механизма SQL (`supabase/migrations/` против `scripts/*.sql`) с
неизвестным порядком применения, от которого зависит, действует ли отзыв прав на
таблицу пользователей.

**`revoke all on public.users` держится на `security definer`.** Авторизация цела именно
потому, что функции проверки членства объявлены `security definer`. Эти два факта
записаны РЯДОМ на каждой странице, где упоминается хоть один: агент, «починивший» revoke
в отрыве от второго факта, уронит вход всем пользователям.

- **Якоря:** две независимые проверки, 458 и 690 ссылок вида `файл:строка`. После
  правочного прохода прогнан повторный контроль.

  ни там, ни там.

### НЕ проверено

- **Прораб доки не читал** — они написаны и сверены агентами, но приёмки текста не было.
- **Прод не трогали вообще.** Ни одного запроса к базе, ни одного деплоя: моста нет,
  а без него все утверждения о живой базе — реконструкция по коду и SQL-файлам.
- **Проект не запускался.** Нет `node_modules`, нет `.env` — ни `npm run dev`, ни сборка
  не проверялись. Значит и утверждения о поведении в браузере в библии отсутствуют
  осознанно.
- **Не прочитано целиком:** тело одной RPC, DML-часть большого SQL-скрипта
  (идемпотентность повторного прогона), поведение поповеров при скролле и ресайзе.
  Перечислено в разделах «Не покрыто» соответствующих страниц.
- **`README.md` и `AUDIT-2026-08-19.md` построчно не проверялись.** README уличён в
  одном конкретном вранье; полный аудит обоих — в backlog.

Харнесс стоит и исполним: следующая сессия начинается с `/session-start`, который сам
поднимет `current-state`, этот handoff, состояние репозитория, ветку и мост.

продом до тех пор, пока допущение не проверено или не опровергнуто.

## Следующий шаг

**Закрыть два вопроса, отложенных прорабом на первую рабочую сессию** — оба требуют
доступа к настройкам, которых у агента нет:

1. **Публикует ли Vercel из `main`.** Весь осторожный режим (работа в ветке, запрет
   авто-push, слияние только по команде) стоит на этом ДОПУЩЕНИИ. Проверяется в
   настройках проекта на Vercel → Git → какая ветка production. Опровергнется —
   правило смягчается явным решением прораба со строкой в `decisions.md`.
2. **Принимается ли предложенная очередь целей** (`current-state`, топ-3). Она
   составлена по цене отказа, а не по бизнес-ценности, и прорабом не подтверждена.

Первая веха предложена такая: **поднять мост и восстановить схему в репозитории.**
Первое действие в ней — не агента, а прораба: подключить в настройках коннекторов ту
организацию Supabase и тот аккаунт Vercel, где живёт склад. Без этого агент слеп, и
любая работа с данными идёт по реконструкции.

Если мост поднимать сейчас не хочется — вторая веха («приложение перестаёт падать
молча») моста не требует и закрывается целиком по коду.

## Грабли и решения

| Симптом | Причина | Решение |
|---|---|---|
| Агент, писавший страницу 02, вернул «задачи нет» и не создал файл | в промте внутри JS-шаблона остались неэкранированные обратные кавычки — строка оборвалась, на вход ушёл символ `0` | в промтах для воркфлоу обратные кавычки не использовать вовсе; страницу переписали отдельным проходом |
| Разведчик заявил, что CSS-переменная нигде не используется | `grep` без экранирования скобок — регулярка съела `var(--sidebar)` | утверждения вида «нигде не используется» подтверждать `grep -F` или экранированным шаблоном; отрицательный результат поиска — самое лёгкое место соврать |
| Целая зона разведки дала верное содержание при систематически смещённых адресах | агент считал строки по укороченному выводу, а не по файлу | номер строки берётся только из `grep -n` или `sed -n`, никогда «на глаз»; и это ловится дешёвой механической проверкой, а не чтением |
| Страница дизайн-системы противоречила сама себе: одна строка процитирована и как 126, и как 127 | часть якорей автор снимал, часть досчитывал в уме | при систематическом сдвиге пересниматься должны ВСЕ якоря страницы, а не только найденные проверкой |
| Две страницы библии дали разные ответы на один вопрос (экранирование XML: одна установила, вторая держала открытым) | писались параллельно и независимо | параллельное авторство требует финального прохода на противоречия между страницами — механическая проверка якорей его не ловит |
| Правила Cursor годами предписывали стек, которого в проекте нет | доки не переписали при смене стека, а удалить забыли | врущая дока опаснее отсутствующей: агент ей верит. При смене стека конфиги-инструкции сносятся тем же коммитом, что и код |
