### Почему разделили выдачу сотрудников

`fetchEmployees` тянула `select('*')` — паспорт, ПИНФЛ, адрес прописки. Кэшировать
это на диск нельзя, а без диска нет первого кадра после перезагрузки. Прораб
возразил на memory-only решение («F5 частый»), и возражение верное: выход не в
том, чтобы рискнуть, а в том, чтобы **разделить**. Реестр (`employees:list`) —
семь колонок без единого документа, ложится на диск наравне с машинами; полная
карточка приезжает на открытие дровера, паспорта выбранных — в момент сборки
файла, без кэша. Экспорт по машинам заодно перестал качать всех сотрудников
целиком ради водителей трёх выбранных.

### Почему подписанные ссылки теперь переживают перезагрузку

Прежнее решение («signed URL только в памяти») стоило 931 КБ фото на КАЖДУЮ
загрузку раздела: после F5 браузер получал новые адреса тех же файлов и качал
их заново, хотя они лежали у него в кэше под старыми. Довод «протухший URL как
факт» снят гейтом — у каждой ссылки своя метка истечения, просроченная не
отдаётся. Ключ уехал в `persistentCache`, а не в `localStorage` напрямую, ради
одного: там ключи именованы пользователем и стираются на выходе. Подписанная
ссылка открывает файл без авторизации, и на общем ноутбуке она не должна
пережить смену человека.

### Где прораб развернул решение

**«Агрессивный префетч всего»** — просьба прораба была шире, чем то, что уехало
в код. В прогрев взято только лёгкое (реестры по 1–3 КБ на раздел), тяжёлое
оставлено за порогом и это сказано вслух: греть полный каталог (109 КБ) и фото
(под мегабайт) заранее — значит вернуть в профиль ту самую болезнь, которую
сессия и лечила. Каталог греется под `/lists`, фото качает тот, кто открыл
раздел.

### Трансформация картинок Supabase не работает

План `pro`, но трансформация в проекте ВЫКЛЮЧЕНА: `createSignedUrl` с
`transform` вернул исходный файл байт в байт (45 987 = 45 987), а URL остался
`/object/sign/`, а не `/render/image/sign/`. Батчевый `createSignedUrls`
опции `transform` не принимает вовсе (storage-js 2.7.1) — включат её, и
подписывать придётся по одной ссылке на файл. Решение прораба: пока не
включаем, взяли бесплатный путь (персист ссылок).

## Грабли и решения

| Симптом | Причина | Решение |
|---|---|---|
| Замер в dev показал по два одинаковых запроса на каждый экран | `StrictMode` в React 19 дважды вызывает эффекты в разработке; `cachedQuery` склеивает запросы в полёте, но ветка `bypass` к ним не присоединяется | Цифры сети снимать ТОЛЬКО на прод-сборке (`npm run build && vite preview`). Дублей в проде нет — они были артефактом инструмента |
| `transferSize === 0` показал «все фото из кэша» и на тёплом, и на холодном заходе | Supabase не отдаёт `Timing-Allow-Origin`, поэтому у cross-origin ресурса размеры в Resource Timing всегда нули | Вес по сети мерить через CDP (`Network.loadingFinished.encodedDataLength` плюс `Network.requestServedFromCache`), а не через `performance.getEntriesByType('resource')` |
| Контроль чувствительности по залам показал данные там, где ждали скелет | `localStorage` чистился, пока запрос прошлого захода был ещё в полёте: ответ пришёл и записал ключ обратно | Чистку кэша делать на успокоившейся странице (увести на `/login`, дождаться тишины), иначе замер меряет гонку, а не кэш |
| `min-height` плитки главной игнорировал новый `clamp` | Рядом жило правило `.home-row--refs .home-destination { min-height: 300px }` — два класса против одного, специфичность выше | При правке размеров грепать ВСЕ правила селектора, а не только базовое; `getComputedStyle` показывает победителя и экономит час |
| Главная стала вдвое выше на 1280×1024 после правки, которая её чинила | `grid-auto-rows: 1fr` выравнивает ярусы, а нижний ярус в раскладке «2 + 1» двухстрочный — верхний подтянулся до его высоты | Выравнивание ярусов гейтить по ширине: включать только там, где нижний ярус — одна строка |
| `page.waitForTimeout` внутри обработчика `page.route` падает с «setTimeout is not defined» | В песочнице Playwright-скрипта нет таймеров Node | Задержки сети эмулировать через CDP `Network.emulateNetworkConditions`, а не задержкой в обработчике маршрута |
| Значение-`Map` в кэше превращается в `{}` | `persistentCache` персистит через `JSON.stringify` | Map кэшировать только `{ persist: false }`; на диск кладём то, что переживает JSON (массив, словарь) |
