# Handoff: 2026-09-15 (сессия 29) — Excel на Windows перестал звать xlsx повреждённым

Сессия началась с приёмки карточки оборудования в очереди, но прораб принёс баг:
коллега на Windows открывает выгруженный список в Excel и получает «обнаружена
ошибка в части содержимого в книге», файл не открывается; в Numbers на Mac и в
Google Sheets тот же файл открывается. Цель сменилась на этот баг, выкачено по
решению прораба до проверки коллегой.

## Сделано

- **`513554e`** — порядок детей `<headerFooter>` приведён к схеме CT_HeaderFooter
  (`oddHeader, oddFooter, evenHeader, evenFooter`; писали `oddHeader, evenHeader,
  oddFooter, evenFooter`). Чётные колонтитулы дублировали нечётные буква в букву и
  убраны вместе с `differentOddEven`: печать не меняется, поверхности для той же
  ошибки нет. Общая правка на оба генератора — лист списка и каркас документов.
- Там же — `headerFooterText` в `lib/xlsx/cells.ts`: амперсанд внутри колонтитула
  управляющий символ, «Q&A форум» Excel прочитал бы как «Q» плюс код `&A`.
- **`962b1a9`** — `planner` возвращён на Fable: сессию вёл Fable, лимит вернулся.
- **`16fbf25`** — доки закрытия с28 перенесены cherry-pick'ом на ветку от `main`.
  Ветка `session-28-doc-export` целиком НЕ сливалась: в ней непринятая карточка
  оборудования, и «сделать деплой» не должно было выкатить её без приёмки.

### Как искали, чтобы это была причина, а не догадка

Excel на этой машине нет, и Numbers с Google Sheets как судьи бесполезны: они и
показали, что файл «открывается». Судьёй стали официальные XSD ECMA-376:
Part 4 (транзишн-схемы SpreadsheetML/DrawingML), Part 2 (OPC: content types, rels,
core properties) и Dublin Core для `core.xml`. Прогнаны через `xmllint --schema`
ВСЕ части пакета: styles, workbook, content types, rels, core, app, drawing и лист.
Чистыми оказались все, кроме листа, и в листе — ровно одна ошибка, у всех трёх
генераторов сразу.

Контроль чувствительности: до правки валидатор называл `oddFooter` поимённо,
после правки на четырёх образцах (рабочий, на согласование, без реквизитов,
документ сотрудников с `&` в имени) остаётся только ложная тревога на `xml:space`.

Образцы собирались в Node: `esbuild --bundle` экспортёра с подменой `document` и
`URL.createObjectURL` — генератор не зависит от DOM, кроме клика по ссылке.
Скрипты и схемы одноразовые, в дерево не клались.

Данные прода как причина исключены запросом: контрольных символов XML нет ни в
1482 единицах оборудования, ни в пяти списках.

## НЕ проверено

- **В Windows Excel ни один файл этой сессии не открывался.** Выкачено по решению
  прораба до проверки коллегой. Это первое действие следующей сессии.
- **Противоречие с с19:** там записано, что документы сотрудников и машин прораб
  открывал в Excel «молча». Та же ошибка порядка была и в них. Либо открывали не в
  Windows Excel, либо запись неточна. Проверять вместе со списком.
- Документы сотрудников и машин после правки собраны только в Node, без фото;
  полный путь с `drawing` на проде после правки не прогонялся.
- **Карточка оборудования по-прежнему не принята.** Ветка `session-28-doc-export`
  (`a0db1c9`) теперь отстаёт от `main`; перед приёмкой — `git rebase main`,
  конфликтов не ждём (файлы не пересекаются).
- Полный `npm run build` зелёный; превью Vercel ветки не смотрели, деплой `main`
  проверен только по статусу.

## Следующий шаг

Коллега на Windows открывает список с прода (`/lists`, любой сохранённый, оба
режима). Открылся молча — долг закрыт, тем же способом проверить документ
сотрудников с фото. Не открылся — нужен САМ упавший файл и версия Excel, метод
XSD тогда недостаточен. После этого — приёмка карточки оборудования.

## Грабли и решения

| Симптом | Причина | Решение |
|---|---|---|
| Windows Excel: «ошибка в части содержимого», Numbers и Google Sheets открывают | Порядок дочерних элементов нарушал схему; Excel проверяет последовательность строго, остальные читатели — нет | Любой новый элемент в OOXML ставить по порядку схемы и гонять лист через XSD, не через «открылось у меня». Правило — gotchas §15 |
| Ссылки на zip со схемами ECMA отдают HTML | Прямые адреса из памяти устарели; живые — на странице стандарта | Part 4 5th edition zip содержит `OfficeOpenXML-XMLSchema-Transitional.zip`; OPC-схемы — в Part 2; `core.xml` тянет `dc.xsd`/`dcterms.xsd` с dublincore.org, `schemaLocation` патчить на локальные копии |
| `xmllint` ругается на `xml:space` у каждого `<t>` | Схема sml не импортирует `xml.xsd` | Ложная тревога: сам Excel так пишет; фильтровать |
| Vite в dev: `%VITE_*% is not defined` | Литерал `%VITE_*%` в комментарии `index.html` попадает под подстановку | Косметика, строка в backlog |
| `SUM(C13:C13)` у пустого списка ссылается на саму итоговую ячейку | `Math.max(dataStart, totalRow - 1)` при нуле строк указывает на строку итога | Циклическая ссылка при экспорте пустого сохранённого списка, строка в backlog |
