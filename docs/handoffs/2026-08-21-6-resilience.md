# Handoff: 2026-08-21 (сессия 6) — веха 2: приложение перестаёт падать молча

Цель, заданная прорабом: **веха 2 целиком** — граница ошибок, канал диагностики,
обработчик провала чанка, индикатор возраста данных. Выполнена целиком за одну
сессию: четыре шага плана (A→B→C→D) плюс два круга адверсариального ревью.
Схема базы не менялась, зависимостей не добавлено, `vercel.json` не тронут.

Раскладка тиров отступала от дефолта по требованию прораба «Fable сильно не
расходовать»: планировщик — Opus вместо Fable, `coder` Opus ×3, ревью Opus ×2,
`scout` Sonnet ×1, чеклист Opus ×1; Fable — только брифы и ревью отчётов.
Отступление сработало, качество плана не просело (факты в плане проверялись по
исходникам Vite, докам React 19 и живому `curl`, а не по памяти).

## Сделано

По шагам плана (коммит — в скобках):

1. **Шаг A — канал ошибок** (`7e752ee`). Новый `src/react/lib/reportAppError.ts`:
   `reportAppError(error, {scope, route?, componentStack?, detail?})`,
   `setErrorSink()` — весь шов под будущий Sentry одной функцией,
   `installGlobalErrorReporting()` — слушатели `error`, `unhandledrejection`,
   `vite:preloadError` на `window` (**только отчёт**, без `preventDefault` и без
   перезагрузки). Канал никогда не бросает (тело в `try/catch` — его зовут из
   фолбэка границы, и падение там дало бы цикл); дедуп-троттл 5 с по подписи
   `scope:message`; в прод-консоль уходят только `message` и `code` (`details`/`hint`
   у `PostgrestError` содержат данные строк — правило 3 CLAUDE.md); auth-коды
   получают `level: 'auth'` и в sink не идут — `isAuthError` **экспортирована**
   из `persistentCache.ts`, а не скопирована. `main.tsx`: `installGlobalErrorReporting()`
   до `createRoot`, сам рут — с `onUncaughtError` и `onRecoverableError`.
   Шесть `.catch(() => undefined)` получили след: два прогрева в `App.tsx`,
   `prefetchSavedListDetails` (`lists/api.ts`), прогрев следующей страницы и
   загрузчик каталога (`EquipmentPage.tsx`), таксономия (`EquipmentCreatePage.tsx`).
   **Это первый `console.*` во всём `src/react`** — утверждение «0 console» стало
   ложным осознанно и патчено в библии этим же закрытием.
2. **Шаг B — граница ошибок** (`a5c385c`). Новый `src/react/components/AppErrorBoundary.tsx`:
   классовый компонент, `variant: 'app' | 'page'`, `resetKey`, сброс в
   `componentDidUpdate` и только когда граница уже в состоянии ошибки. Границ две:
   корневая в `main.tsx` выше `BrowserRouter` (переживает падение самих провайдеров;
   язык берёт из нового экспорта `readStoredLanguage()` в `i18n.tsx`, которым теперь
   инициализируется и `LanguageProvider` — одно чтение ключа `argo:language` на
   проект) и постраничная — `RouteBoundary` в `App.tsx` стал границей + `Suspense`;
   `/login` тоже под границей. Экран: «Что-то сломалось» / «Nimadir buzildi» +
   кнопка «Перезагрузить» (именно перезагрузка, а не «попробовать снова»:
   `React.lazy` кэширует отказ), в dev — `<pre>` со стеком. Dev-триггеры
   `?__crash=1` (постраничная) и `?__crash=app` (корневая) вырезаются из прод-бандла
   (`grep __crash` по `dist` → 0).
3. **Шаг C — провал чанка после выкатки** (`0bcf1f1`). Новый
   `src/react/lib/lazyWithReload.ts`: отказ динамического импорта → отчёт
   `scope:'chunk'` → офлайн (`navigator.onLine`) → `throw` на границу → бюджет
   (`sessionStorage` `argo:chunk-reload-at`, таймштамп, окно 60 с) → `location.reload()`
   → **никогда не резолвящийся промис** (без него React за оставшиеся до навигации
   ~100 мс отрисует ошибку). Шесть `lazy()` в `App.tsx` заменены на `lazyWithReload()`;
   загрузчики прогрева не тронуты. Перезагрузка висит **на пути `lazy`, а не в
   глобальном `vite:preloadError`**: глобальный сработал бы от фонового прогрева и
   перезагрузил вкладку под человеком, заполняющим `/equipment/new`. Загрузчик
   `ListsPage` получил отчёт `scope:'loader'`.
4. **Шаг D — возраст данных** (`f268b0b`). `readCachedQueryMeta(key)` в
   `persistentCache.ts` — **без TTL-гейта** (значение из ветки отказа по определению
   просрочено, гейт вернул бы `null` ровно там, где возраст нужен); `formatAge()`
   в `date.ts` на `Intl.RelativeTimeFormat` (`ru-RU` / `uz-UZ`, `Math.floor`);
   `readCachedEquipmentMeta` / `readCachedEquipmentListsMeta` в api-модулях;
   новый `src/react/components/DataAge.tsx` — бейдж «Обновлено 40 минут назад» /
   «40 daqiqa oldin yangilangan» + кнопка «Обновить», `role="status"`; в тулбарах
   `EquipmentPage` и `ListsPage`; 4 строки CSS (`.data-age` + 44 px на ≤820 px).
   Бейдж **условный, а не постоянный**: `dataAt` ставится только там, где исход
   запроса известен (`.then`/`.catch`), при живой сети `bypassCache` всегда
   дозапрашивает, поэтому бейдж не появляется никогда; рядом с блоком «Ошибка
   загрузки» скрыт.
5. **18 фиксов по двум кругам адверсариального ревью** (`a18aa25`, `73e02d8`).
   Блокеров ревью не нашли, но нашли пять содержательных дефектов:
   отчёт прогрева `primary-data` был недостижим за `Promise.allSettled` (успешный
   `allSettled` не идёт в `.catch`) → разбор результатов; дедуп был **скользящим** —
   ошибка с периодом чаще 5 с печаталась один раз и больше никогда; бейдж мигал на
   пустом месте при кэше в пределах TTL; провал чанка позже 60 с после загрузки
   (висящий коннект) уводил вкладку в бесконечный круг перезагрузок → сравнение
   метки с `performance.timeOrigin`, а не с `Date.now()`; перезагрузка офлайн
   убивала вкладку вместе с кэшем → `navigator.onLine`. Плюс `isFetching`
   отдельным флагом от `isLoading` (офлайн кнопка «Обновить» иначе не отвечала
   на нажатие ничем).

### НЕ проверено

- **Ни один сценарий не прогнан руками прораба.** Работа принята с той же
  формулировкой, что и в с5 («что можем — сам протестирую»). Все 25 пунктов
  чеклиста ждут человека; критичны пункты про перезагрузку чанка — она
  воспроизводится только на `preview`/проде, в dev `__vitePreload` не существует.
- **Превью снаружи проверить не удалось.** У проекта включена Vercel Authentication
  (`ssoProtection: prod_deployment_urls_and_all_previews`; сам домен
  `warehouse.argomedia.uz` открыт) — и `curl`, и bypass-ссылка через MCP уходят на
  логин `vercel.com`. Решение: защиту оставляем (репозиторий публичный), агент
  проверяет превью по build-логу, кликает прораб. В с5 в handoff записано «превью
  проверено снаружи» — значит защита включилась позже либо проверялось иначе;
  **текущее состояние — превью снаружи агенту недоступно.**
- **`/rls-verify` по-прежнему невыполним** — в проде один аккаунт (долг с с2).
  Веха 2 прав и ролей не касалась, но обязательство по пересозданной в с5 RPC
  никуда не делось.
- `baseline.sql` ни разу не исполнялся на чистой базе (долг с с2).

## Состояние

- **Работает:** приложение больше не умеет падать молча. Любое необработанное
  исключение ловит граница (постраничная сохраняет сайдбар, корневая переживает
  падение провайдеров), любой отказ оставляет строку `[argo] …` в консоли,
  провал чанка после выкатки чинится одной автоматической перезагрузкой,
  отданные из кэша данные объявляют свой возраст.
- **Известные ограничения (не баги):** dev-оверлей Vite на React-ошибках больше
  не всплывает — переопределён `onUncaughtError` и всё ловит корневая граница;
  вместо него `console.error` и `<pre>` со стеком в фолбэке. Заголовок `immutable`
  всё ещё липнет к 404 `/assets/` — это неустранимо заголовками, закрыто
  перезагрузкой, и остаётся операционное правило «не откатываться на байт-в-байт
  тот же билд».
- **Выкатка:** `<коммит слияния>` → деплой `<id>` — заполнит архитектор.

## Грабли и решения

| Симптом | Причина | Решение |
|---|---|---|
| На старте сессии 24 untracked-файла вида «имя 2.ext», в конце — ещё 6 | причина опознана: репозиторий лежит в папке, синхронизируемой **iCloud Drive**, и это iCloud плодит конфликтные копии « 2» | `git status --short` перед каждым `git add`; сверять `cmp` с оригиналом (первые 24 были побайтно тождественны, последние 6 — снимок предыдущего коммита) и удалять; уточнение внесено в gotchas §10 |
| `curl` и bypass-ссылка MCP на превью уходят на логин vercel.com | у проекта включена Vercel Authentication на все превью (`prod_deployment_urls_and_all_previews`) | защита оставлена (репозиторий публичный); агент проверяет превью по build-логу и runtime-логам, снаружи кликает прораб |
| `npm run preview` на пропавший `/assets/*.js` отдаёт `200 text/html` вместо 404 | у `vite preview` свой SPA-фолбэк, рерайта из `vercel.json` он не знает | механизм `lazyWithReload` срабатывает в обоих случаях (`import()` падает и на HTML вместо модуля); но проверять статус ответа надо на проде, а не в `preview` |
| Отчёт о провале прогрева никогда не печатался | `.catch` висел на `Promise.allSettled`, который **всегда** резолвится | разбирать массив результатов и докладывать каждый `rejected` отдельно |
| Ошибка, повторяющаяся чаще раза в 5 с, печаталась один раз за всю жизнь вкладки | дедуп сдвигал метку времени на КАЖДОЙ попытке, включая подавленную — окно скользило вперёд бесконечно | выход по окну ставится ДО отметки: получается честный троттл «не чаще раза в 5 с», а не «один раз навсегда» |
| Бейдж возраста мигал на здоровой странице | `dataAt` выставлялся из кэша ДО запроса, а свежий ответ приходил мгновением позже | возраст ставится только там, где исход запроса уже известен — в `.then` и в `.catch`; перед запросом сбрасывается в `null` |
| Вкладка ушла бы в бесконечный круг перезагрузок | бюджет сравнивался с `Date.now()`, а чанк умеет провалиться и через 10 минут после загрузки (висящий коннект) — к тому моменту бюджет всегда выглядел свободным | сравнивать метку с `performance.timeOrigin` — моментом старта ДОКУМЕНТА: метка, поставленная перед прошлой перезагрузкой, всегда впритык к нему |
| `localStorage.clear()` в черновике чеклиста выкинул бы прораба из аккаунта | Supabase хранит сессию в том же `localStorage` | в чеклисте — точечная чистка ключей с префиксом `argo-warehouse:v4:` |
| `preventDefault()` на `vite:preloadError` ломает загрузку модуля | событие cancelable, и отмена заставляет `preload()` резолвиться `undefined` — `lazy` тут же падает на чтении `.default` (проверено по исходнику Vite 7.3.6) | событие не гасим никогда: только отчёт |
