# 02-decisions — ARGO Warehouse

**Что здесь лежит:** решения, которые нельзя восстановить чтением кода, — почему сделано
так, где грабли, что сломается от «очевидной» правки. Устройство экранов, состав полей и
последовательность вызовов здесь НЕ описаны: это читается из `src/react` за минуту, а
дубль обязан разойтись.

**Чего здесь нет и не должно быть:** пересказа компонентов, списков полей формы,
перечисления вызовов. Причина конкретной строки живёт комментарием рядом с ней — код
проекта на 12 % состоит из таких комментариев, и это правильное место. Сюда попадает
только то, что **связывает разные файлы или разные системы**, либо объясняет отсутствие
чего-то.

Схема, RLS и правила миграций — `03-data-model`. Границы продукта — `01-product`.

## 1. Контракты между слоями

**Ровно три импортёра `lib/supabase`:** `features/lists/api.ts`,
`features/equipment/api.ts`, `features/auth/AuthProvider.tsx` (последний — только
`supabase.auth.*`). Ни одна страница не обращается к Supabase напрямую. Это соблюдается
на 100 % и это самое здоровое свойство архитектуры — распилы модулей его не нарушили.

**Граф импортов между фичами ациклический, и держится это одним приёмом.**
`lists/api` → `equipment/api` (за `fetchEquipmentByIds`) — ребро одностороннее. Обратное
ребро тоже нужно: правка модели меняет подписи в составе сохранённых списков, значит
`equipment/api` обязан сбросить их кэш. Чтобы не замкнуть цикл, ключ вынесен в **листовой**
`lists/cacheKeys.ts` (импортирует только `persistentCache`), и `equipment/api` зависит от
него, а не от `lists/api`.

**Порядок провайдеров значим.** `LanguageProvider` снаружи `AuthProvider` — поэтому экран
входа локализован. `AuthProvider` снаружи `App` — поэтому `App` читает `useAuth()`
безусловно. Корневая граница выше всех — поэтому падение самих провайдеров даёт экран
ошибки, а не белый лист.

**Гейт маршрутов — UX, а не защита.** Он прячет экраны от анонима; доступ к данным решает
RLS. Обход гейта не даёт данных, но и не должен считаться «защитой маршрута».

**Адрес каталога — контракт** (с11): `q`, `type`, `subtype`, `status`, `page`, `item`;
с с15 ещё `mbrand`/`mmodel` — открытая модель, два параметра, а не склейка (разделитель
пришлось бы экранировать от самих данных). Локальным остался только `searchInput`.
Следствие, ради которого делалось: жест «назад» на телефоне закрывает карточку вместо
ухода из раздела; с с15 он шагает карточка → модель → каталог.

**Каталог модельный — ЗАМЕНОЙ, а не переключателем «Модели/Единицы»** (решение прораба,
с15, U29): один каталог — одна правда, вторая поверхность жила бы вечно. Оплаченная цена:
поиск по серийнику ведёт к МОДЕЛИ, а не сразу к карточке единицы — один клик длиннее.
Серверный агрегат (`fetch_equipment_models`) вместо клиентской группировки: тянуть весь
каталог в браузер — то, от чего U29 лечит. Счётчики модели считаются по всем её строкам,
а не по совпавшим с фильтром: «596 штук» не должно превращаться в «1», когда модель
нашлась по серийнику одной единицы.

### Значения, продублированные в двух местах руками

Их четыре, и каждое разойдётся молча:

| Значение | Где |
|---|---|
| Мобильная граница 820 px | `lib/breakpoints.ts` и медиазапрос в `styles.css` |
| Высота липких вкладок редактора 57 px | `MOBILE_TABS_HEIGHT` и `.quick-catalog-toolbar { top }` |
| Размер страницы каталога и реестра | входит в **ключ кэша**, поэтому число отдаёт сама фича (`preferredEquipmentPageSize()`), а прогрев спрашивает у неё же — вторая копия формулы «мобильный или нет» легла бы мимо ключа |
| Правило нормализации модели `lower(btrim(...))` | в SQL (RPC) и в клиентской группировке состава |

## 2. Кэш и первый кадр

**Прогрев и есть источник первого кадра.** Таймеры в `AppShell` кладут результат в
`persistentCache`, а страницы читают тот же кэш синхронно, в инициализаторе `useState`.

> **Менять сигнатуру прогревочного вызова нельзя в отрыве от `readCached*` на странице.**
> Разошёлся хоть один параметр ключа — прогрев остаётся в кэше мусором, страница
> показывает скелетон, и **никакой ошибки при этом не будет.**

**Ключ принадлежит человеку, а не браузеру:** `argo-warehouse:v4:<id>:<ключ>`. Раскладка
`v3` хранила ключи без id, и на общем ноутбуке первый кадр следующего пользователя
рисовался данными предыдущего. Scope ставится **до** `setSession`.

**Без scope не персистится ничего** — `storageKey` возвращает `null`, `writeEntry` молчит.

**Первый кадр не рисует протухшее.** `readCachedQuery` сверяет срок. Иначе TTL ограничивал
бы только повторный запрос, но не показ, и экран рисовал бы сколь угодно старые данные.

**Прогретый первый кадр каталога читается ТОЛЬКО для нетронутого каталога** (`page=1`, ни
одного фильтра): под фильтром кэш без фильтра отвечал бы не на заданный вопрос, и честнее
скелет.

**Порядок в `catch` значим:**

```
if (isAuthError(error)) throw error   // «разлогинило / прав нет» — наружу
if (cached) return cached.value       // всё остальное — подмена старым
throw error
```

Подменять «тебя разлогинило» старыми данными — враньё, после которого пользователь
работает с экраном, за которым нет доступа. Всё остальное **гасится и до UI не доходит**.

**Поколения инвалидации.** Загрузчик запоминает поколение на старте и пишет результат,
только если оно не сменилось: иначе застрявший в полёте ответ вернул бы обратно только что
сброшенное значение. Вызвавшему значение всё равно отдаётся — он его ждал.
`bypass` **не присоединяется к запросу в полёте**: тот мог стартовать до записи, которую
bypass как раз и хочет увидеть.

**Три ключа устроены не как соседи, и каждый по своей причине:**

- **`equipment:all` не персистится** — ~1,4 МБ JSON съедали треть квоты Safari. Цена:
  после перезагрузки редактор ждёт сеть вместо первого кадра.
- **`list-draft:new` живёт ВНЕ префикса `equipment-lists:`** — тот целиком сбрасывается на
  каждом создании, правке и удалении, и унёс бы с собой работу, которую ещё не сохраняли.
- **`composition` носит в ключе `v2`** — форма значения сменилась с массива на объект, и
  без смены ключа первый кадр после выкатки читал бы массив как объект.

**Тонкость префиксов:** `equipment:` накрывает `equipment:all`, `:model-count:`,
`:movements:`, но **не** накрывает `equipment-taxonomy` и `equipment-lists:*` — другой
разделитель. Таксономия сбрасывается отдельной строкой, и при заводе нового ключа с
дефисом это легко забыть.

**Тонкость `clearListDraft`:** точечного удаления ключа нет, стирать приходится префиксом,
а инвалидация поднимает поколение — то есть **отменяет запись всех ответов, летящих прямо
сейчас**. Поэтому пустой вызов гасится проверкой `readListDraft() === null`: обычный заход
на `/lists/new` без черновика иначе выбрасывал бы прогрев каталога.

**Обрезка идёт по последней записи, а не по сроку годности:** просроченная, но недавно
записанная переживёт свежую редкую. Если ключей не больше лимита, значения вообще не
разбираются — разбор JSON стоит дорого, а происходит на каждой записи.

**При выкатке нового билда кэш не инвалидируется.** Версия `v4` — литерал; чтобы сбросить
всё, надо руками поднять до `v5` и выкатить.

## 3. Отказы: что видно, а что молчит

**Ни один `catch` в проекте не возвращает разрешающего значения.** Они глушат ускорение и
подсказки, но не защиту. Это инвариант — при правке обработчика проверяй его первым.

**Пары отказов, которые пользователь различить не может.** Это не недоделка по недосмотру,
а следствие того, что клиент не знает роли, — но знать про них надо:

| Неразличимы | Почему так |
|---|---|
| Неверный пароль / сеть лежит | одно сообщение на входе |
| Отказ по роли / обрыв сети при сохранении | роль клиенту недоступна, поэтому кнопки показаны всем и отказ приходит только на сохранении |
| Отказ RLS в виде пустой выборки / «ничего не найдено» | RLS отдаёт ноль строк, а не ошибку |
| Отказ удаления по правам / сбой сети | RLS не возвращает ошибку — строка просто не попадает под `delete`, и запрос успешен с нулём строк. Отказ распознаётся по **отсутствию данных** |

**Молчит совсем (в backlog):** порча localStorage, отказ `getSession()` (считается «нет
сессии» → редирект), `catch` без параметра в экспорте сохранённого списка.

**Пустое состояние различает причину.** Пустой ответ под фильтром — «Ничего не найдено»;
пустой ответ **без** фильтров — «Каталог пуст или недоступен… обратитесь к администратору»:
у сотрудника без строки в `public.users` RLS отдаёт ноль строк, и это не «не найдено».
Иллюстрированная заглушка показывается только в первом случае: рисовать «пока ничего нет»
человеку, который просто опечатался, — враньё.

### Две границы ошибок — почему именно две

Только постраничная пропускала бы крэш в `AppShell`; только корневая уносила бы сайдбар на
любой ошибке раздела. **Разница видна пользователю сразу: есть сайдбар — сломался раздел,
нет сайдбара — сломалось приложение.**

- **`tr` приходит границе пропсом, а не из `useLanguage()`.** Корневая стоит ВЫШЕ
  `LanguageProvider`, и хук внутри неё бросил бы прямо в том, что ловит ошибки.
- **Сброс по `resetKey`, а не ремаунтом `key={pathname}`.** `useRoutes` сверяет элементы по
  позиции, поэтому экземпляр границы переживает смену маршрута и без сброса ошибка залипла
  бы на всём приложении. Ремаунт при этом **запрещён**: редактор после создания списка
  делает `navigate(…, {replace:true})`, и пересборка поддерева стёрла бы набранный список.
- `errorElement` React Router неприменим — он работает только в дата-роутере.

### Самолечение чанка после выкатки

- **офлайн — не перезагружаемся:** без сети провал означает не «вышла новая версия», а
  «сети нет»; перезагрузка убила бы вкладку вместе с прогретым кэшем;
- **бюджет — таймштамп, а не флаг** (флаг потратился бы на первой выкатке дня), и
  сравнение с `performance.timeOrigin`, **а не с `Date.now()`**: чанк умеет провалиться
  через десять минут после загрузки, и от `Date.now()` бюджет всегда выглядел бы свободным —
  вкладка ушла бы в круг перезагрузок;
- **промис, который не резолвится никогда** — не заглушка, а требование: `reload()` уводит
  страницу не мгновенно, и за оставшиеся ~100 мс React успел бы прочитать `.default` у
  `undefined`;
- **почему на пути `lazy`, а не в глобальном `vite:preloadError`:** глобальный слушатель
  срабатывает и на фоновый прогрев, то есть перезагрузил бы вкладку под человеком, который
  заполняет `/equipment/new`, где автосейва нет.

> **Операционное правило: не откатываться на байт-в-байт тот же билд.** `Cache-Control:
> immutable` на `/assets/` приклеивается и к 404 — заголовки Vercel ставятся до файловой
> системы. Хэши совпадут, 404 по ним закэширован на год, перезагрузка не поможет.
> **Откат делается ВПЕРЁД, новой сборкой.**

### Канал диагностики

`lib/reportAppError.ts` — единственное место в проекте с `console.*`.

- **Никогда не бросает** (три вложенных `try/catch`). Канал зовут из фолбэка границы:
  упади он сам, границе прилетела бы новая ошибка, и выхода из цикла нет.
- **Троттл 5 с, и выход по окну стоит ДО отметки времени** — иначе метка сдвигалась бы на
  каждой подавленной попытке, и ошибка с периодом чаще 5 с напечаталась бы один раз за всю
  жизнь вкладки.
- **В прод-консоль уходят только `message` и `code`.** У `PostgrestError` в `details`/`hint`
  лежит содержимое строк базы (правило 3 CLAUDE.md).
- **Auth-ошибки — не крэш**, и список кодов **не скопирован**: `isAuthError` экспортирована
  из `persistentCache`.
- **`onCaughtError` намеренно не задан:** пойманное границей докладывает сама граница, и
  второй обработчик давал бы два отчёта на одну ошибку — с разными `scope`, так что дедуп
  их даже не сливает.
- `vite:preloadError` — **только отчёт, без `preventDefault()`**: событие cancelable, и
  отмена заставила бы `preload()` резолвиться `undefined`, а `lazy` упал бы на `.default`.

**Бейдж возраста данных условный, и это условие задачи.** При живой сети `bypassCache`
всегда дозапрашивает свежее, поэтому бейдж не появляется никогда — он показывается ровно
тогда, когда сеть не ответила и на экране старое. Рядом с блоком «Ошибка загрузки» скрыт:
два сообщения об одной беде противоречили бы друг другу. `readCachedQueryMeta` читается
**без TTL-гейта** — значение из ветки отказа по определению просрочено, и гейт вернул бы
`null` ровно там, где возраст и нужен.

**Признака «вы офлайн» нет** — есть только возраст данных. `navigator.onLine` читается в
одном месте, в `lazyWithReload`.

## 4. Гонки, порядок и защита ввода

**Конфликт версий карточки оборудования.** Правка «данных модели» задевает ВСЕ единицы с
тем же брендом и моделью, поэтому устаревшая вкладка была дорогой ошибкой. Drawer при
открытии перечитывает карточку в обход кэша каталога и шлёт `updated_at` обратно;
расхождение отменяет правку целиком, код `PT409` (до с14 — `40001`, см. ниже). **Форма при этом не сбрасывается**, а
карточка перечитывается фоном — повторное сохранение проходит.

**Черновик формы не пересобирается из пришедшей записи, пока идёт правка:** перечитывание
карточки не имеет права стереть введённое.

**Количество серийной карточки не отправляется вовсе** (`undefined`, а не `1`). Триггер
реагирует на изменение `count`, и запись с фактическим количеством ≠ 1 получала фантомную
строку «Изменено количество» в журнале при правке одного описания.

**Отказ проверки серийника — отдельное состояние `'failed'`, а не «дубля нет».** Раньше
`catch` возвращал `false` — то же значение, что и успешная проверка, то есть любой сбой
**разрешал** вставку. Разрешает только база, а раз уникального индекса нет, «мы не знаем»
не имеет права означать «можно». Кнопку при `'failed'` намеренно **не** блокируют: отправка
перепроверит сама, иначе один сетевой сбой запирал бы форму.

**Дебаунс поиска и адрес.** В адрес запрос уезжает с `replace` (иначе каждая буква
оставляла бы запись в истории), а обратная синхронизация идёт через `pushedSearchRef`: без
него собственная запись дебаунса, прилетающая через 350 мс, затирала бы буквы, набранные за
это время.

**Открытие дровера пушит запись в историю, закрытие крестиком её ЗАМЕНЯЕТ** — иначе «назад»
открывал бы карточку заново.

**«Показать ещё» пересчитывает, а не накапливает.** Строки остаются чистой функцией от
фильтров и числа N: страницы 1…N тянутся одним `Promise.all`. Инкрементальный `append`
дешевле на вид, но даёт двойную вставку в StrictMode и хвост от прошлого фильтра, если тот
сменился пока запрос летел. **Первый кадр из кэша рисуется либо целиком, либо никак:**
склейка «две страницы из кэша, третья пусто» показала бы обрезанный список как полный.

**Номер страницы зажимается на рендере** (`Math.min(page, pageCount)`), и зажатое значение
и рисуется, и грузится — иначе после сокращения выборки выходила «Страница 3 из 1».

**Сортировка реестра двухключевая** (`created_at desc, id desc`): `created_at` не уникален —
импорт кладёт пачку одной секундой, — и без второго ключа строка могла попасть на две
соседние страницы сразу либо не попасть ни на одну.

**Гидратация редактора разведена на две.** Шапка заполняется, как только приехала строка
списка, и каталог не ждёт. Раньше и то и другое шло одним эффектом, и на холодном старте
приехавшие данные затирали название, которое пользователь успел набрать.

**Восстановление черновика запускается только по живому каталогу**, и автосейв заблокирован
флагом, пока восстановление не закончилось: «ничего не нашлось» стёрло бы черновик вместо
того, чтобы его вернуть, а стартовый пустой стейт затёр бы сохранённое раньше, чем оно
поднимется.

**Escape закрывает по одному слою за раз.** Попап ловит Escape **в фазе перехвата** и
гасит распространение, слой drawer'а слушает **в фазе всплытия**, то есть последним. Без
этого один Escape закрывал и попап, и весь drawer вместе с несохранёнными правками.

**Прокрутка в поповерах слушается в фазе перехвата:** попап позиционируется абсолютными
координатами в `body`, события `scroll` не всплывают, и без capture прокрутка внутри
drawer'а до `window` не доходила — попап висел на старом месте.

**Смена языка не делает ни одного сетевого запроса.** `tr` меняется вместе с языком и
попадает в зависимости любого эффекта, где текст ошибки лежит в стейте строкой. Поэтому в
стейте лежит **код или флаг**, а текст собирается на рендере. Это не стиль, а защита от
сетевого залпа на клик по переключателю.

## 5. Данные: что решает база, а что браузер

**Состав списка хранится одной копией** (с10) — `equipment_ids` + `equipment_items` в
строке списка. Правка списка — **replace, а не merge**.

**Выборка редактора хранит КЛЮЧ группы, а не снимок группы.** `label` — минимальный снимок
подписи, нужный ровно в одном случае: группы больше нет в свежем каталоге и строку нечем
нарисовать. Раньше в выборке лежала копия группы на момент клика, и обновление склада до
панели **не доезжало**.

**Как выбор раскладывается на позиции:** отмеченные серийники → по позиции на каждый;
остаток → по количественным единицам; что не покрылось складом → одна позиция `planned`
без `equipment_id`. Появился хоть один `planned` — весь список становится `abstract`.

**Асимметрия, которую надо помнить:** потеря позиции при открытии показывается плашкой у
**черновика** и **молча отбрасывается** у сохранённого списка. Это разные пути кода, второй
остался молчаливым (в backlog).

**Два независимых сборщика состава для одного списка** — из редактора и из карточки.
**Совпадение результатов ничем не гарантировано.**

**Доступность в редакторе определяется эвристикой по подстрокам русского текста статуса.**
Русских статусов в проде не осталось ни одного, то есть ветки мёртвые — и они **маскируют
опечатку в английском значении**: незнакомая строка молча считается недоступной.

**Локация — данные, а не текст интерфейса.** `DEFAULT_LOCATION = 'Офис'` — константа, не
`tr()`: при узбекском интерфейсе в базу уезжало `'Ofis'`, заводя вторую локацию рядом с той,
под которой лежит весь каталог.

**Два места ломаются тихо от `db-max-rows`** (значение для проекта не установлено):
`fetchAllEquipment` — условие выхода `batch.length < batchSize` смешивает «таблица
кончилась» и «сервер обрезал страницу»; `fetchEquipmentTaxonomy` — запрошено 2000 строк без
единого `.order()`, то есть подмножество произвольное, и оно кэшируется на сутки.

**Легаси-фолбэк списков гейтится по коду**, а не по факту ошибки: только `PGRST205`,
`42P01`, `PGRST204`, `42703` — «в базе НЕТ того, что мы просим». До с5 единичный сетевой
сбой давал вымышленные данные, и они ложились в кэш на десять минут.

### Где клиент решает за базу — сводка

Правило проекта (CLAUDE.md, п. 2): клиентская проверка права или уникальности без пары в
базе — дыра.

| Проверка | Статус |
|---|---|
| **(а)** Уникальность серийного номера — check-then-insert | **ДЫРА.** `UNIQUE` в проде нет. Две одновременные вкладки создают дубль. Регистр, пробелы и `_`/`%` расхождения не дают — осталась ровно гонка |
| **(б)** `brand/model/type/subtype` позиции не сверяются с оборудованием | **ДЫРА.** Существование `equipment_id` проверяется, соответствие текста — нет |
| **(в)** `requested_count` не сверяется со складом | **ОТКРЫТО.** В базе может лежать список на 9999 единиц. Клиентское «больше текущего остатка» — только текст |
| **(г)** Расчёт остатков в браузере по кэшу до 10 минут | **СУЖЕНО.** Свежие остатки доезжают до панели, но между приходом каталога и сохранением склад может измениться |
| **(д)** `tracking_mode` и `inventory_code` — не колонки, а разбор `serialnumber` | **ОТКРЫТО.** Парсер должен остаться один; второй жил в SQL-бэкфилле снесённой таблицы |
| **(е)** Кнопки не прячутся по роли — клиент **не может** её прочитать | **Дыры нет.** Эффект только UX. **Не «чинить» revoke** — `03-data-model` §3 |
| **(ж)** Право удалить список | **Дыры нет по безопасности.** Отказ распознаётся по нулю возвращённых строк |
| **(з)** Версия карточки при сохранении | **Пара на месте.** Отменяет правку сервер, клиент только переводит `PT409` в человеческий текст |

## 6. Вид и доступность

**Шкалы отступов и радиусов как системы не существует.** Цветовые токены работают и
покрывают почти всё; геометрические — декоративны: `--radius-lg` не используется ни разу,
переменных под отступы нет вообще, `border-radius` — числа руками от 4 до 999 px без шага.
Заводя компонент, не ищи шкалу — её нет. Инвентарь токенов — в шапке `styles.css`.

**Ячейку-константу на телефоне убирают ИЗ DOM, а не прячут `display: none`.** Спрятанный
элемент остаётся в `:last-child` и `nth-child`, а мобильная строка — грид в две колонки:
чётность ломается, рядом с последней ячейкой висит пустая половина с рамкой.

**Drawer каталога редактора рисует страница, а не панель:** у `.data-panel` и `.editor-grid`
анимация с `fill-mode: both`, и её `transform` стал бы блоком-контейнером для
`position: fixed` — drawer уехал бы внутрь панели.

**Высота сетки редактора — замер, а не константа** (`useEditorChrome.ts`). Константа врала
при баннерах и при раскрытых реквизитах; значение в CSS — запасное на один кадр до замера.

**Поповеры при скролле и ресайзе закрываются, а не перепозиционируются:** позиция считается
один раз при открытии, поэтому «закрыть» — единственный способ не оставить попап
оторванным. Высота попапа **оценивается, а не измеряется**: координаты нужны до появления в
DOM, иначе первый кадр рисуется в углу и прыгает на место.

### Чего в доступности нет

1. **Фокус-ловушки в drawer'ах и возврата фокуса на триггер.** В поповерах возврат
   реализован — **проект не согласован сам с собой**, образец лежит в соседнем каталоге.
2. **`AppSelect` не выполняет заявленный listbox-контракт.** Роли и `aria-selected`
   объявлены, навигации стрелками, Home/End и `aria-activedescendant` нет. **Для скринридера
   это хуже нативного `<select>`: контракт обещан и не исполнен.**
3. **`aria-live` почти нет.** Успех сохранения, ошибка, удаление, конец экспорта меняют DOM
   молча — для незрячего нажатие «Сохранить» не даёт обратной связи.
4. **Skip-link'а нет** — при табуляции придётся пройти весь сайдбар на каждой странице.
5. `aria-label` скелетона маршрута зашит по-русски мимо `tr`.
6. **Контраст (WCAG) не проверялся ни для одной пары фон/текст.**

## 7. Сборка и выкатка

**Гейтов ровно два:** `npm run check` (`tsc -b`) и `npm run build`. **Тестов нет, линтера
нет** — это следствие отсутствия зависимостей, а не забытого конфига.

**Гейт окружения в `vite.config.ts`:** сборка падает без `VITE_SUPABASE_URL` и
`VITE_SUPABASE_ANON_KEY`. Иначе деплой уезжал зелёным, а логин отвечал «неверный пароль» на
всё. **Переменные нужны и для Preview**, иначе превью-деплой ветки падает на этом гейте.

**`manualChunks` разводит вендор**, чтобы правка строки в приложении не сбрасывала React и
Supabase из кэша у всех сотрудников. `chunkSizeWarningLimit` опущен до 250 — рост чанка
должен быть заметен в логе.

**Рерайт Vercel обходит ассеты** (`/((?!assets/|equipment-images/).*)`). Без этого промах по
чанку отдавал бы `index.html` со статусом 200 вместо честного 404.

**`noUncheckedIndexedAccess: true`** — `arr[0]` типизируется как `T | undefined`; отсюда
`?.` и `.at(-1)?` по всему коду. Спотыкается об это каждый, кто пишет индексный доступ.

**В `lib/database.types.ts` руками лезут только чтобы описать то, чего генератор ещё не
видел, и только с комментарием «ПРАВКА РУКАМИ», по которому правку потом снимут.** Сейчас
таких вставок четыре — генератор не выражает nullable-аргументы RPC, и без них сборка
красная. Всё остальное — перегенерация.
