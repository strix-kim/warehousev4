# Каноны ARGO Warehouse

Инварианты «как у нас принято», снятые с решений сессий с11–с29. Вынесены из
`current-state.md` в с30 ДОСЛОВНО (диета стартового файла: 39,6 → ~12 КБ) — ни одна
строка не переписана. Читать не целиком, а раздел по теме задачи: Excel, кэш,
язык системы, карточка-профиль, стили, тексты, проверки, залы, прочее.
Новый канон — сюда, в свой раздел; «почему» — в handoff той сессии.

- **База авторитетна.** Правило только в React — не существует.
- **`main` — прод; сливаем принятое** с зелёными `npm run check` и `npm run build`.
- **Тиры (с18): ведущего выбирает прораб**; код — `coder` (Opus), планы —
  `planner` (Fable, с с29 снова), механика — `scout` (Sonnet).
  Раскладку называть перед воркфлоу.

### Excel (с29)

- **Excel проверяет порядок элементов по схеме, Numbers и Google Sheets — нет.**
  «У меня открылось» на Mac ничего не доказывает. Судья — XSD ECMA-376 через
  `xmllint`, потом коллега с Windows. Рецепт — gotchas §15.
- **Колонтитул один на все страницы** (`oddHeader`/`oddFooter`), чётных нет;
  амперсанд в тексте колонтитула удваивается (`headerFooterText`).
- **Генератор xlsx от DOM не зависит**: образец собирается в Node через
  `esbuild --bundle` с подменой `document` — так и проверять, без браузера.

### Скорость и кэш (с26)

- **Первый кадр рисуется из кэша во ВСЕХ шести разделах.** Механика одна на
  проект: `readCachedX()` синхронно в `useState`, `isLoading = !cached`, запрос
  с `bypassCache` при живом кэше, `DataAge` в тулбаре.
- **Возраст записи — единственный честный признак отказа сети** (gotchas §11):
  `cachedQuery` при живой записи подменяет провал последним значением и промис
  резолвится. Метка `touchedAt` до и после запроса; не сдвинулась — ответа не было.
- **Реестр сотрудников и полная карточка — РАЗНЫЕ выдачи.** На диск ложится
  только реестр (`employees:list`, семь колонок); паспорт, ПИНФЛ и адрес
  прописки приезжают `fetchEmployeeById` на открытие дровера и
  `fetchEmployeesByIds` в момент сборки документа. Memory-only для полной выдачи
  ОТВЕРГНУТО прорабом: F5 частый, первый кадр нужен и после него.
- **Подписанные ссылки переживают перезагрузку** (ключ `signed-urls:<бакет>` в
  `persistentCache`), у каждой своя метка истечения. Отсюда 0 КБ фото на
  повторном заходе вместо 931 КБ. В `localStorage` НАПРЯМУЮ им нельзя: ссылка
  открывает файл без авторизации, а `persistentCache` именует ключи
  пользователем и стирает их на выходе.
- **Значение-`Map` кэшируется только `{ persist: false }`** — `JSON.stringify`
  превращает Map в `{}`.
- **Прогрев греет ЛЁГКОЕ и только его.** Реестры шести разделов (1–3 КБ) — на
  каждой загрузке; полный каталог (109 КБ) — под `/lists`, где живёт его
  единственный потребитель; фото не греются вовсе. Просьбу прораба «грузить
  заранее всё» исполняем в этих границах и говорим об этом вслух.
- **`preconnect` к Supabase в `index.html`** подставляет Vite из `%VITE_SUPABASE_URL%`
  — второго источника правды нет. Предзагрузки иллюстрации там больше нет: тег
  висел на всех адресах, а картинка нужна двум.
- **Цифры сети снимать только на прод-сборке.** В dev `StrictMode` дублирует
  каждый запрос — это артефакт инструмента, а не поведение прода.
- **Вес по сети мерить через CDP** (`encodedDataLength` + `requestServedFromCache`):
  `transferSize` у Supabase всегда ноль, там нет `Timing-Allow-Origin`.

### Язык системы (с25) — снят с `equipment`/`lists`, не выдуман

- **Жанр выбирает единица данных.** Таблица — «сравнить много одинаковых по
  колонкам» (сотрудники, машины). Карточка — «узнать свою работу и что-то с ней
  сделать» (списки, планы залов). Третьего жанра не заводим; специальная сетка —
  только там, где данные двумерны (матрица залов).
- **Счётчик отвечает на ОДИН вопрос и печатается в ОДНОМ месте:** без фильтра
  «Сущность: всего», с фильтром «Найдено: видно из всего».
- **У картинки три роли, четвёртой не нужно:** предмет в строке (это ДАННЫЕ),
  пустое состояние раздела, плитка главной.
- **Загрузка при пустом экране — скелет формы контента, никогда не текст.**
- **Картинка появляется плавно и ровно один раз** (с26, `PhotoThumb`):
  плейсхолдер до загрузки, кадры движения общие с витриной оборудования
  (`equipment-image-arrive`). Реестр показанных адресов — чтобы возврат в раздел
  не проигрывал анимацию заново; `ref`-колбэк по `complete && naturalWidth` —
  потому что картинка из кэша грузится раньше, чем React повесит `onLoad`.
- **Главная обязана помещаться в экран целиком** (с26). Это витрина выбора:
  прокрутка прячет половину разделов. Вертикальные метрики считают ВЫСОТУ окна,
  нижний ярус три в ряд от 950 px, выравнивание ярусов включается только там,
  где их честно два.
- **ТВ — отдельный жанр по построению.** Всё на витрине читается с того же
  расстояния, что доска. Домовые `.data-panel`, `.state-block`, `.button` на
  витрину не тащим.
- **Кегль доски ТВ — одна формула на всех** (с21, подтверждено с25). Не влезает —
  переносится БЕЙДЖ, имя остаётся целым.
- **Резерв полосы под арт завязан на его наличие** (`:has`, с25).

### Карточка-профиль (с27, проверена третьим дровером в с28)

- **Контракт выдержал третий случай без единой правки `ProfileCard`** (с28) —
  ровно то, ради чего он писался. Оборудованию понадобились две добавки СНАРУЖИ
  контракта: `EquipmentIcon` в `EquipmentVisual` и `equipmentHeadParts` в
  `format.ts`.
- **Заголовок карточки оборудования разный у двух способов учёта.** У серийной
  единицы — номер плашкой (как госномер), у количественной — «Бренд Модель»:
  настоящего номера у неё нет, в колонке лежит штамп импорта. Аналогия с
  госномером работает только там, где номер есть у каждого.
- **Штамп импорта (`AUTO-…`, `QTY::…`) в карточке не показывается вовсе.** Для
  базы это значение, для человека — пустое место; различаются по форме, потому
  что колонка одна. В проде 46 таких единиц, ещё 4 без кода, 1432 серийных.
- **Картинка модели в режиме чтения живёт в шапке, в режиме правки — полосой под
  ней:** там она показывает, во что превратится единица при смене категории, и
  92 px для этого мало.


- **Профиль отвечает на два вопроса по очереди.** Сначала «тот ли это» — шапка:
  фото, имя или госномер, ОДИН главный факт. Потом «что с ним» — секции реквизитов
  и бейджи состояния. Второй факт в шапке возвращает её в тот же список, от
  которого уходили.
- **Один и тот же факт печатается один раз.** Должность ушла из реквизитов в
  шапку, марка с моделью — тоже; срок живёт ТОЛЬКО бейджем, потому что дата стоит
  внутри него.
- **Незаполненный срок молчит** (решение прораба): серый бейдж «не указан»
  читался бы как проверенный факт. Порог «скоро» — 30 дней, `lib/expiry.ts`.
- **Цвет обязан дублироваться словом.** «истёк» / «истекает» / «действителен до» —
  три разных текста. Один текст на три цвета не читает ни дальтоник, ни тот, кто
  смотрит мельком.
- **Реквизиты профиля — ОДНА колонка** (`.detail-list--profile`). Две давали серую
  дыру на нечётном числе полей: подложка просвечивает там, где ячейки нет, а
  правило на чётность бесполезно — поля фильтруются по заполненности.
- **Раскладку шапки гейтит СОДЕРЖИМОЕ, а не ширина окна**
  (`.drawer__header:has(.profile-head)`): дровер всегда 480 px, и тесно ему, а не
  окну. Медиазапросов не добавляли.
- **Любое поле копируется нажатием**, подтверждение — цвет плюс слово. Кнопка
  растянута на ячейку, поэтому выделение значения мышью потеряно — осознанный
  размен. Общий `copyText` живёт в `lib/clipboard.ts` (переехал из `features/halls`).
- **Внутри `<dl>` обёртка `div` содержит ТОЛЬКО `dt` и `dd`.** Кнопка и
  подтверждение стояли их соседями — невалидно; уехали внутрь `dd`.
- **Заголовки секций профиля — свой лёгкий стиль**, не `.panel-heading`: тот
  остаётся у оборудования, модели и каталога.
- **Фото шапки приходит пропом со страницы** уже подписанным — свой запрос отложил
  бы первый кадр и завёл второго судью «какое фото главное».
- **Скачивание файла включает параметр в подписанном адресе** (`toDownloadUrl`):
  HTML-атрибут `download` на чужой домен браузер игнорирует молча. Фото качается,
  документы открываются на просмотр.

### Стили (с25–с26)

- **`styles.css` — баррель из шести `@import`, и порядок в нём работающий код.**
  `06-responsive.css` обязан идти замыкающим.
- **Локальные `@media` внутри блоков остаются на местах.**
- **Разделители сетки карточек рисуют сами карточки тенью,** а не подложка.
- **Общие правила (`.list-card`, `.data-table`, `.state-block`) не переписываем —
  расширяем модификатором.**
- **Правишь размер — грепай ВСЕ правила селектора** (с26): жёсткий `min-height`
  с двумя классами перебивал общий `clamp` специфичностью, и правка «не работала».
  `getComputedStyle` показывает победителя за один вызов.

### Тексты и числа

- **Тексты интерфейса — только `tr(ru, uz)`.**
- **Своего словаря окончаний не ведём** (`lib/date.ts`): склонения отдаём `Intl`.
  Где склонение неизбежно — форма «метка: число».
- **Даты на `uz` печатаются в ISO** — свойство `Intl`, вопрос продуктовый, в backlog.

### Проверки

- **Разделение проверок (с24):** механический прогон — работа агента через
  Playwright; вкусовая приёмка — прораба.
- **Браузер профиля — единоличный ресурс** (с27): агенты воркфлоу открывают в нём
  свои стенды и перехватывают вкладку. Прогон глазами и воркфлоу одновременно не
  живут — воркфлоу останавливать.
- **Заголовки ответа чужого домена из страницы не видны** (с27): `Content-Disposition`
  не в безопасном списке CORS, `fetch` вернёт `null` и с ним, и без него. Проверять
  `curl`-ом.
- **Проверка без контроля чувствительности не проверка (с24).** Сломай образец
  нарочно и убедись, что метод это видит.
- **Кэш чистить только на успокоившейся странице** (с26): запрос прошлого захода
  дописывает стёртый ключ обратно, и контроль показывает не то, что меряет.
- **Пиксельное сравнение скриншотов — не судья** для страниц с ленивыми
  картинками и временем на экране (с25).
- **Мерить, а не подбирать (с25).**
- **Гипотеза из чтения кода — не факт (с24).** Для визуальной задачи планировщику
  скриншоты нужны ДО выводов (с25).
- **Упавший агент воркфлоу оставляет правки частичными** (с25). Гейты обязательны.
- **Перф-находку без объёма данных не принимать (с23).**
- **Аудит отвечает на тот вопрос, который ему задали (с23).**
- **Возражение агента против плана ведущего — не шум (с23).** Обратное тоже:
  возражение ПРОРАБА против решения агента разворачивает решение (с26 — разделение
  выдачи сотрудников выросло именно из него).
- **Права — `/rls-verify`;** RPC и Storage — smoke curl-ом.

### Залы

- **Печать матрицы (с22, развязана в с24):** цвет зала — ЧЕРТА под именем; панель,
  шапка и полоса сводки — `display: contents`; серые токены темнеют внутри
  `@media print`; поле сверху 14 мм. Проверять только по самому PDF. gotchas §14.
- **На бумаге список свободных полный, на экране обрезан шестью именами** (с25).
- **Цвет зала живёт в БАЗЕ (с24).** Правка `HALL_PALETTE` красит только НОВЫЕ залы.
- **Залы — матрица (с20):** позиции — строки, залы — колонки, ячейка = максимум
  один человек ИЛИ слот «Наём» (UNIQUE `cell_key`).
- **Слот «Наём» (с21):** `is_external` + CHECK; кнопка — только в операторских
  строках (правило в UI, backlog); FK на employees — `on delete cascade`.
- **Имена в расстановке — «Имя Фамилия»** (`employeeDisplayName`, с21).
- **Залы — общий черновик staff (с20/с21):** изоляции между staff нет по замыслу.
  **Один менеджер в работе (с23, прораб).**
- **ТВ `/halls/:planId/tv` (с21) — инструмент планёрки:** назначение кликом,
  структура только в редакторе; поллинг 30 с через `silentRefresh`; портал
  пикера — `fullscreenElement ?? body`.
- **Кэшируется ТОЛЬКО список планов** (с26). Сам план и ТВ — никогда: общий
  черновик, который правят несколько человек, и витрина, перечитывающая его
  каждые 30 секунд. Сбрасывает список КАЖДАЯ запись модуля — `updated_at` двигает
  база и на правку зала, и на правку ячейки, а он виден на карточке.
- **Текст для чата (с22):** по залам, не матрицей; **без markdown**.
- **Справочник позиций (с20):** общий на всех; FK из планов НЕТ намеренно.
- **Один человек в нескольких ячейках — норма**; скрепка = несколько позиций
  в ОДНОМ зале, ×N — по всему плану.
- **Директор не назначается на залы** (с21).

### Прочее

- **`HTTP 200` + ноль строк = отказ политики,** а не успех (с22).
- **`document.title` — владелец один** (`LanguageProvider`), страница называет
  себя через `useDocumentTitle`. С с25 названы семь страниц.
- **Safari: кнопка с `autoFocus` + `onBlur`-гашением обязана иметь
  `onMouseDown preventDefault`** (с21, gotchas §6).
- **Двухшаговые кнопки (`useArmedAction`) держат взвод 4 секунды** (с24) — в
  агентском прогоне жать двойным кликом.
- **`git branch --show-current` перед `git add`** — привычка остаётся.
- **`cd` в Bash переживает вызовы** (с25).
- **Схема — только миграциями.**
- **Фото в xlsx: якорь `oneCellAnchor` + АБСОЛЮТНЫЕ координаты в `a:xfrm`** (с19/с20).
- **Фото для документов — `employees.document_photo_id`** (с19), NULL → последнее.
- **Язык документа ≠ язык интерфейса** (с19); **новые стили xlsx — только в хвост
  `styles.ts`** (с19); **руководитель для документов — `companyDirector`** (с19).
- **Госномер: канон в базе** (с18); **машина↔водитель — M2M** (с18);
  **сотрудники: уникальность по документам** (с17); **файлы — только добавление**.
- **Фото ужимает клиент** (с17, `maxSide` 1600, JPEG 0.85).
- **Пачечный upsert/insert под RLS — `defaultToNull: false`** (с18).
- **Ошибки вставки разбирать по ИМЕНИ ограничения** (с14); `.contains()` — тип (с14).
- **Состояние каталога — в адресе** (с11/с15); каталог модельный (с15).
- **Порог входа в библию (с12):** только невосстановимое чтением `src/react`.
- **`security definer` в `private.*` цел** (с12). **Роли `admin` в проде НЕТ** (с15).
- **`reservation_start`/`reservation_end` — дата мероприятия, не бронь.**
