# Воксельный мир — бриф (согласован прорабом в с46, 2026-10-06)

Направление после закрытия вех 3–4: система становится «игровой» — 3D-мир поверх
рабочих экранов. Внутренний продукт, поэтому решения прораба свободные.

## Решения прораба

- **Three.js, настоящее 3D.** Вес бандла и старые телефоны — не ограничение.
  Стек — `react-three-fiber` (+ `drei`); онбординг по правилу CLAUDE.md: доки,
  версия, шпаргалка `docs/system/libs/`.
- **Граница игры — разделённый экран.** Снаружи кампус как главная и навигация;
  внутри здания слева 3D-сцена как живой выбор объекта, справа рабочая панель
  (карточка, форма, экспорт — нынешние компоненты). 3D заменяет список-таблицу,
  а не работу.
- **Склад — исключение по масштабу:** 1471 единица кликабельными не рисуется;
  стеллажи по категориям (218 моделей), клик по стеллажу — каталог справа,
  отфильтрованный, с поиском.
- **Макет раньше кода продукта.** Продукт не трогаем до «да» прораба по макету.

## Облик

**Схема, не реализм (прораб с46).** Белый мир на сетке — как фон приложения: земля
светлая, с тонкой сеткой, без неба, погоды и времени суток, без теней «как в жизни».
Здания и машины — сборки из кубов без текстур в токенах ARGO, акценты только
цветом (как метки залов). Генерируются из данных (6 машин в базе — 6 фургонов
в гараже). `prefers-reduced-motion` — статика.

Кампус: офис (списки), склад (оборудование), гараж (машины), отели/площадки
(новая сущность `venues`, сейчас у списка только текст `client_name`/`venue` —
`planner`), фигурки сотрудников. В день мероприятия: сцена на крыше отеля, фургон
едет от гаража. Числа на табличках — `home_summary`.

Телефон 390: разделённый экран не встаёт — сцена сверху, панель листом снизу,
либо сцена только картой.

## Макет (цель с47)

Один HTML на Three.js, две сцены: кампус (без мероприятий / с мероприятием сегодня)
и гараж с разделённым экраном. Прораб смотрит живьём, крутит камеру, решает.

## Открытые риски

- Редизайн с31–с39 не принят против макета; второй визуальный слой поверх
  непринятого первого — принять или сознательно отложить.
- Доступность 3D-навигации: все здания и объекты обязаны иметь клавиатурный и
  текстовый путь (нижняя панель, прямые ссылки остаются).

## Приёмка макета (с47)

- **Направление и стиль приняты прорабом** («схема на белой сетке» — да). Макет —
  `voxel-s47.html`, шпаргалка — `docs/system/libs/three.md` (Three r186, CDN).
- Находки первого прохода: здания и машины скучные — нужна детализация в тех же
  кубах; «мероприятие сегодня» как отдельная вкладка не читается — стало
  переключателем состояния кампуса с заметными изменениями (сцена у отеля, фургон
  в пути, люди с кейсами, карточка события, числа на табличках).
- **Следующий вопрос прораба — внедрение в продукт:** «лаконично, не мешает, но
  прикольно». Эскиз ответа: кампус заменяет главную (числа `home_summary` на
  табличках, здания = навигация); внутри раздела 3D слева от нынешних панелей,
  сворачивается кнопкой в обычный список; на телефоне сцена сверху как карта.
  Решение — после «да» по второму макету.

## Решение о внедрении (прораб, с47)

**Правило:** 3D не стоит на пути основного сценария (редактор, каталог, формы).
Где живёт мир:

1. **Главная = кампус.** Здание = плитка, табличка = число `home_summary`, клик =
   раздел. Нижняя панель и меню — текстовый путь. Без WebGL / `reduced-motion` —
   нынешние плитки (откат бесплатный). Телефон: кампус сверху как карта, плитки ниже.
2. **«Сегодня» без новой сущности:** список или план залов с сегодняшней датой
   включает состояние «мероприятие» (фургон, сцена у отеля, карточка с `venue`).
   Таблица `venues` — только когда отели понадобится различать.
3. **Гараж для `/vehicles`:** разделённый экран, машины из базы, карточка справа.
4. **Залы** — кандидат на третий вид плана, отложено. **Оборудование, сотрудники,
   списки — без 3D** (поиск, фото и документы важнее мира).

Технически: Three.js ленивым чанком только на главной и у машин, прогрев после
входа. Следующий шаг макета — кампус внутри оболочки с31 (сайдбар, нижняя панель),
чтобы оценить «лаконично и не мешает».

**Навигация наверх (идея прораба, с47):** сайдбар отдаёт ~240 px ширины, которой не
хватает и 3D, и таблицам; верхняя полоса ~56 px. Риск — две полосы хрома подряд
(навигация + шапка страницы); решение — узкая тёмная полоса, заголовок страницы без
второго фона. Третий проход макета показывает оба варианта переключателем.

**Находки прораба по проходам 3–4 (с47):** отель с кампуса убран (кампус = офис,
склад, гараж; мероприятие — выезд за край карты, карточка события у выезда);
здания — игрушечный масштаб, офис эталон; выбор — заливка круга красным, не
покраска кольца; переход в гараж быстрее на 30 %; сцена подбирает камеру и
раскладку машин под пропорции окна (один ряд на широком, два на узком).

## HUD и облик (с48)

- **HUD — направление «Знаки» (прораб):** таблички — вывески на ножке со счётчиком, событие —
  указатель «выезд», кнопки-дубли со значками-силуэтами. Отвергнуты «Чертёж» (выноски без
  коробок) и «Бирки» (складская бумага). Доработка заказана по четырём осям: скругление,
  вес, таблички, кнопки и карточка; варианты веса B2/B3 ждут выбора.
- **Зоны HUD на реальном кадре** (вместо чертежа с47): плашка дня — слева сверху, кнопки —
  слева снизу, карточка события — справа снизу у выезда. Причина: по чертежу плашка ложилась
  на склад, кнопки — на указатель выезда.
- **Подпись машины = модель + знак госномера с флагом UZ** (прораб: одного номера мало).
- **«Слишком квадратно» (прораб):** мир ищет менее кубический язык — стенд
  `voxel-style-s48.html`, оси форма (кубы / галька / игрушка / контур), цвет (белая схема /
  красные крыши / ночь / дуотон), насыщенность. Габариты, расстановка и плотность деталей
  между вариантами не меняются. Выбор не сделан.

## Облик принят, настройки мира (с49)

- **HUD — «Знаки B2»** (тёмные вывески зданий, остальное светлое).
- **Форма — «Галька + контур»** (`softline`): скруглённые объёмы со светом + линия 2 px
  (`LineSegments2`; обычный `LineSegments` всегда 1 px и шёл лесенкой). Остальные формы
  живут только на стенде `voxel-style-s48.html`. Ось «насыщенность» и палитры «Крыши» /
  «Дуотон» сняты.
- **Настройки мира — выбор пользователя, не константа (прораб):** отдельная вкладка
  «Настройки» с живым предпросмотром главного хаба. Оси: цвет (белая схема / ночь) и
  контур (мягче / светлый / бледный; чёрный снят как слишком контрастный). В ночи контур
  тёмный по серой стене — светлая линия, тускнея, проходит через цвет стены.
- **Не решено:** где живёт настройка. Предложение ведущего — `localStorage` на устройство,
  единственный владелец, без копии в базе (облик, не данные; `users` клиенту не читается).
- **Мир из трёх квадратов по кругу (прораб):** «Кампус» → «Площадки» (работаем сейчас и
  скоро: здание места, грузовик при списке, отель при расселении) → «Где работали» (архив
  мест с историей). Соседи видны плитами с крупной надписью на земле: наведение — подсветка
  и подъём, клик — перелёт. Квадрат места вычисляется из дат привязанного, флага нет.
  Чертёж зон — `voxel-world-s49.html`. Требует таблицы мест `venues`.
- **Имена над человечками (прораб):** чип с именем из `employees`, слабее вывесок зданий.
