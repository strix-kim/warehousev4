# 06-design-system — ARGO Warehouse

Как продукт выглядит и по каким правилам: токены, палитра, типографика, брейкпоинты,
примитивы, изображения.

Вся стилизация — **один файл `src/react/styles.css` (900 строк)**, без CSS-модулей,
препроцессора и CSS-in-JS. Классы — плоские BEM-подобные имена. Единственная внешняя
UI-зависимость — `lucide-react` (иконки); Tailwind, Radix, Headless UI, MUI и подобных
в проекте нет.

**Файл за порогом распила (900 > ~800)** — кандидат на разбиение по слоям при первой
крупной правке вида.

## 1. Токены

Все переменные — в одном блоке `:root`, без light/dark: **тема одна, переключателя нет.**

| Группа | Токены |
|---|---|
| Текст | `--ink` `#171c20` · `--ink-soft` `#5e686f` · `--ink-faint` `#8b949a` |
| Поверхности | `--surface` `#ffffff` · `--surface-soft` `#f7f8f6` |
| Границы | `--line` `#e2e5e1` · `--line-strong` `#ccd1cc` |
| Акцент | `--accent` `#ef1236` (фирменный красный ARGO) · `--accent-strong` `#cf0d2d` |
| Статусы | `--success` / `--success-bg` · `--warning` / `--warning-bg` · `--danger` / `--danger-bg` |
| Геометрия | `--radius-sm` 8px · `--radius-md` 12px · `--radius-lg` 18px · `--shadow` |
| Сайдбар | `--sidebar` `#0c1116` — средний тон градиента |

Две инлайновые переменные задаются из React через `style={}`:
`--equipment-image-ratio` и `--equipment-image-width` (`EquipmentVisual.tsx`).

## 2. Что в этой системе работает, а что декоративно

**Цветовые токены работают.** `--accent`, `--line`, `--ink-*` используются
последовательно и покрывают почти все обращения к цвету.

**Геометрические токены — нет.** `--radius-lg` объявлена и **не используется ни разу**.
Подавляющее большинство `border-radius` — числа руками, россыпью от 4 до 999 px без
видимого шага. Переменных под отступы нет вообще. Тень одна (`--shadow`), рядом полтора
десятка inline-теней под конкретные компоненты.

**Вывод: шкалы отступов и радиусов как системы не существует.** Есть работающая цветовая
система и декоративные геометрические токены поверх ручных значений. Заводя новый
компонент, не рассчитывай найти шкалу — её нет.

**Графитовая основа не токенизирована единым значением:** `#171c20` (текст), `#0c1116`
(сайдбар), `#0d1217` (панель логина), `#10161b` (карточка каталога на главной) — семейство
близких тёмных серых, а не одно значение.

**Светлый фон страницы `#f3f4f2` — хардкод, ни разу не через токен**, и объявлен дважды:
в `:root` и в `html`. **У `body` фона нет вообще** — страница выглядит светлой за счёт
фона `html`, который браузер распространяет на канву.

Красный ошибки (`#b64242`) визуально отличён от акцентного (`#ef1236`), так что «ошибка»
и «фирменный акцент» не смешиваются.

## 3. Типографика

Шрифт — **только системный стек**, ничего не подключается: ни `@font-face`, ни ссылок на
Google Fonts.

```
-apple-system, BlinkMacSystemFont, 'Segoe UI', Arial, sans-serif
```

Заголовки — `font-weight: 750` (валидно как произвольное число, браузер округлит до
ближайшего доступного начертания системного шрифта). `h1` — `clamp(28px, 3vw, 40px)`,
`letter-spacing: -0.035em`. Размер шрифта тела явно не задан — браузерный дефолт.

Моноширинный текст (серийники, ID) — класс `.mono` с **`font-size: 13px !important`**.
Побочный эффект: переопределить размер можно только ещё одним `!important`.

**У каждого правила одно место объявления** — хвостовой readability-блок влит в исходные
правила в с5 (118 переносов, эквивалентность каскада проверена машинно). «Финальный
размер определяется порядком каскада» больше не описывает этот файл.

## 4. Брейкпоинты

Восемь медиазапросов, из них три мобильных — и это разные вещи:

| Условие | Что меняет |
|---|---|
| `max-width: 1500px` | Плитка главной 3 → 2 колонки |
| `max-width: 1050px` | Сайдбар схлопывается в узкую колонку (76 px, иконки без подписей), `.list-grid` 3 → 2, `.editor-grid` в одну колонку |
| `(min-width: 701px) and (max-width: 1050px)` | Планшет: панели редактора рядом, поверх правил блока 1050 |
| **`max-width: 820px`** | **Главный брейкпоинт ОБОЛОЧКИ.** Сайдбар → нижний таб-бар, полоса `.mobile-account` над контентом, таблицы → карточки (`tbody tr` становится гридом), дровера на весь экран, `.toolbar` в столбик. Тач-размеры 44 px, степпер 46. **`font-size: 16px` на полях ввода — чтобы iOS Safari не зумил при фокусе** |
| **`max-width: 700px`** | **Телефонная раскладка РЕДАКТОРА.** Липкие вкладки (57 px), панели по одной, тулбар каталога sticky под ними, действия в футере, реквизиты уезжают ПОД панели через `order` на flex-контейнере |
| `max-width: 520px` | Заголовок дровера в перенос, сетка правки в одну колонку |
| `(hover: hover) and (pointer: fine)` | Hover-эффекты только там, где есть курсор — на тач бейдж не залипает повёрнутым |
| `prefers-reduced-motion: reduce` | Один блок, гасит `scroll-behavior`, анимации и транзишены |

**JS-граница одна — 820 px (`lib/breakpoints.ts`), и редактор её не читает.** Высота
липких табов (57) живёт в двух местах синхронно: `.quick-catalog-toolbar { top }` в CSS и
`MOBILE_TABS_HEIGHT` в `ListEditorPage.tsx`. Пара «820 в CSS ↔ 820 в JS» тоже правится
руками.

**Зоны касания 44 px объявлены точечно, не единой утилитой** — базовые правила несут
итоговый размер, мобильные донастройки живут в блоке 820.

### Ячейку-константу на телефоне убирают ИЗ DOM, а не прячут стилями

В карточной раскладке каталога ячейки «Количество» и «Статус» рисуются, только когда
значение отличается от общего по каталогу — иначе на первый экран помещалась одна
карточка ради полей, одинаковых у 97 % строк.

**Решение принимается в разметке (флаг `isMobile`), а не через `display: none`:**
спрятанный элемент остаётся в `:last-child` и `nth-child`, а строка — грид в две колонки,
и чётность ломается — рядом с последней ячейкой висит пустая половина с рамкой.
Последняя ячейка занимает обе колонки правилом `td:last-child:nth-child(even)`; первая
вне счёта, она и так во всю ширину.

## 5. Примитивы `AppSelect` и `AppDatePicker`

Оба — кастомные компоненты на нативном `<button>` + `createPortal` в `document.body`.

**`AppSelect`** — попап с `role="listbox"`, опции `role="option"` + `aria-selected`.
Позиция считается вручную в `useLayoutEffect`: ширина `max(rect.width, 220)`, высота —
**эвристика** `min(options.length * 42 + 12, 330)`. Высота именно оценивается, а не
измеряется: координаты нужны до появления попапа в DOM, иначе первый кадр он рисует в
углу и прыгает на место. Открывается вниз, если помещается, иначе вверх.

> **Контракт listbox заявлен и не исполнен.** Нет навигации стрелками, Home/End, выбора
> по Enter/Space, `aria-activedescendant`. Для скринридера это хуже нативного `<select>`
> (`04-architecture` §13).

**`AppDatePicker`** — попап `role="dialog"` с **`aria-modal="false"`**: фокус из него не
запирается, и это честно отражено в атрибуте. Узбекские месяцы и дни недели зашиты
вручную (`yanvar…dekabr`; `Du, Se, Ch, Pa, Ju, Sh, Ya`), не через `Intl` — для остальных
локалей используется `Intl.DateTimeFormat`.

**Оба при скролле и ресайзе закрываются, а не перепозиционируются** (общий
`lib/usePopoverLayer.ts`): позиция считается один раз при открытии, поэтому «закрыть» —
единственный способ не оставить попап оторванным от триггера. Исключение: прокрутка
внутри самого списка не закрывает — иначе список из 56 подкатегорий нельзя пролистать.

Оба возвращают фокус на триггер при выборе. **В drawer'ах такого возврата нет** — проект
не согласован сам с собой, и образец правильного поведения лежит в соседнем каталоге.

## 6. Изображения

| Каталог | Содержимое |
|---|---|
| `public/brand/` | 3 PNG: `apple-touch-icon`, `favicon-32`, `video-engineer-avatar` |
| `public/illustrations/` | 3 WebP: `av-team`, `av-warehouse`, `equipment-kit` |
| `public/equipment-images/` | **176 WebP** фотографий оборудования, и больше ничего |

Карта соответствия живёт в `src/react/generated/equipmentImages.ts` (176 записей, числа
с файлами сходятся), генерируется из `scripts/image-cache/manifest.json`. Моделей в
каталоге 218 — остальные показывают категорийную иконку.

**Контракт именования эмитит генератор**, а не компонент: `normalize()` и
`equipmentImageKey()` вкомпилированы в сгенерированный файл исходником из
`scripts/fetch-equipment-images.mjs`. Правка `normalize` там приезжает сюда сама; своей
копии контракта у `EquipmentVisual` больше нет. Ключ — `normalize(brand)::normalize(model)`,
например `"apple::mac mini"`.

**Промах ключа и битая ссылка визуально неразличимы:** обе ветки показывают
категорийную SVG-иконку, выбранную эвристикой по регэкспам над `type`/`subtype`
(дефолт — `PackageOpen`). Успешно загруженное фото запоминается в module-level `Set`/`Map`
на время жизни вкладки, чтобы не мигать при повторном рендере.

## 7. Правило иллюстраций

> Иллюстрации — на входе, главной и в пустых/обучающих состояниях.
> Реальные фото — в превью конкретной модели.

**Правило зафиксировано аудитом, но ничем не проверяется** — нет линта, который запретил
бы воткнуть иллюстрацию в таблицу. Фактическое использование ему не противоречит.

## 8. Что не проверялось

- **Контраст цветов (WCAG AA/AAA) не проверялся ни для одной пары фон/текст.**
- Реальный визуальный результат снимался прорабом глазами, не автоматически — скриншотных
  тестов в проекте нет.
- Порядок свойств и стайл-гайд CSS не формализованы.
