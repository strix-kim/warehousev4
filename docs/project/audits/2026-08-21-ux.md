# UX-аудит ARGO Warehouse — 2026-08-21 (сессия 7)

**Предмет:** сценарии, не визуальный стиль. Главный — «собрать список оборудования
на мероприятие → сохранить (необязательно) → скачать Excel». Приоритет платформ по
слову прораба: **компьютер главный**, телефон/планшет вторичны, плюс вывод на большой
телевизор (режим использования ТВ — открытый вопрос №1 ниже).

**Артефакт для приёмки** (решения по каждой находке, ответы на вопросы, кнопка «скопировать
для чата»): https://claude.ai/code/artifact/ec963c3e-d2c2-4356-8fc7-3e0cb5a8543a

**Метод.** 68 снимков живого dev против прод-базы под реальным аккаунтом: четыре
вьюпорта (390×844, 820×1180, 1440×900, 1920×1080) × 17 экранов, плюс замеры
раскладки (`metrics.json`: высота документа, координаты блоков). Четыре аудитора
(Opus) по сценариям — редактор-телефон, редактор-десктоп/ТВ, реестр и жизненный цикл,
каталог и заведение техники; каждая находка привязана к `файл:строка` и/или снимку.
Сверху — адверсариальная сверка ключевых утверждений по коду и `SELECT`-ами в прод
(архитектор). Две гипотезы съёмки **опровергнуты и в отчёт не попали**:
«полупрозрачная» правая панель редактора — артефакт полностраничного скриншота
(живой `opacity` = 1); «перенос бейджа на вторую строку» — на самом деле поворот
кнопки hover-эффектом. Подробные отчёты аудиторов — `2026-08-21-ux/01…04`.
База и код в ходе аудита **не менялись**; Playwright поставлен вне репозитория.

## 1. Вердикт

Интерфейс собран аккуратно и красиво, но **в порядке, обратном работе человека**:

1. **Редактор — анкета, к которой прикручен каталог.** Шесть полей реквизитов стоят
   между «Создать список» и первой единицей техники: 26 % первого экрана на 1440,
   638 px (0,75 экрана) на телефоне. При этом сам интерфейс подписывает их «можно не
   менять».
2. **Дефолты притворяются данными.** Поля стартуют чёрным текстом «Техническое
   обеспечение мероприятия / Заказчик не указан / Площадка мероприятия», очистить их
   нельзя (`onBlur` возвращает дефолт), и эти строки уезжают в базу, в Excel под гриф
   «УТВЕРЖДАЮ» и в имя файла. В проде уже лежат два неотличимых списка.
3. **Результат действия не виден.** Подтверждение сохранения рисуется за нижней кромкой
   экрана (формула высоты сетки ошибается на ~94 px) или в скрытой мобильной панели;
   после сохранения список не показывает своего имени.
4. **Есть тупики без выхода.** Подтверждённый список-план нельзя ни выдать, ни
   исправить — только удалить. Правки сохранённого списка не автосохраняются, а
   несохранённый черновик бережётся сутки. На телефоне нельзя выйти из аккаунта.
5. **Каталог показывает единицы там, где человек думает моделями:** 93 % строк —
   повторы (одна модель — 596 строк = 75 страниц на телефоне), фильтра по категории
   нет, «В наличии» означает «не выдано», а не «свободно на дату».
6. **Интерфейс разговаривает с разработчиком:** «поиск, фильтр и страницы считает
   база», «Подключены реальные данные Supabase», «РАСШИРЕННЫЙ УЧЁТ», статичный
   «Быстрый процесс 01/02/03», «Текущая локация» с мёртвым шевроном.

Блокеров, не дающих собрать список, нет ни на одной платформе. Но цена главного
сценария складывается из десятков мелких потерь, и две из них портят данные (п. 2, п. 4).

## 3. Целевая картина

### 3.1. Редактор — десктоп и ТВ (1440–1920+)

Подробно: `2026-08-21-ux/02-editor-desktop.md`, раздел «Предлагаемая раскладка».

1. **Шапка `position: sticky`**: назад · **имя списка** · единственная пара
   «Сохранить / Скачать Excel» · место под подтверждение/ошибку. Дубли в футере
   уходят; в футере остаются «Всего единиц» и «Очистить» (с подтверждением).
2. **Реквизиты — полоса в одну строку** (`Название · 21.08.2026 · Заказчик ·
   Площадка · [Реквизиты ⌄]`), раскрывается в нынешнюю сетку. Раскрыта автоматически,
   когда режим «на согласование» требует заполнения. Экономия ~160 px первого экрана.
3. **Честная высота сетки**: `clamp(420px, calc(100dvh − 246px), 900px)` — футер
   перестаёт резаться, прокрутка страницы исчезает.
4. **≥1800 px — три колонки**: рельс категорий (210 px) · каталог · рабочий список.
   Категории уже считаются в `ListEditorCatalog`; это перерисовка, не логика.
5. Если ТВ — **пассивное табло**: отдельный проход по ~15 объявлениям `font-size`
   в строках каталога/списка (всё в px, `html { font-size }` не поможет).

### 3.2. Редактор — телефон (≤700 px)

Подробно: `2026-08-21-ux/01-editor-mobile.md`, раздел «Предлагаемая раскладка».

Без отдельной мобильной архитектуры — тот же JSX, порядок задаёт CSS `order`:
шапка (компактная, без кнопок) → плашка черновика → табы (sticky) → панель
(каталог или список; тулбар поиска sticky) → **реквизиты внизу**. Плавающая полоса
становится полосой действий на обеих вкладках («В списке N →» + Excel на каталоге;
«Сохранить / Скачать» на списке). Память прокрутки при переключении вкладок.
Планшет 820 чинится разрезом медиазапроса 820 → 700 (JS-брейкпоинт редактор не
читает, ключи кэша не сдвигаются).

### 3.3. Политика дефолтов (U1)

**Рекомендую основной вариант — «пусто в форме, честно в документе, обязательно
только для заказчика»:**

- `name`, `clientName`, `venue` стартуют пустыми с нынешними плейсхолдерами;
  `onBlur`-возврат и `selectDefaultInputValue` удаляются.
- Пустое имя при сохранении/экспорте → **автоимя `Список 21.08.2026 · 14:32`**
  (уникально, годится для реестра и имени файла).
- Пустые заказчик/площадка **в документ не пишутся** (строка метаданных не выводится).
- Режим **«на согласование» требует реквизитов** — единственная обязательность во
  всём редакторе, ровно там, где документ уходит наружу. Рабочий Excel — как раньше,
  без единого поля.
- Имя файла: `2026-08-21_Название_рабочий.xlsx` / `…_на-согласование.xlsx`.

Альтернатива на сегодня (S): дефолты оставить, но снять возврат на `onBlur` и
дописывать дату-время к дефолтному имени при сохранении. Лечит неразличимость, не
лечит «Заказчик: Заказчик не указан» под грифом.

### 3.4. Реестр и карточка

Подробно: `2026-08-21-ux/03-registry-lifecycle.md`, раздел «Предлагаемая структура».

Над карточками — только H1 + «Создать список» и один тулбар (поиск по названию,
заказчику и площадке · период · этап · счётчик). **Первичный идентификатор карточки —
дата мероприятия + заказчик**, название второй строкой. Две кнопки: «Открыть» (для
`draft` — сразу редактор) и «⤓ Скачать ▾» с двумя форматами — одна ментальная модель
с редактором. В деталях: реквизиты (сейчас их там нет) → состав → **текущее действие
этапа развёрнутым** → подробности учёта в `<details>` → правка → скачать → удалить.
Несохранённый черновик — первой карточкой «Не сохранён · вчера 18:40 · Продолжить /
Отбросить».

Тупик U2 структурой не лечится: нужен серверный переход `confirmed → draft` (миграция,
`/rls-verify`) либо запрет подтверждать `abstract`-список с кнопкой «Назначить S/N».

### 3.5. Каталог

Подробно: `2026-08-21-ux/04-catalog-equipment.md`, раздел «Предлагаемый каталог».

Целевой режим «**По моделям**» (строка = модель, «свободно N из M», аккордеон единиц)
требует серверного агрегата (view/RPC по `lower(btrim(brand)), lower(btrim(model))`) —
это L. **Дешёвый первый шаг без схемы:** честная подпись счётчика («Найдено: N позиций ·
M штук»), фильтр по категории (справочник уже греется при старте), сжатая мобильная
карточка (статус/количество/локация — только когда отличаются от типового), «Добавить
ещё такую же» в форме заведения.

## 5. Открытые вопросы прорабу

Ответы меняют объём работ; без них берём вариант «по умолчанию» в скобках.

1. **Телевизор** — монитор оператора с мышью или пассивное табло на стене?
   (по умолчанию: оператор → третья колонка, масштаб шрифтов не делаем)
2. **Как называют списки в жизни** — номер заявки, мероприятие, заказчик? Нужен ли
   период «с — по» вместо одной даты? (по умолчанию: дата + заказчик первичны)
3. **Статусами `confirmed / issued / returned` пользуются**, или всё заканчивается
   Excel? Часто ли правят подтверждённый список? (по умолчанию: пользуются → U2 в
   волне 3 серверным переходом)
4. **Документ «на согласование» уходит внешнему заказчику?** (по умолчанию: да →
   реквизиты обязательны только для него, U1 в волне 2 первой)
5. **S/N отмечают вообще?** Оба списка в проде — `abstract`. (по умолчанию: редко →
   U12 сворачиваем)
6. **Телефон и планшет реально в работе?** Типичный комплект — 5 позиций или 25?
   (по умолчанию: телефон иногда, планшет нет → U15 и U45 во второй волне, U18 в первой)
7. **Локации** — появятся ли реальные (склад / в пути / у заказчика)? (по умолчанию:
   нет → колонку убираем, словарь не строим)
8. **«Свободно» на складе** = «не выдано» или «не расписано ни в один подтверждённый
   список»? (по умолчанию: второе → U30-M в волне 3)
9. **Как заводят технику** — партией из накладной или по одной? (по умолчанию:
   партией → U34-S сейчас, U34-L в бэклог)
10. **Два сохранённых списка с дефолтными именами** — переименовать миграцией или
    оставить? **Битая подкатегория** (1 строка) — чиним `UPDATE`? (оба — необратимые
    правки данных, исполняются только после «да»)
11. **Кто удаляет списки** — одна почта осознанно? **Узбекский интерфейс** кто-то
    использует? (по умолчанию: да/да)

## 6. Что работает хорошо и что нельзя сломать

- **Excel скачивается без сохранения** — ядро продукта; обязательность полей не должна
  превратиться в обязательное сохранение.
- **Каталог редактора свёрнут по моделям** (223 строки вместо 1 480), подсветка
  добавленных, счётчик на кнопке — обратная связь верная, чинить только геометрию (U10).
- **Внутренний скролл панелей редактора**, липкий тулбар поиска, футер `flex: 0 0 auto` —
  страница не растёт от длины списка; при перекомпоновке сохранить.
- **Выборка хранит ключ группы, а не снимок**; восстановление черновика по живому каталогу
  с подсчётом пропавших позиций.
- **Плавающая полоса «Добавлено в список N»** и счётчик в табе на телефоне — расширять,
  не убирать.
- **Экспорт с карточки реестра без открытия списка** — один тап до файла.
- **Drawer на телефоне полноэкранный, футер виден без прокрутки** (реестр).
- **Оптимистическая блокировка карточки**, честное «мы не знаем» в проверке серийника,
  `count` серийной карточки не уезжает в базу.
- **Мобильная таблица каталога без горизонтального скролла**; дебаунс и сброс страницы
  при новом запросе; префетч следующей страницы.
- **Вход на телефоне** — форма на первом экране; календарь даты — удобный.
- Узбекский не ломает ни одного экрана (он компактнее русского).
