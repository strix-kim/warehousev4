# Каталог, карточка единицы, заведение техники, сквозные вещи — находки

Цифры по проду взяты `SELECT`-ами через Supabase MCP (только чтение), они помечены
«прод». Всё остальное — код и снимки.

**Опорные цифры прода:** 1 481 строка каталога = **1 877 физических штук** (35 строк с
`count > 1`, максимум 86 в строке); 218 моделей, из них **111 моделей дают 1 374 строки
из 1 481** (93 % каталога — повторы одной и той же модели); 7 категорий, 56 подкатегорий;
**локация в базе ровно одна — «Офис»**; статусы: `available` 1 475, `unavailable` 5,
`diagnostics` 1, `issued` 0.

## Маршрут пользователя как он есть

### «Сколько свободных Shure SM58» — телефон (390×844)

1. Вход в приложение → нижняя навигация (`styles.css:665-671`) → тап **«Оборудование»**.
2. Первый экран (`mobile--02-equipment--fold.png`): заголовок + описание + красная
   кнопка «Добавить оборудование» во всю ширину + плашка «Позиций в базе 1 481» +
   плашка «Общие данные модели…». Поиск начинается на **385 px**, таблица — на 490 px
   (`metrics.json`, `probes`). **На первом экране помещается ровно одна единица из 1 481.**
3. Тап в поиск → набрать «SM58» → 350 мс дебаунса (`EquipmentPage.tsx:77-83`) → запрос
   на сервер (`api.ts:102-111`).
4. Ответ читать негде, кроме двух мест: плашка «Позиций в базе N» вверху
   (`EquipmentPage.tsx:158-162`) и «Показано 1–8 из N» в подвале таблицы, то есть
   **на 3,7 экрана ниже** (`metrics.json`: `scrollHeight` 3 087, `screens` 3,66).
5. Чтобы получить «свободных», а не «всего», — тап «Все статусы» → тап «В наличии»
   (`EquipmentPage.tsx:189-198`).

Итого: **4 тапа + ввод**, ответ читается как число под подписью «Позиций в базе».
Число — количество СТРОК, не штук (см. F3). Модели SM58 в проде нет вовсе; ближайший
реальный аналог — Beterva SP-BE-2300D, 32 единицы, 32 отдельные строки.

### То же на десктопе (1440×900)

Шаги те же, но на первом экране видно 7,7 строк из 50 (таблица начинается на 343 px,
строка 72 px, `styles.css:207`), а страница вся — 4 101 px.

**Почему десктоп выше телефона:** размер страницы каталога зависит от ширины —
**50 строк на десктопе, 8 на телефоне и планшете** (`api.ts:11-12`, выбор `:16-18`,
граница 820 px `lib/breakpoints.ts:8`). 50 × 72 px = 3 600 px таблицы против 8 карточек
× ~300 px = 2 410 px. То есть десктоп выше не потому, что раздут, а потому, что телефон
показывает в 6 раз меньше данных: **1 481 / 8 = 186 страниц** на телефоне против 30 на
десктопе.

### «Поправить описание/локацию единицы»

Тап по строке → drawer (`EquipmentPage.tsx:235-237`). На телефоне он полноэкранный
(`styles.css:279` `width: min(480px,100%)`, `height:100%`, `overflow-y:auto`), прокрутка
внутри, фон заблокирован (`useModalLayer.ts:23`). Фото модели занимает ~31 % первого
экрана (`mobile--03-equipment-drawer.png`, `.equipment-thumb--large`, `styles.css:225-226`).
«Редактировать» — вверху, видно сразу (`EquipmentDrawer.tsx:219`). После нажатия форма
разворачивается в 11 полей в одну колонку (`styles.css:250` — на ≤520 px сетка полей схлопывается в одну колонку), и
**кнопка «Сохранить изменения» оказывается в самом низу** — 2–3 экрана прокрутки
(`EquipmentDrawer.tsx:260-263`, липкой панели нет).

### «Завести 6 радиосистем с серийниками»

`/equipment/new`. Форма на телефоне — 1 822 px = 2,16 экрана (`metrics.json`), 12 полей.
Единственная кнопка сохранения — **вверху** (`EquipmentCreatePage.tsx:196-198`), потому
что правая колонка предпросмотра со второй кнопкой на телефоне скрыта
(`styles.css:773` `.equipment-preview { display: none }`, кнопка `EquipmentCreatePage.tsx:293`).
После сохранения — экран успеха с «Открыть каталог» и «Добавить ещё» (`:171-184`).
«Добавить ещё» вызывает `resetForm()`, который стирает **всё, включая бренд, модель,
категорию и подкатегорию** (`:88-107`). Шесть единиц одной модели = шесть полных
заполнений формы.

### «Из каталога добавить модель в список»

**Такого пути нет.** В `src/react/features/equipment/` нет ни одной ссылки на списки,
кроме импорта функции сброса кэша (`api.ts:6`). Ни в строке таблицы, ни в drawer'е
кнопки «в список» нет. Обратной ссылки («в каком списке эта единица сейчас») тоже нет.

### «Первый вход нового сотрудника»

`/login` — две панели. На телефоне брендовая панель ужата до 210 px, иллюстрация и
подзаголовок скрыты (`styles.css:731-738`), форма начинается сразу — прокрутки до формы
нет. Переключатель RU/UZ стоит первым элементом карточки (`LoginPage.tsx:74`). Ошибка
входа одна на все причины: «Не удалось войти. Проверьте логин и пароль.» (`:50`).

## Находки

### F1. Каталог показывает единицы там, где человек думает моделями: 93 % строк — повторы

- **Серьёзность:** серьёзно (на телефоне — близко к блокеру)
- **Где:** `mobile--02-equipment.png`, `desktop--02-equipment--fold.png` (Akai APC Mini ×2,
  Behringer B210D ×2, Behringer UMC202HD ×2 подряд); `EquipmentPage.tsx:213-264`;
  `api.ts:96-99` (сортировка `type, brand, model, id`). Прод: 111 моделей из 218 дают
  1 374 строки из 1 481; ITC TS‑0370HD — **596 строк**, Televic Confidea BP G4 — 98.
- **Симптом:** поиск «TS-0370HD» на телефоне возвращает 596 строк = **75 страниц по 8**,
  и все 596 карточек одинаковы, кроме серийного номера. Ответить «сколько их» можно
  только прочитав счётчик, а не глядя на список; пролистать список бессмысленно.
- **Почему мешает:** главный складской вопрос — «есть ли модель и сколько». Каталог
  отвечает на другой вопрос — «покажи мне каждый экземпляр». В редакторе списков
  группировка по моделям есть (в редакторе их 223 — он считает ключ модели
  по-своему; в базе различных `brand + model` 218), в каталоге — нет; человек видит два разных
  представления одних данных и не понимает, почему.
- **Предложение:** режим «По моделям» переключателем в тулбаре, по умолчанию включённый
  на телефоне: строка = модель, справа «свободно N из M», тап раскрывает единицы
  (серийник + статус). Единицы остаются вторым режимом для инвентаризации. Детали —
  в разделе «Предлагаемый каталог для телефона».
- **Цена:** L (нужен серверный агрегат: view или RPC `group by lower(btrim(brand)),
  lower(btrim(model))` со счётчиками по статусам — считать 1 481 строку на клиенте
  ради телефона нельзя).

### F2. «В наличии» означает «не выдано прямо сейчас», а не «свободно на дату»

- **Серьёзность:** серьёзно
- **Где:** прод, тело `transition_equipment_list_status`: `availability` переводится в
  `'issued'` **только в переходе «выдано»**; подтверждение списка (`confirmed`) статус
  единицы не трогает. Фильтр каталога — `api.ts:113-117`.
- **Симптом:** единица, уже расписанная в подтверждённый список на завтра, в каталоге
  показана «В наличии» зелёным. Сотрудник на складе считает её свободной.
- **Почему мешает:** ровно тот сценарий, ради которого он открыл каталог («есть ли
  свободные»), даёт завышенный ответ. Ошибка всплывёт на выдаче второго списка —
  RPC откажет «Some equipment is no longer physically available», но уже на площадке.
- **Предложение:** минимум — переименовать статус в подписи: «На складе» вместо
  «В наличии», и добавить в карточку единицы строку «Забронировано в списке …»
  (данные есть: `equipment_reservation_items`). Максимум — второй бейдж «занято по
  брони» в строке каталога (RPC `reservation_shortages` уже существует и используется
  редактором).
- **Цена:** S для переименования; M для строки «в каком списке» в drawer'е.

### F3. Число, которое человек читает как ответ, — это строки, а подпись говорит «в базе»

- **Серьёзность:** серьёзно
- **Где:** `EquipmentPage.tsx:158-162` («Позиций в базе» + `total`), `:276-277`
  («Показано … из …»). Прод: 1 481 строка = 1 877 штук; максимум 86 штук в одной строке.
- **Симптом:** два разных дефекта в одном числе. (а) После поиска «Behringer» плашка
  показывает не 1 481, а найденное количество — но подпись по-прежнему «Позиций в базе»,
  как будто это размер каталога. (б) Число считает СТРОКИ: три строки количественного
  учёта могут быть 120 штуками. Итог «сколько у нас кабелей» из каталога получить нельзя.
- **Почему мешает:** это единственное место, где виден ответ на главный вопрос,
  и он неверен для количественных позиций и неверно подписан для всех.
- **Предложение:** подпись менять по состоянию: без запроса — «Позиций в базе N»,
  с запросом/фильтром — «Найдено: N позиций · M штук», где M = `sum(count)`.
  `sum(count)` по фильтру берётся тем же запросом (RPC или `head`-запрос с агрегатом).
- **Цена:** S для подписи, M вместе с суммой штук.

### F4. Мобильная карточка каталога: три ячейки из пяти — константы

- **Серьёзность:** серьёзно
- **Где:** `mobile--02-equipment--fold.png`; `styles.css:691-704` (таблица становится
  карточками, горизонтального скролла НЕТ — это сделано хорошо); ячейки
  `EquipmentPage.tsx:255-259`. Прод: локация — единственное значение «Офис» на все
  1 481 строк; статус `available` у 1 475 из 1 481; `count = 1` у 1 446 строк.
- **Симптом:** карточка ~300 px высотой несёт: Категория, Серийный номер, **Количество
  «1 шт.»**, **Статус «В наличии»**, **Локация «Офис»**. Последние три в 97 % случаев
  одинаковы у всех карточек подряд. На первый экран телефона помещается одна карточка.
- **Почему мешает:** плотность списка убита ради полей, которые ничего не различают.
  Пролистать 8 позиций = 3 экрана; найти нужную глазами в выдаче поиска — дольше, чем
  набрать запрос точнее.
- **Предложение:** на телефоне в карточке оставить фото + «Бренд Модель» + серийник
  (моноширинным) и показывать статус ТОЛЬКО когда он не `available`, количество —
  только когда `> 1`, локацию — только когда она отличается от локации по умолчанию.
  Категорию убрать из карточки (она уже во второй строке под названием). Карточка
  сжимается до ~110 px, на экран влезает 5–6 позиций вместо одной.
- **Цена:** M (условный рендер ячеек + правка мобильного блока CSS).

### F5. Партия одинаковых единиц: «Добавить ещё» стирает и модель тоже

- **Серьёзность:** серьёзно
- **Где:** `EquipmentCreatePage.tsx:88-107` (`resetForm` обнуляет `brand`, `model`,
  `type`, `subtype`, `specification`, `description`, `kind`), кнопка `:180`.
- **Симптом:** шесть радиосистем одной модели с разными серийниками — это шесть полных
  заполнений формы: бренд, модель, категория, подкатегория, характеристики, примечание
  вводятся заново каждый раз. Отличается ровно одно поле — серийный номер.
- **Почему мешает:** это самый частый способ пополнения склада (прод подтверждает:
  111 моделей заведены по нескольку раз, одна — 596 раз). Ручной повтор одних и тех же
  строк — прямой источник расхождений в написании модели, а расхождение бренда/модели
  разбивает группу: правка «данных модели» в drawer'е и счётчик «N единиц» работают по
  `lower(btrim(brand/model))`, и опечатка выводит единицу из группы навсегда.
- **Предложение:** на экране успеха две кнопки вместо одной: «Добавить ещё такую же»
  (сохраняет бренд, модель, категорию, подкатегорию, характеристики, локацию, статус;
  очищает только серийник и ставит на него фокус) и «Добавить другую» (нынешний
  `resetForm`). Ещё лучше — поле «Серийные номера» с вводом нескольких номеров через
  перевод строки и одним сохранением всей партии.
- **Цена:** S для «такую же» (сброс только двух полей); L для пакетного ввода партии.

### F6. На телефоне единственная кнопка сохранения формы заведения — вверху, над формой

- **Серьёзность:** мешает
- **Где:** `mobile--04-equipment-new.png`; `EquipmentCreatePage.tsx:196-198` (кнопка в
  шапке), `:293` (вторая кнопка внутри `.equipment-preview`), `styles.css:773`
  (`.equipment-preview { display: none }` на ≤820 px).
- **Симптом:** заполнив последнее поле «Примечание» внизу второго экрана, человек
  должен прокрутить страницу на 1 800 px вверх, чтобы нажать «Добавить в каталог».
- **Почему мешает:** на десктопе кнопок две и одна из них всегда рядом (правая колонка
  `position: sticky`, `styles.css:565`); на телефоне сценарий заканчивается прокруткой
  вслепую. Это ровно тот случай, где телефон ведёт себя хуже десктопа без причины.
- **Предложение:** на ≤820 px дублировать submit последним блоком формы (или сделать
  шапку `position: sticky; top: 0` — форма всё равно уже вертикальная).
- **Цена:** S.

### F7. В drawer'е «Сохранить» и сообщение о конфликте версий живут в самом низу

- **Серьёзность:** мешает (на телефоне — серьёзно)
- **Где:** `EquipmentDrawer.tsx:259-263` (ошибка и кнопки — последние узлы панели),
  `styles.css:279` (`.drawer { overflow-y: auto }`), `styles.css:250` (на ≤520 px сетка
  полей схлопывается в одну колонку).
- **Симптом:** правка единицы на телефоне — это 11 полей в столбик плюс фото сверху,
  то есть 2–3 экрана. «Отмена/Сохранить» — под ними. Сообщение «Карточку уже изменили в
  другой вкладке…» (`:194-198`) рисуется там же: человек нажал «Сохранить» внизу, ответ
  пришёл — и, если он к этому моменту прокрутил вверх посмотреть поля, ответа он не видит.
- **Почему мешает:** механика оптимистической блокировки сделана правильно (правка не
  теряется, введённое остаётся на экране, карточка перечитывается фоном), но её главное
  сообщение можно не заметить — и человек решит, что сохранение прошло.
- **Предложение:** в режиме правки — липкая нижняя панель drawer'а с кнопками (у drawer'а
  списка такая уже есть: `.reservation-drawer__footer`, `styles.css:728`), а `editError`
  и `editSuccess` показывать ВВЕРХУ, под заголовком карточки, а не только у кнопок.
- **Цена:** M.

### F8. «N единиц» в шапке правки молча превращается в «1 единиц», если счёт не прошёл

- **Серьёзность:** серьёзно (риск данных)
- **Где:** `EquipmentDrawer.tsx:122-128` — `.catch(() => setModelUnitCount(1))`, вывод
  `:236`. Начальное значение тоже `1` (`:70`).
- **Симптом:** блок «Данные модели» честно предупреждает «Изменятся у всех экземпляров
  с тем же брендом и моделью» и показывает бейдж с числом. При отказе RPC (сеть, права,
  неприменённая миграция мимо гейта `PGRST202`/`42883`) бейдж показывает **«1 единиц»** —
  неотличимо от честного «эта единица единственная».
- **Почему мешает:** человек правит описание, видит «1 единиц» и жмёт «Сохранить», а
  правка уезжает в 596 строк. Предупреждение превращается в ложное успокоение — это хуже,
  чем отсутствие числа.
- **Предложение:** третье состояние — `null`: при отказе показывать не число, а
  «у всех единиц этой модели» (без цифры), как уже сделано для сообщения об успехе
  (`api.ts:333-337`, `EquipmentDrawer.tsx:187-188` — там выдуманное число намеренно не
  подставляется). Заодно поправить согласование: сейчас всегда «единиц» («1 единиц»).
- **Цена:** S.

### F9. Состояние каталога не живёт в адресе: страница, поиск и drawer теряются

- **Серьёзность:** мешает
- **Где:** `EquipmentPage.tsx:39-47` (весь стейт локальный, `useSearchParams` не
  используется), `:290-306` (drawer — состояние, а не маршрут).
- **Симптом:** три отдельные потери. (а) Ушёл в «Добавить оборудование» и вернулся
  «Назад к каталогу» (`EquipmentCreatePage.tsx:189`) — страница компонента размонтирована,
  каталог открывается на странице 1 с пустым поиском. (б) F5 — то же самое. (в) На
  телефоне открыт drawer, человек делает жест «назад» — браузер уходит с `/equipment`
  на предыдущий маршрут вместо того, чтобы закрыть карточку.
- **Почему мешает:** (в) — самый частый жест на телефоне; сейчас он выкидывает из
  каталога. (а) бьёт по сценарию «завёл технику — вернулся к тому месту, где смотрел».
- **Предложение:** `page`, `search`, `availability` — в query-параметры (`useSearchParams`),
  drawer — в `?item=<id>` либо перехват `popstate` внутри `useModalLayer`.
- **Цена:** M.

### F10. Единственный фильтр — статус, который одинаков у 1 475 позиций из 1 481

- **Серьёзность:** серьёзно
- **Где:** `EquipmentPage.tsx:189-198` (единственный `AppSelect`), опции
  `availability.ts:44-46`. Прод: `available` 1 475, `unavailable` 5, `diagnostics` 1,
  `issued` 0. При этом в базе 7 категорий и 56 подкатегорий, и они уже загружены
  (`api.ts:186-201`, справочник греется при старте, `App.tsx:114-125`).

## Что работает хорошо и что нельзя сломать

1. **Мобильная таблица без горизонтальной прокрутки.** `styles.css:691-704` превращает
   таблицу в карточки с подписями из `data-label`, ничего не обрезая. Это правильное

   RPC, отдельное сообщение на `40001`, **сохранение введённых значений после конфликта**

   сохранение, а не пропускает его (`EquipmentCreatePage.tsx:120-127`, `:138-144`) —

   единица», `EquipmentDrawer.tsx:233-258`) — деление и предупреждающая подпись верны;
   чинить нужно только цифру (F8).
5. **`count` серийной карточки не уезжает в базу** (`:182`) — закрывает фантомные записи
   в журнале движения.
6. **Префетч следующей страницы и картинок** (`EquipmentPage.tsx:113-118`) — «вперёд»

8. **Вход на телефоне** — брендовая панель ужата до 210 px, форма на первом экране,

9. **Дебаунс 350 мс, крестик очистки, сброс на страницу 1 при новом запросе**
   (`EquipmentPage.tsx:77-83`, `:183-187`) — поиск ведёт себя предсказуемо.

- переключатель режима «Модели / Единицы» — маленький, справа.

**Строка результата (заменяет «Позиций в базе»):**
`Найдено: 6 моделей · 23 единицы · свободно 21` — прямо под тулбаром, всегда видно.

**Карточка модели (~92 px вместо нынешних ~300):**
```
[фото 56×56]  Beterva SP-BE-2300D                    32 / 32
              Микрофоны (проводные, беспроводные…)   свободно
```
Строка 1 — бренд + модель. Строка 2 — подкатегория. Справа — «свободно N из M»
крупно, зелёным при N > 0, серым при N = 0. Тап раскрывает список единиц внутри
карточки (аккордеон, без ухода с экрана): серийник моноширинным + бейдж статуса,
только если он не «свободна». Тап по конкретной единице открывает нынешний drawer.

**Режим «Единицы»** (инвентаризация, сканирование серийников) — нынешняя карточка,
но урезанная по F4: фото + бренд/модель + серийник; статус, количество и локация
рисуются, только когда отличаются от типового значения.

**Путь «сколько свободных X» становится таким:**
открыть «Оборудование» → тап в поиск → набрать «X» → **прочитать «свободно N из M»
на первой карточке**. Три действия, ответ на первом экране, без прокрутки и без
второго фильтра. Сегодня это 4 тапа + ввод, ответ подписан «Позиций в базе» и
считает строки, а не штуки.

**Цена: L.**
- Серверный агрегат — обязателен: view или RPC `equipment_models`,
  `group by lower(btrim(brand)), lower(btrim(model))` с `count(*)`,
  `count(*) filter (where availability = 'available')`, `sum(count)`, `min(id)` для
  картинки и подкатегории; поиск и фильтр по категории уходят в тот же запрос,
  пагинация — по моделям (218 вместо 1 481, на телефоне это 27 страниц по 8 или
  одна «Показать ещё»). Без агрегата режим невозможен: считать по 1 481 строке на
  клиенте — это те самые 1,4 МБ, которые уже пришлось выселить из localStorage
  (`api.ts:126-129`).
- Клиент: новый режим рендера в `EquipmentPage` (~120 строк), карточка-аккордеон,
  чипы категорий, строка результата. Нынешний режим единиц остаётся как есть.

**Дешёвый первый шаг (S+M, без схемы), если L сейчас не по бюджету:**
F3 (подпись «Найдено: N позиций · M штук») + F4 (сжать карточку) + F10 (фильтр по
категории). Это не отвечает на «сколько свободных» одним взглядом, но убирает три
из четырёх препятствий и оставляет режим «по моделям» на потом.
