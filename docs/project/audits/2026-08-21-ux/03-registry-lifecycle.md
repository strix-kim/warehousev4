# Реестр, статусы, навигация вокруг редактора — находки

## Маршрут пользователя как он есть

### 1. «Зашёл → хочу собрать список»

**Десктоп (1440).** `/` → в сайдбаре шорткат «Новый список / Собрать комплект»
(`App.tsx:160-164`) → редактор. **1 клик, без прокрутки.** Альтернатива через плитку
«Списки оборудования» (`HomePage.tsx:27-35`): её подпись-действие — «＋ Создать список»,
но `to="/lists"` — попадаешь в реестр, там ещё раз «Создать список» (`ListsPage.tsx:248`).
**2 клика при обещанном одном.**

**Телефон (390×844).** Шортката «Новый список» нет — `.sidebar__utility` скрыт с 1050 px
(`styles.css:643`). Первый экран главной занят плиткой «Оборудование» (~750 px высоты),
плитка списков начинается ниже; вся страница 1 270 px = 1,5 экрана (metrics `mobile/01-home`).
Путь: нижняя панель «Списки» → `/lists` → «Создать список» на 202 px от верха
(виден на сгибе, `mobile--05-lists--fold.png`) → редактор. **2 тапа, без прокрутки** —
если человек догадался, что «собрать комплект» живёт в разделе «Списки», а не «Оборудование».

### 2. «Вернуться к вчерашнему черновику и дособрать»

Два разных объекта называются «Черновик», и человек не различает их по интерфейсу:

- **Сохранённый список** со статусом `draft`: `/lists` → нужная карточка → «Открыть детали
  списка» (`ListsPage.tsx:323`) → в футере дровера «Открыть и изменить список» (`:502`) →
  `/lists/:id/edit`. **3 тапа после реестра**; прямой кнопки «Изменить» на карточке нет.
- **Несохранённый черновик** (`/lists/new`, 24 ч, `cacheKeys.ts:28-29`): в реестре его
  **не видно вообще**. Единственный вход — кнопка «Создать список», которая молча
  подставляет вчерашнюю работу и плашку «Черновик восстановлен» (`ListEditorPage.tsx:460-472`).

В редакторе открытого списка заголовок — «РЕДАКТИРОВАНИЕ ЧЕРНОВИКА / Открытый список»
(`:443-444`), имени списка в шапке нет (`desktop--15-editor-existing--fold.png`).

### 3. «Найти список прошлого месяца и скачать документ с реквизитами»

`/lists` → поиск только по названию (`api.ts:255`, плейсхолдер `ListsPage.tsx:267`),
фильтр только по этапу (`:269-281`), порядок фиксированный `created_at desc`
(`api.ts:252-253`). Названия у списков одинаковые (дефолт `documentDefaults.ts:7`),
поэтому поиск бесполезен → остаётся листать: 12 карточек на странице на десктопе,
**6 на телефоне** (`api.ts:110-111`), карточка на телефоне 437 px (metrics) → страница
реестра ≈ 2 600 px прокрутки. Нашёл — «С реквизитами» прямо с карточки, **1 тап до файла**
(`ListsPage.tsx:325`). Это лучший участок всего маршрута.

### 4. «Выдать комплект и потом вернуть» (draft → confirmed → issued → returned)

`/lists` → карточка → «Открыть детали списка» → в футере раскрыть `<details>` «Учёт выдачи
и возврата» (`:508-509`) → прокрутить **внутри** блока (`max-height: 38–43dvh`,
`styles.css:490`, `:729`) → «Подтвердить комплект» (+ необязательный комментарий) →
дровер перезагружается → «Отметить выдачу» → «Принять возврат».
**4 клика до первого перехода**, из них два — «раскрыть» и «прокрутить внутри».

### 5. «Удалить ошибочный список»

Карточка → «Открыть детали списка» → «Удалить список» → «Да, удалить» (`:557-579`).
Подтверждение инлайн, текст последствий честный. Кнопка показана всем, права — только
у одной почты (`docs/project/02-features.md` §9).

### 6. Навигация между разделами

Десктоп: сайдбар (Главная / Оборудование / Списки), шорткат «Новый список», «Быстрый
процесс» 01-02-03, «Текущая локация», RU/UZ, аккаунт + «Выйти».
Телефон и планшет (≤820): нижняя панель = Главная / Оборудование / Списки / RU / UZ.
Скрыты: шорткат «Новый список» (`styles.css:643`), локация, аккаунт и **кнопка выхода**
(`styles.css:666`). Из редактора «назад» всегда ведёт в `/lists` (`ListEditorPage.tsx:439`).

## Находки

### F1. Подтверждённый план-список — тупик без выхода
- **Серьёзность:** блокер
- **Где:** `ListsPage.tsx:385` (`cannotIssuePlan`), `:501-503` (кнопка правки только для
  `draft`), `:528` (плашка «Сначала назначьте конкретные единицы»),
  `ListEditorPage.tsx:145-146` + `:456-457` (`openError: 'not-draft'`);
  скриншоты `desktop--06b-lists-details-drawer-full.png`
- **Симптом:** список в статусе `confirmed` с `list_mode = 'abstract'` показывает:
  «План по моделям можно подтвердить, но выдавать допустимо только фактический комплект».
  Чтобы назначить единицы, нужно открыть список на правку — но кнопки правки в дровере
  нет (она только для `draft`), а прямой заход на `/lists/:id/edit` отвечает «Изменять
  можно только черновики». Перехода `confirmed → draft` в модели нет
  (`getTransitionCopy`, `:84-90`). Состав заморожен и триггером в базе.
- **Почему мешает:** человек сделал ровно то, что интерфейс предложил (подтвердил), и
  получил документ, который нельзя ни выдать, ни исправить. Единственный выход — удалить
  список (кнопка тут же, рядом) и собрать заново. Тот же тупик у любой опечатки в
  подтверждённом списке: дата, заказчик, лишняя позиция.
- **Предложение:** (а) не давать подтверждать `abstract`-список — заменить в `draft`
  кнопку «Подтвердить комплект» на «Назначить серийные номера» с переходом в редактор,
  когда `list_mode` выйдет `abstract`; либо (б) добавить переход `confirmed → draft`
  («Вернуть в черновик») в `getTransitionCopy` и в серверный граф — тогда плашка
  `cannotIssuePlan` получает действующую кнопку. Минимум-минимум (S): в самой плашке
  дать кнопку «Вернуть в черновик и изменить», а не текст без выхода.
- **Цена:** L (нужен серверный переход и снятие заморозки состава при возврате в draft);
  вариант (а) — M.

### F2. Реестр не позволяет найти список: единственный идентификатор — название, а оно у всех одинаковое
- **Серьёзность:** серьёзно
- **Где:** `ListsPage.tsx:313` (`<h3>{list.name}</h3>`), `:267` (поиск по названию),
  `:269-281` (фильтр только по этапу), `api.ts:255-256`, `:252-253` (порядок);
  `desktop--05-lists--fold.png`, `mobile--05-lists.png`
- **Симптом:** две карточки в проде отличаются только номером «01/02» и числом единиц:
  одинаковые «Техническое обеспечение мероприятия», «Заказчик не указан · Площадка
  мероприятия», одинаковые даты. Номер `01/02` — это порядок на странице
  (`(currentPage-1)*pageSize + index + 1`, `:299`), а не идентификатор списка: на второй
  странице он начнётся с 13, после удаления соседа — сдвинется.
- **Почему мешает:** маршрут «найти список прошлого месяца» не выполняется никак: поиск
  по названию ничего не различает, фильтра по дате/заказчику/площадке нет, сортировка
  одна. Остаётся листать по 6 карточек на телефоне. При 50 списках это десятки экранов.
- **Предложение:** (1) первичный идентификатор карточки — **дата мероприятия + заказчик**,
  название второй строкой (см. раздел «Предлагаемая структура»); (2) расширить поиск на
  `client_name` и `venue` — PostgREST `.or('name.ilike.*,client_name.ilike.*,venue.ilike.*')`
  поверх уже имеющегося `escapeLikePattern` (осторожно с запятыми в шаблоне);
  (3) добавить фильтр периода по `reservation_start` (`.gte/.lte`) — «этот месяц /
  прошлый месяц / выбрать»; (4) поменять плейсхолдер на «Название, заказчик или площадка…».
- **Цена:** M (карточка + два фильтра + запрос); только поиск по трём полям — S.

### F3. На телефоне нет выхода из аккаунта, не видно, кто вошёл, и нет входа в главный сценарий
- **Серьёзность:** серьёзно
- **Где:** `App.tsx:159-189` (утилити-блок, локация, язык, аккаунт + `signOut`),
  `styles.css:643-644` (`.sidebar__utility`, `.sidebar__signal--bottom` скрыты ≤1050),
  `:666` (`.sidebar__brand, .sidebar__scope, .sidebar__footer` скрыты ≤820);
  `mobile--01-home--fold.png`, `tablet--05-lists--fold.png`
- **Симптом:** `signOut` вызывается ровно из одного места — кнопки в `sidebar__footer`
  (`App.tsx:188`), которая на телефоне и планшете не отрисовывается. Выйти или сменить
  аккаунт с телефона **нельзя вообще**; почта текущего пользователя не видна; «Текущая
  локация» не видна; шортката «Новый список» нет.
- **Почему мешает:** основная аудитория — на телефоне, на складе и площадке. Чужой
  телефон, увольнение, «зашёл не тем аккаунтом» — тупик до десктопа. И главное действие
  продукта («Новый список») на телефоне лишено прямого входа, тогда как на десктопе оно
  первым слотом в сайдбаре.
- **Предложение:** в нижней панели свернуть RU/UZ до **одной** кнопки-переключателя
  (44 px, показывает текущий язык, тап меняет) — это освобождает ~45 px; на освободившееся
  место поставить четвёртый пункт «Ещё» с аккаунтом, локацией и выходом, а «＋ Новый
  список» вынести отдельной круглой кнопкой над панелью на `/lists` (там, где она нужна).
  Минимально (S): продублировать выход и почту в шапку страницы на ≤820.
- **Цена:** M.

### F4. На телефоне «Сохранить» из шапки не даёт никакого ответа — ни успеха, ни ошибки
- **Серьёзность:** серьёзно
- **Где:** `ListEditorPage.tsx:447-449` (кнопка в шапке), `:649-653`
  (`successMessage` / `saveError` — внутри `selection-footer`), `styles.css:752-753`
  (`.editor-grid .selection-panel { display: none }`, показывается только с
  `.mobile-active`); metrics `mobile/15-editor-existing`: `.selection-panel` — `display: none`
- **Симптом:** на телефоне видна одна из двух панелей — «Каталог» или «В списке».
  Сообщения «Список сохранён в системе» / «Изменения сохранены» / «Не удалось сохранить
  список» рендерятся только в подвале панели «В списке». Пользователь на вкладке «Каталог»
  жмёт «Сохранить» в шапке и не видит **ничего**: ни подтверждения, ни ошибки. Единственный
  признак успеха — что подзаголовок шапки поменялся с «Быстрый рабочий документ» на
  «Редактирование черновика» (`:443-444`).
- **Почему мешает:** это тихий провал записи. Человек уверен, что список сохранён, уходит,
  список не сохранён. И обратное: сохранил, не понял, что сохранилось, жмёт ещё раз.
- **Предложение:** перенести `successMessage`/`saveError` под шапку редактора (рядом с
  `editor-draft-notice`), а в подвале оставить только дублирование на десктопе; либо
  один блок сообщений, отрисованный вне обеих панелей.
- **Цена:** S.

### F5. Правки сохранённого списка не переживают закрытие вкладки, а черновик /lists/new — переживает
- **Серьёзность:** серьёзно
- **Где:** `useListDraftAutosave.ts:39` (`if (listId || !restoredRef.current) return`),
  `cacheKeys.ts:28-29` (24 ч только для `list-draft:new`), `ListEditorPage.tsx:439`
  (кнопка «назад» → `/lists` без предупреждения)
- **Симптом:** на `/lists/new` каждое изменение через 1 с уходит в кэш и живёт сутки.
  На `/lists/:id/edit` автосейва нет: закрыл вкладку, разрядился телефон, нажал «назад»
  или тапнул «Списки» в нижней панели — 20 минут правок исчезли молча. Никакого
  «есть несохранённые изменения» нет.
- **Почему мешает:** асимметрия ровно наоборот ожидаемой: незначительный черновик
  бережётся, работа над сохранённым документом — нет. Обычный сценарий «дособрать
  вчерашний список на складе» бьётся именно об это.
- **Предложение:** минимум (S) — `beforeunload` + подтверждение при уходе с грязной
  формой (сравнение с гидратированным снимком) и блокировка кнопки «назад» тем же
  условием. Полноценно (M) — распространить автосейв на режим правки под ключом
  `list-draft:<listId>` с плашкой «Есть несохранённые изменения от 18:40 · Восстановить /
  Отбросить»; ключ обязан лежать вне префикса `equipment-lists:` по той же причине, что
  и черновик нового (`cacheKeys.ts:23-27`).
- **Цена:** S (предупреждение) / M (автосейв правок).

### F6. Смена статуса спрятана за раскрытием и внутренней прокруткой
- **Серьёзность:** мешает
- **Где:** `ListsPage.tsx:508-512` (`<details>` «Учёт выдачи и возврата» в футере дровера),
  `:530-539` (`transition-panel` внутри), `styles.css:490` (`max-height: min(43dvh, 410px)`),
  `:729` (38dvh на телефоне); `mobile--06-lists-details-drawer.png`
- **Симптом:** на сгибе дровера видно «Учёт выдачи и возврата · Необязательно —
  открывайте только для складского учёта». Кнопка «Подтвердить комплект» лежит внутри
  свёрнутого блока, а сам блок прокручивается отдельно от дровера: на телефоне его
  высота ограничена 38 % экрана, и внутри него ещё дефицит, комментарий, кнопка и вся
  история статусов.
- **Почему мешает:** весь жизненный цикл — заявленная фича продукта — стоит четырёх
  действий и двух вложенных прокруток. Плюс подпись «Необязательно» прямо отговаривает
  туда заходить: тот, кто пришёл выдавать комплект, читает это как «не сюда».
- **Предложение:** вынести **текущее** доступное действие (`action.label` + кнопка) в
  футер дровера первой строкой, всегда развёрнутым; в `<details>` оставить историю и
  дефицит («Подробности учёта»). Комментарий к переходу — вторым шагом после нажатия
  (или свернуть в «Добавить комментарий»), чтобы не занимать место в футере.
- **Цена:** M (перекомпоновка футера дровера).

### F7. Над карточками — экран текста, написанного для разработчика
- **Серьёзность:** мешает
- **Где:** `ListsPage.tsx:246` (описание раздела), `:253-256` (metric-strip: «Всего
  списков 2» + нотация про Excel), `:258-262` (заголовок «Сохранённые списки» +
  подзаголовок «поиск, фильтр и страницы считает база — по всему архиву» + бейдж
  «РАСШИРЕННЫЙ УЧЁТ»); metrics `mobile/05-lists`: `.toolbar` top = 611, первая карточка
  top = 716 при экране 844
- **Симптом:** на телефоне до первой карточки — 716 px, до её содержимого (название) —
  за сгибом; вся страница с двумя списками = 1 777 px (2,11 экрана). Из этих 716 px
  полезны два элемента: H1 и «Создать список». Остальное: «Excel скачивается без
  сохранения; нехватка остаётся предупреждением и не блокирует работу» (описание
  внутренней политики системы), «поиск, фильтр и страницы считает база — по всему
  архиву» (пересказ коммита с5 пользователю), «РАСШИРЕННЫЙ УЧЁТ» (бейдж без действия и
  без объяснения), «Всего списков 2» (число, которое уже написано в пагинации:
  «Показано 1–2 из 2»).
- **Почему мешает:** маршруты 2–5 начинаются с карточек, а карточек не видно. На
  телефоне каждый заход в реестр — прокрутка через полтора экрана служебного текста.
- **Предложение:** удалить подзаголовок про базу и бейдж «РАСШИРЕННЫЙ УЧЁТ» целиком;
  нотацию про Excel перенести в пустое состояние и в подсказку у кнопки экспорта;
  «Всего списков N» — в строку тулбара слева от поиска (тогда `metric-strip` со страницы
  уходит); описание раздела оставить только на десктопе (`:246` под медиазапрос).
  Результат: первая карточка поднимается на ~300 px, тулбар — в пределах первого экрана.
- **Цена:** S.

### F8. Четыре кнопки на карточке, и та, что открывает список, выглядит как «история»
- **Серьёзность:** мешает
- **Где:** `ListsPage.tsx:322-326` (`list-card__actions`), `:323` («Открыть детали
  списка» с иконкой `Clock3`), `styles.css:722` (на телефоне — три кнопки в столбик);
  `mobile--05-lists.png`
- **Симптом:** карточка заканчивается блоком «Открыть детали списка / Рабочий Excel /
  С реквизитами». На телефоне это три кнопки в столбик ≈ 150 px из 437 px карточки.
  Иконка часов у главной кнопки обещает журнал, а за ней — состав, статусы, редактирование
  и удаление. Слова «редактировать» на карточке нет вообще: правка сохранённого списка —
  третий уровень (карточка → дровер → футер).
- **Почему мешает:** самое частое продолжение работы с черновиком — дособрать его —
  спрятано глубже, чем экспорт. Плюс две кнопки экспорта на каждой карточке умножаются
  на 6–12 карточек: 12–24 кнопки «скачать» на экране.
- **Предложение:** на карточке — одна первичная кнопка «Открыть» (по всей карточке
  кликабельно) и одна вторичная иконка «Скачать» с выбором из двух форматов (меню на
  `AppSelect`/details). Для карточки в статусе `draft` первичной сделать «Изменить»
  → сразу `/lists/:id/edit`, а состав и статусы оставить в дровере.
- **Цена:** M.

### F9. Четыре точки экспорта, две разные ментальные модели и неразличимые имена файлов
- **Серьёзность:** мешает
- **Где:** `ListEditorPage.tsx:450-452` и `:650` (две кнопки «Скачать Excel», формат — из

  `exportSavedList`, что и на карточке; (3) на карточке свести два формата в одну кнопку
  с выбором (см. F8), чтобы модель везде была одна: «Скачать → какой формат».
- **Цена:** S (имя файла) + M (единая точка выбора формата).

### F11. Кнопка удаления есть у всех, но работает у одного; отказ прав выглядит как сбой сети

1. Как сотрудники **называют** списки в жизни — есть ли внешний номер заявки, название

## Предлагаемая структура реестра и карточки

**Порядок блоков над карточками** (телефон и десктоп одинаково, без второго экрана):

1. `H1 «Списки оборудования»` + кнопка **«＋ Создать список»** (на телефоне — во всю
   ширину, как сейчас). Описание раздела — только на десктопе.
2. Строка тулбара: **поиск** («Название, заказчик или площадка…») · **период**
   («Все даты / Этот месяц / Прошлый месяц / Выбрать…») · **этап** («Все этапы») ·
   счётчик «N списков» справа · бейдж возраста данных.
3. Карточки.

Уходят: `metric-strip` целиком (нотация про Excel → в пустое состояние; «Всего списков» →
в тулбар), подзаголовок «Необязательный архив: поиск, фильтр и страницы считает база»,
бейдж «РАСШИРЕННЫЙ УЧЁТ», заголовок «Сохранённые списки» (H1 страницы уже это сказал).
Выигрыш на телефоне — около 300–350 px, первая карточка попадает на первый экран.

**Первичный идентификатор списка — дата мероприятия + заказчик.** Название — вторичное:
оно у всех дефолтное, а дата и заказчик уникальны и совпадают с тем, как человек помнит
работу («форум в Hyatt в марте»).

**Карточка (сверху вниз):**

```
[21 августа 2026]                      [• Черновик]     ← дата мероприятия крупно + этап
Заказчик не указан · Площадка мероприятия               ← заказчик · площадка
Техническое обеспечение мероприятия                     ← название, вторая строка
4 единицы · только модели · создан 21.08                ← состав, режим, дата создания
[ Открыть ]                              [ ⤓ Скачать ▾ ] ← первичная + меню двух форматов
```

- Вся карточка кликабельна и ведёт в то же, что «Открыть»: для `draft` — сразу в
  редактор (`/lists/:id/edit`), для остальных статусов — в дровер деталей.
- «⤓ Скачать» — одна кнопка с двумя пунктами («Рабочий список» / «На согласование +
  реквизиты»), одна ментальная модель с селектором «Формат Excel» в редакторе.
- Порядковый номер `01/02` убрать: он вводит в заблуждение, будто это номер документа.

**В деталях (дровер) остаётся и добавляется:**
шапка (имя, этап, период, режим, число единиц) **+ заказчик · площадка · комментарий**
(сейчас их там нет) → состав → **текущее действие этапа развёрнутым** («Подтвердить
комплект» / «Отметить выдачу» / «Принять возврат») → «Подробности учёта» в `<details>`
(дефицит, история, комментарий) → «Открыть и изменить список» → «Скачать» (два формата)
→ разделитель → «Удалить список».

**Цена варианта:** M — карточка и тулбар реестра (`ListsPage.tsx:240-330`), меню экспорта
(новый мелкий компонент поверх `AppSelect`), фильтр периода в `fetchEquipmentLists`
(`api.ts:214-263`, `.gte/.lte` по `reservation_start` + ключ кэша), перекомпоновка футера
дровера (`:500-579`). Без F1 (тупик `confirmed`) структура не лечит жизненный цикл — это
отдельная работа ценой L.
