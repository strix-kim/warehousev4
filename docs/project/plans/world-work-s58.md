# План: мир как рабочая поверхность — `planner`, с58

Заказ прораба (с58): мир — не витрина. Сначала **мир в проде на живых данных**, чтобы смотреть и
править в приложении; потом участок мероприятия с действиями, люди по данным, гараж. HTML-макетов
нет — всё в `src/react/features/world/`. Продолжение `world-s51.md` (Ш1–Ш5 сделаны); Ш6–Ш9 оттуда
здесь пересобраны под живые `projects`.

**Живая база (SELECT, с58):** `projects` 2 — «Bionorica Workshop» 12–14 окт, место «Double Tree by
HILTON», 1 список, 1 план залов, состав 0, обедов 0; «Список 21.08.2026 · 10:34» — 21 авг, без места
(бэкфилл с54). `employees`: 12 `staff` + 27 `hired`. `vehicles` 6. Значит сегодня в проде
«Площадки» = **один участок**, «Где работали» = **пусто**, людей на участке нет, пока не заведён состав.

## Решения

1. **Схема не меняется ни на одном этапе этого плана.** Всё читается существующими API; миграций,
   RPC и новых политик нет → `/rls-verify` не требуется (запись идёт только через готовые экраны).
2. **Участок = мероприятие, а не место.** Действия прораба — про мероприятие (список, обед, план,
   состав); место — его реквизит и силуэт здания. Два мероприятия в одном отеле — два участка.
   Мероприятие без места — участок с типовым зданием и табличкой «Площадка не указана».
   `venues_board()` из `lodging-s49.md` этапа 8 остаётся там: он нужен, когда появятся заезды.
3. **Источник — `fetchProjects` / `readCachedProjects`** (`features/projects/api.ts`, ключ
   `projects:list`, батчи по 1000, счётчики `listCount`, `staffCount`, `hasHallPlan`). Своих ключей
   `persistentCache` мир не заводит (канон `useWorldData`); сброс уже есть —
   `invalidateProjectsCache` / `invalidateProjectCounters` зовут списки, состав, залы. Детали участка
   (строки списков, планов, состав, обеды) — по требованию, без кэша, как на `ProjectPage`.
   **RPC не нужен,** пока мероприятий десятки: порог пересмотра — реестр > ~300 строк или жалоба на
   трафик (backlog «счётчики — вложенные id»).
4. **Критерий зоны** (`lodging-s49.md`, этап 8), считает клиент через `todayDateValue()`:
   `coalesce(date_to, date_from) >= сегодня` или `date_from is null` → «Площадки»; иначе, если есть
   место → «Где работали» (группировка по `venue.id`); прошлое без места — нигде. Чистая функция
   `splitProjects(projects, today)` в `data/` — скаут сверяет её скриптом против SQL.
5. **Тип здания** (`hotel | arena | hall`) — колонки нет; чистая функция `venueKind(name)` по словам
   в названии (hilton, hyatt, hotel, отель → hotel; arena, арена, спорт → arena; дворец, palace →
   palace только в архиве; иначе hall). Это облик, не данные; неверный силуэт ничего не ломает.
6. **Честность:** нет данных — нет сцены. Расселения нет в базе → отель на участке стоит
   **запертым** («появится с расселением»), без «плюса»: плюс, ведущий в никуда, — ложь.
7. **Фикстуры** остаются dev-стендом худшего случая (6 участков, имена на 43 знака), но опт-ин:
   `?mock=on` и только `import.meta.env.DEV` (динамический импорт срезается из прода — как сейчас).
   Форма приводится к новому типу тем же шагом, что меняет тип.

## Э2. Участок с действиями (с59)

Объекты участка и данные (контракт — `LOT_PARTS` в `worldStore.ts`, правит один кодер первым):

| Объект | Есть, когда | Клик в сцене / кнопка-дубль | Пусто → «плюс» |
|---|---|---|---|
| Здание места `lot` | всегда | выбор участка, панель | — |
| Грузовик `truck` | `lists > 0` | 1 список → `/lists/:id/edit`; больше → секция «Оборудование» со строками | `/lists/new?project=:id` |
| Стол плана `plan` | `hasPlan` | 1 план → `/halls/:id`; больше → строки | `/halls?new=1&project=:id` (новый параметр) |
| Кафе `cafe` (новое) | всегда | `/projects/:id/meals` | — (обед создаётся там) |
| Состав `crew` | `staff > 0` | секция «Состав» → `/projects/:id` | «Добавить состав» → `/projects/:id` |
| Отель `stay` | никогда (до таблиц) | запертый, табличка «Расселение — скоро» | нет |
| Табличка «Площадка не указана» | `place === null` | `/projects/:id` | — |

- **`VenuePanel` → рабочая карточка:** шапка (мероприятие, место, даты, «Открыть мероприятие»),
  секции = кнопки-действия; содержимое секций грузится при открытии панели существующими

  (`staffApi.ts`), `fetchProjectMealDays` (`meals/api.ts`); отказ — строка «не загрузилось · повторить»,
  без экрана ошибки. Каждый объект сцены = кнопка в панели (текстовый путь, `design-game-ui` §13).
  390 — лист снизу (`.w-stage.is-sm .w-vpanel` уже есть), тач-цели ≥ 44 px.
- **`/halls?new=1&project=ID`:** `HallPlansPage` открывает `HallPlanMetaDrawer` с предвыбранным
  мероприятием (новый проп `initialProjectId`; дровер уже умеет `projectId`). Параметр снимается

- Кафе — новый строитель `buildCafe` в `engine/zones/venues.ts`, место — передний левый слот
  (сдвиг отеля назад); числа раскладки участка — внутри одного файла.
- Чекпоинт: на участке Bionorica клик по грузовику → редактор списка; по кафе → обеды; по пустому

## Э3. Люди по данным (с60)

**Уровень 1 — жизнь кампуса.** Новый `engine/life.ts` (`createLife(ctx, figures)`, `tick(dt)`):
прохожие ходят по своим полосам из `peopleSpots` (`zones/campus.ts`) туда-обратно, `pose()` из
`people.ts` в шаге, стоящие — лёгкое покачивание раз в несколько секунд. Тик — в `setAnimationLoop`
`createWorld.ts`; при `reducedMotion` life не создаётся (кадр по требованию). Пересборка зоны и
`dispose` снимают life.

**Уровень 2 — расстановка по данным** (без новых таблиц; источник — `project_staff` + даты):

| Состояние человека сегодня | Где стоит |
|---|---|
| в составе мероприятия, которое идёт (`date_from ≤ сегодня ≤ coalesce(date_to, date_from)`) | на участке этого мероприятия (у здания/кафе) |
| в составе мероприятия, которое начинается завтра | бригада с кейсами у рампы склада («сборы») |
| штат, ни то ни другое | офис и прохожие кампуса |
| наёмный (`department = 'hired'`) вне идущего мероприятия | нигде — на кампусе их нет |

- Данные: новая `fetchStaffOfProjects(ids)` в `projects/staffApi.ts` (`project_id, employee_id`,
  `in` по ≤ 7 id участков, без кэша); `WorldPerson` получает `department`. Пересечение двух
  мероприятий в один день — берётся раннее по `date_from` (база такого не запрещает).
- Чистая функция `placePeople(people, lots, staffByProject, today)` в `data/` — скаут сверяет.
- Честность: состава нет → участок без фигурок, в панели «Состав не указан». Сегодня в проде так и
  будет (состав 0) — прорабу добавить состав Bionorica, иначе уровень 2 не увидеть.
- Чекпоинт: добавить в состав Bionorica 3 штатных + 2 наёмных, сдвинуть даты на сегодня → в мире 5
  фигурок на участке, на кампусе 9; даты «завтра» → 3 штатных у рампы с кейсами, наёмных нет.

## Риски

- **Бандл.** Маршрут в проде добавляет чанки `three` (~600–700 КБ min) и мира — ленивые; варнинг
  Vite принят в с51. Любой статический `import 'three'` вне `engine/` — дефект; гейт — grep и размер
  входного чанка в отчёте Э1а.
- **Кэш.** Мир читает `projects:list` (TTL 5 мин). Запись из другой вкладки доедет до 5 минут —
  при возврате в мир `bypassCache` после показа кэша. Сброс у всех писателей уже есть; новый писатель
  (`/halls?new`) идёт через существующий `createHallPlan` → `invalidateProjectCounters`.
- **Смена формы `WorldVenue`** — в `persistentCache` её нет (собирается из чужих ключей) → ключи не
  меняются.
- **Лимит 1000** не задевается: реестр мероприятий уже батчится; `fetchStaffOfProjects` ≤ 7 id.
- **«Сегодня» на клиенте** — часы устройства (Ташкент); уехавший телефон увидит сдвиг на день.
- **Права:** запись только через готовые экраны; не-staff роль увидит кнопки, база откажет (`42501`)
  — тексты отказов уже есть в `projectErrorText`. Нового права нет → `/rls-verify` не нужен.
- **Прод открыт для 2 пользователей**: мир в меню виден обоим; телефон/Safari/палец машиной не
  проверяются — приёмка только прорабом.
- **Тестов и линтера нет;** чистые функции (`splitProjects`, `venueKind`, `placePeople`) держать без
  three, чтобы скаут сверял их скриптом. HMR и StrictMode — как в с51 (полный `dispose`, life тоже).
- **Мусорные данные:** 5 тестовых списков и бэкфилл «Список 21.08…» видны и в мире — удаление за
  прорабом (current-state, очередь 1).
