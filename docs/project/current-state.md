## Курс

**ARGO Warehouse** — внутренняя система учёта AV-оборудования ARGO Media.
Сотрудник собирает список оборудования на мероприятие, сохраняет и выгружает
Excel. Всё остальное подчинено этому сценарию.

- **Репозиторий:** `github.com/strix-kim/warehousev4`, ветка `main`. **Публичный.**
- **Весь живой код — `src/react`: 41 файл, 7 765 строк** (в с8 добавился
  `lib/useArmedAction.ts`). **За порогом ~800 строк два файла:** `styles.css` 859 и
  `ListEditorPage.tsx` 825 — кандидаты на чистый распил (backlog с8).
- **Стек:** React 19 + TypeScript 5.9 + Vite 7 + Supabase (Postgres/Auth/Data API),
  хостинг Vercel. Версии — `docs/system/tooling.md`.
- **Граница с базой типизирована (с5):** `createClient<Database>`,
  `src/react/lib/database.types.ts` снят с прода; запрос к несуществующей
  таблице — ошибка компиляции.
- **Бандл (с8):** вендор отделён — `react-vendor` 230.8 КБ + `supabase` 113.1 КБ +

  Локальная сборка требует `.env` — гейт валит build при пустых `VITE_`.

## Каноны (нарушать нельзя, не переспросив)

- **База авторитетна.** Правило, существующее только в React, не существует.
- **`main` — это прод; сливаем принятое** (подтверждённый чекпоинт, зелёные
  `npm run check` и `npm run build`). Работа идёт в ветке ради превью.
- **Схема — только миграциями.** Baseline (134 объекта, снимок 2026-08-20) +
  девять миграций после него (4 из с2 + 5 из с5) — всё в `supabase/migrations/`.
  С с5 новых миграций не было.
- **Прод открыт, необратимое объявляется — и исполняется тем же ходом** (с8, по
  слову прораба: «не проси разрешений, я доверяю»): `DELETE`/`UPDATE` по живым
  данным — запрос, число строк и способ отката текстом в том же сообщении, без
  паузы «выполню, если не остановишь». Правила из с5 в силе: каждый
  `create/replace function` — с `revoke from public, anon` и контрольной выборкой
  грантов (gotchas §3); worktree-агент срезается с `main` (gotchas §13); перед
  `git add` — проверка на воскрешённые синхронизацией файлы (gotchas §10).
- **Разрешения инструментов — allowlist в `.claude/settings.json` проекта** (с8);
  повторяющуюся команду добавлять туда, а не спрашивать каждый раз.
- **`revoke all on public.users` держится на `security definer`** —
  «починка» уронит вход всем (разбор в `03-data-model`).
- **Тексты интерфейса — только `tr(ru, uz)`**, оба языка обязательны.
- **Прогон под двумя аккаунтами обязателен** для всего про права — и он
  **по-прежнему НЕВЫПОЛНИМ**: в проде один пользователь. Долг с с5: RPC
  `update_equipment_model_and_unit` пересоздана, `/rls-verify` для неё —
  обязательство при появлении второго аккаунта. С с8 к нему добавились ветки,
  видимые только второму аккаунту: отказ прав на удалении списка, пустой каталог
  у сотрудника без строки в `public.users`.

### Волна 1 UX-аудита (с8) — что теперь иначе

- **Редактор.** Шапка липкая, в ней единственная тройка «Сохранить · Рабочий Excel ·
  С реквизитами» и строка состояния на месте eyebrow (статус списка / результат
  действия; h1 — имя списка). Высота сетки честная: `clamp(420px, 100dvh −
  var(--editor-chrome, 409px), 900px)` — **409 = нынешняя панель реквизитов; U6
  волны 2 свернёт её в полосу и сменит число на 246.** Поле количества (1…999,
  коммит на blur/Enter), «Очистить»/«Начать заново» — двухшаговое подтверждение в
  кнопке, S/N за иконкой в строке позиции. На телефоне (≤700) действия — в футере
  панели, шапка без кнопок; планшет 701–1050 — две панели рядом.
- **Реквизиты без дефолтов.** Поля стартуют пустыми; пустое имя → автоимя «Список
  21.08.2026 · 14:32» (дата мероприятия + время действия); пустые заказчик/площадка —
  `NULL` в базе и **отсутствие строки в Excel** (сетка листа переменная). «С
  реквизитами» требует трёх полей (клиентская проверка = UX: документ собирается в
  браузере, пары в базе у неё быть не может); «Рабочий Excel» и «Сохранить» — нет.
  Имя файла `2026-08-21_Имя_рабочий.xlsx` / `…_на-согласование.xlsx` — и из реестра.
  У открытого списка `beforeunload` при расхождении со снимком сохранённого.
- **Реестр и главная.** Над карточками только H1 + «Создать список» + тулбар
  (счётчик «Всего/Найдено: N» в нём); тексты переходов — «что случится → что
  делать», термины «Только модели» / «С серийными номерами»; отказ RLS на удалении
  назван своим текстом (`LIST_DELETE_FORBIDDEN`); в деталях — заказчик · площадка и
  комментарий. Плитки главной — `<article>` с растянутой ссылкой, «＋ Создать список»
  → `/lists/new`. На ≤820 над контентом полоса аккаунта (почта + «Выйти»).
- **Каталог.** Серверный фильтр по категории и подкатегории (`type`/`subtype` в
  `fetchEquipment` и в ключе кэша; справочник `equipment-taxonomy:v2` с
  `subtypesByType`, батчами по 1000); счётчик «Позиций в базе / Найдено» в тулбаре;
  статус «На складе» (не «свободно на дату»); колонка «Локация» и `EQ-код` из строки
  ушли (в drawer'е есть); счётчик единиц модели без выдуманной единицы (`null` →
  «у всех единиц этой модели», число со склонением); «Добавить ещё такую же»;
  submit внизу формы на телефоне; `DataAge failed` → «Не удалось обновить · данные
  от …» (флаг — по несдвинувшейся метке кэша: при живом кэше `.catch` не срабатывает).
- **Сайдбар без декораций:** «Быстрый процесс», «Склад в рабочем режиме», шеврон
  и подпись «Текущая локация» сняты; нижний блок прижат `margin-top: auto` у `.sidebar__scope`.

### Отказоустойчивость (с6, веха 2 — закрыта целиком)

- **Границы ошибок две** (`components/AppErrorBoundary.tsx`): постраничная внутри
  `RouteBoundary` и корневая в `main.tsx` выше `BrowserRouter`. Белого экрана нет.
- **Канал диагностики** (`lib/reportAppError.ts`): единственный `console.*` проекта;
  `setErrorSink()` — шов под Sentry; сборщика в зависимостях нет.
- **Провал чанка после выкатки чинится сам** (`lib/lazyWithReload.ts`): одна
  перезагрузка на минуту; операционное правило — **не откатываться на байт-в-байт
  тот же билд**.
- **Возраст данных объявляется** (`components/DataAge.tsx`): «Обновлено N минут
  назад» / с с8 — «Не удалось обновить · данные от …» при отказе последнего запроса.

### Инфраструктура

- **Кэш `persistentCache` v4:** ключи со scope пользователя, очистка на выходе,
  поколения инвалидации, `equipment:all` (1.4 МБ) не персистится. **Формы ключей
  с8:** `equipment:{page,search,availability,type,subtype,pageSize}` (прогрев в
  `App.tsx` без полей попадает в ту же запись — дефолты `''`), `equipment-taxonomy:v2`;
  старые записи осиротели и выпадают по TTL. **Грабля:** `cachedQuery` при живой
  записи подменяет провал последним значением и резолвится — отказ сети виден только
  по несдвинувшейся метке `touchedAt`.
- **Деплой из файла:** `npm ci` + `buildCommand` в `vercel.json`; гейт env валит
  сборку без ключей. **Превью агенту снаружи недоступны** (Vercel Authentication):
  проверка по build- и runtime-логам; домен `warehouse.argomedia.uz` открыт, и в с8
  он сверен по хэшам чанков с локальной сборкой.
- **RLS включён; пять миграций с5** — все совместимы со старым клиентом; с8 схему
  не трогала.
