## Каноны (нарушать нельзя, не переспросив)

- **База авторитетна.** Права, видимость, целостность и уникальность живут в Postgres.
  Правило, существующее только в React, не существует.
- **`main` — это прод (ФАКТ, проверен в с2), но осторожный режим СНЯТ (с3).** Все 20
  последних деплоев Vercel: `target: production`, `githubCommitRef: main`. Домены —
  `warehouse.argomedia.uz`, `warehousev4.vercel.app` и branch-алиас `main`.
  Решение прораба в с3: **слияние в `main` отдельной команды не требует.** Основание
  продуктовое — внутренняя система на несколько сотрудников, внешних пользователей нет,
  откат стоит `git revert`. Осталось одно условие, и оно про содержимое: **сливаем
  принятое** — подтверждённый чекпоинт с зелёными `npm run check` и `npm run build`.
  Работа по-прежнему идёт в ветке (это дёшево и даёт превью-деплой).
- **Схема — второй источник правды.** Любое изменение фиксируется миграцией в
  `supabase/migrations/`, даже если применено кликами в дашборде. Стартовая точка —
  `00000000000000_baseline_remote_schema.sql` (снимок прода на 2026-08-20, 134 объекта).
  Он не обновляется сам: правка схемы мимо миграции делает его враньём.
  `scripts/*.sql` — **не архив**: четыре файла от 19.08 применены к проду и
  зарегистрированы как миграции (порядок `scripts/` → `migrations/`, см. `03-data-model` §2).
  Новые SQL туда всё равно не кладём.
- **Мёртвая зона: всё в `src/`, что не `src/react/`** — 173 файла легаси-Vue,
  37 636 строк. Не читать, не править, не брать образцы, не «чинить».
- **Прод открыт, необратимое объявляется (с3).** Технические барьеры сняты решением
  прораба: слияние в `main`, `execute_sql` и `apply_migration` разрешены без
  подтверждения. Взамен действует обязанность предупреждать: `DELETE`/`UPDATE`/`DROP`/
  `TRUNCATE` по живым данным агент показывает текстом ДО исполнения, с оценкой числа
  строк. `SELECT` и добавляющие миграции — свободно. Под подтверждением остались только
  платные и внешние действия (ветки Supabase, создание проектов, Edge Functions,
  `deploy_to_vercel`).
- **`revoke all on public.users` держится на `security definer`.** Авторизация цела
  ИМЕННО потому, что `private.is_app_member()` и `private.has_any_role()` объявлены
  `security definer`. «Починка» revoke уронит вход всем — разбор в `03-data-model`.
- **Тексты интерфейса — только через `tr(ru, uz)`.** Это не словарь, а функция:
  вызвал — обязан дать оба языка.
- **Прогон под двумя аккаунтами обязателен** для всего, что касается прав, ролей и
  чужих записей. Второй ПРОФИЛЬ браузера, не вторая вкладка: сессия живёт в
  `localStorage` и вкладки делят аккаунт. **Сейчас он НЕВЫПОЛНИМ:** в проде ровно
  один пользователь, второго аккаунта не существует. Пока он не заведён,
  `/rls-verify` не запускается, а с ним заблокированы все задачи про права.

### Продукт

- **Каталог оборудования:** поиск с дебаунсом, фильтры, постраничная загрузка,
  префетч следующей страницы, превью-drawer по клику на строку. Клик по строке
  открывает превью, добавление — отдельной кнопкой (сделано по фидбеку аудита:
  случайное нажатие меняло список).
- **Создание оборудования** работает; серийные и количественные позиции различаются.
- **Редактор списка:** два режима — «по единицам» (`specific`, серийные) и
  «по количеству» (абстрактный). Смешанный список сохраняет реальные `equipment_id`,
  а не превращается в абстрактный план.
- **Жизненный цикл списка** `draft → confirmed → issued → returned` с историей этапов
  и историей движения. **Переходы проверяются СЕРВЕРОМ** — клиентские гварды здесь
  дублируют серверные, а не подменяют их.
- **Экспорт в Excel** — самописный ZIP (метод store, ручной CRC32) и OOXML строками,
  без внешних библиотек.
- **Два языка** ru / uz, переключатель в сайдбаре, язык в `localStorage`.
- **Вход** через Supabase Auth; все шесть маршрутов за гейтом сессии.

### Инфраструктура

- **Кэш `persistentCache`** с TTL: страницы оборудования и списков — 10 минут,
  справочник категорий — 24 часа; после записи соответствующий кэш сбрасывается.
  При сетевой ошибке отдаёт старое значение — см. долги, это же и риск.
- **Ленивая загрузка всех шести маршрутов** + три отложенных прогревочных таймера
  в `AppShell` (модули, данные, данные редактора). Основной бандл ≈354 КБ
  (109 КБ gzip) по замеру аудита 19.08.
- **RLS включён** на рабочих таблицах; индексы под внешние ключи добавлены,
  `search_path` у четырёх trigger-функций зафиксирован (аудит 19.08).
- **`vercel.json`:** immutable-кэш на год для `/assets/` и `/equipment-images/`,
  неделя для `/brand/` и `/illustrations/`, security-заголовки, SPA-рерайт.
- **Фото оборудования:** 176 WebP из 217 моделей; для 41 — категорийная пиктограмма.
  Контракт именования задаёт `EquipmentVisual`.

## В процессе / долги

Полный список — `backlog.md`. Здесь то, что меняет планирование.

- **`baseline.sql` ни разу не исполнялся.** Полнота доказана машинной сверкой имён
  (134 из 134), синтаксис и идемпотентность — нет: прогона на чистой базе не было.
  Файл, который не запускается, даёт ложное чувство, что схема восстановима.
- **Инструмента применения SQL в репозитории нет:** ни `supabase/config.toml`, ни
  пакета `supabase`, ни CI. Миграции гоняются вручную — через дашборд или MCP.
- **Пять расхождений схемы с репозиторием**, найденных выпиской с2: `serialnumber`
  объявлен `not null` против nullable в TS · `public.users.id` не связан с `auth.users`
  внешним ключом · удаление списков захардкожено на почтовый адрес вместо роли ·
  дубль FK и четыре триггера пересчёта на `mount_points` · GIN-индекс полнотекстового
  поиска не используется ни одним запросом. Разбор с якорями — `03-data-model`,
  раздел «Расхождения схемы с репозиторием».
- **Отказоустойчивости нет.** ErrorBoundary в проекте отсутствует, все страницы —
  через `React.lazy`, `RouteBoundary` это только `Suspense` без catch. Выкатка нового
  билда при открытой вкладке → старые чанки исчезли → SPA-рерайт отдаёт HTML вместо
  JS → **белый экран всего приложения**. Плюс: ни одного `console.*` во всём
  `src/react`, сборщика ошибок нет — отказ у пользователя невидим. Плюс: офлайн не
  отслеживается, а кэш молча отдаёт старое.
- **Legacy-фолбэк списков срабатывает на ЛЮБОЙ ошибке**, без фильтра по коду (соседние
  функции гейтятся по `PGRST202/42883/PGRST205/42P01`). Сетевой сбой или 401 → все
  списки становятся «черновиками», выданные прячутся, **и это кэшируется на 10 минут.**
  Две копии кода.
- **Шесть дыр «клиенту не верим»** — перечень с якорями в `02-features`, раздел
  «Где клиент решает за базу». Самая дорогая: сервер пишет brand/model дословно из
  клиентского JSON, а дефицит считается джойном склада по этому тексту. Самая
  коварная: проверка уникальности серийного номера обёрнута в `try/catch`, где
  `catch` возвращает «дубля нет» — она отваливается при любом сбое запроса, а не
  только в гонке. Отдельно зафиксировано, что переходы статусов списка — НЕ дыра:
  клиентские гварды там дублируются серверными проверками.
- **Автоматических гейтов только два** — `tsc -b` и `vite build`. Линтера, тестов
  и CI нет; `.eslintrc.json` и `vitest.config.js` снесены в с1 как конфиги-призраки
  от Vue-стека. `.prettierrc` НЕ призрак — его настройки совпадают с фактическим
  стилем кода, это действующая конвенция без гейта.
- **Расхождение Node:** `engines.node` = 22.x, на машине 24.18.0. Локальная сборка
  не доказывает прод-сборку.
- **Безопасность прода не готова к внешнему запуску:** защита от скомпрометированных
  паролей отключена, MFA нестрогая, пароль из шести нулей, доступно обновление
  Postgres с исправлениями безопасности. Годится для закрытого теста, не для публики.
- **11 повторяющихся нормализованных серийников** — автоматически не чинятся,
  нужна физическая сверка наклеек.
- **Доступность:** фокус-ловушки в drawer'ах нет, фокус не возвращается на источник;
  `AppSelect` объявляет контракт listbox, но не выполняет его; `aria-live` нет нигде,
  кроме логина.
- **`styles.css` 889 строк** — единственный файл за порогом ~800.
- **`README.md` уличён во лжи**, `AUDIT-2026-08-19.md` построчно не проверялся и
  дублирует роли current-state и backlog — судьбу обоих решать.
- **Не прочитано полностью:** `xlsxExport.ts` (экранирование пользовательского текста
  в XML), тело RPC `create_equipment_list_document`, DML-часть большого SQL-скрипта

## Очередь целей (топ-3)

Прораб объявит задачу следующей сессии сам — очередь ниже: предложение агента.
Обоснование порядка — цена отказа, не бизнес-ценность (`decisions.md`, с1).

   `ErrorBoundary` нет вообще — каждая выкатка при открытой вкладке сотрудника даёт
   белый экран. Начинать с Plan Mode.
2. **Закрыть дыры «клиенту не верим»** (веха 3), начиная с brand/model: сервер должен
   брать их из `equipment` по `equipment_id`, а не из клиентского JSON.
3. **Убедиться, что `baseline.sql` исполняется** — прогон на чистой базе (локальный
   стек, ветка Supabase или проект-песочница). Полнота доказана, работоспособность нет.

Одно маленькое дело вне очереди, разблокирующее целый класс задач: **завести второй
аккаунт в проде** — без него `/rls-verify` мёртв, а с ним заблокировано всё про права.

Второе такое дело закрыто в с3: права агента перенастроены — git-операции, `execute_sql`
и `apply_migration` больше не требуют подтверждения (`.claude/settings.local.json`,
файл локальный и вне git).
