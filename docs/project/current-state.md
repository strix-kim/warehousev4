## Каноны

- **База авторитетна.** Правило только в React — не существует.
- **`main` — прод; сливаем принятое** с зелёными `npm run check` и `npm run build`.
- **`git branch --show-current` ПЕРЕД `git add`** (с11) и **`git status` на двойники
  iCloud перед КАЖДЫМ `git add`** (с15, с17: двойники приходят и в НОВЫЕ каталоги).
- **Схема — только миграциями.** Код в прод раньше схемы; смена типа возврата
  функции — `drop` + `create`, гранты заново.
- **Сотрудники: уникальность — по документам** (с17): UNIQUE по ПИНФЛ и паре
  серия+номер (нормализует BEFORE-триггер), тёзки с одной датой рождения легальны —
  форма предупреждает, база пропускает. NOT NULL только фамилия/имя — данные
  добиваются постепенно редактированием.
- **Файлы сотрудников: только добавление** (с17): DELETE в бакете и в
  `employee_files` не дан никому (у бакета политик UPDATE/DELETE нет, у таблицы
  нет гранта); прямой `delete from storage.objects` мостом запрещён самим
  Supabase — только Storage API (временная политика при нужде).
- **Signed URL не кэшируется дольше сессии** (с17): в `persistentCache` протухшая
  ссылка стала бы «фактом»; только in-memory, TTL час, запас 5 минут.
- **Фото ужимает клиент до 1600px** (с17), сканы документов — как есть.
- **UX проектирует агент** (мандат прораба, с17): мерило — рядовой сотрудник без
  обучения; готовые решения на приёмку, а не вопросы «как сделать».
- **Код ошибки для клиента — из класса `PT`, не 40** (с14); ошибки вставки
  разбирать по ИМЕНИ ограничения, не по коду (у employees три CHECK под 23514).
- **`.contains()` в postgrest-js смотрит на тип ЗНАЧЕНИЯ** (с14): jsonb — строкой.
- **Гонку уникальности без UNIQUE-индекса закрывает `pg_advisory_xact_lock`**
  (с15/с16, оборудование); у сотрудников гонки закрыты самими UNIQUE-индексами.
- **`CASCADE` на политике RLS — не выход** (с10).
- **Необратимое объявляется и исполняется тем же ходом.** Каждая
  `create/replace function` — с `revoke from public, anon`.
- **`revoke all on public.users` держится на `security definer`** (`03-data-model`).
- **Роли `admin` в проде НЕТ** (с15): оба аккаунта `technician`; удаление
  сотрудников/файлов недоступно никому через клиента — только мостом.
- **`reservation_start` / `reservation_end` — ДАТА МЕРОПРИЯТИЯ, не бронь.**
- **Состояние каталога — в адресе** (с11/с15); у сотрудников — `?employee=<id>`
  (открытие push, закрытие replace).
- **Каталог модельный** (с15); **серийник — опциональный атрибут** (с16);
  **переход между открытыми дроверами без повторной анимации** (с16).
- **Ячейку-константу на телефоне убирают ИЗ DOM** (с11).
- **Значения в `.or(...)` PostgREST квотируются** после `escapeLikePattern`.
- **Тексты интерфейса — только `tr(ru, uz)`.**
- **Права — прогон под двумя аккаунтами** (`/rls-verify`); RPC и Storage мостом
  не проверить (`auth.uid()` пуст) — smoke curl-ом под `rls-test` (с16/с17).
- **Порог входа в библию (с12):** только невосстановимое чтением `src/react`.
- **`security definer` в `private.*` цел** (с12).
- **Протокол с9 сокращён**; **тиры с9:** сессия — Opus (с17 шла на Fable по
  переключению прораба), Fable — `planner`, Sonnet — `scout`, код — `coder`.

## Долги

- **Приёмка глазами — четыре слоя** (см. шапку). Код принят прорабом авансом —
  его решение (с15–с17), браузерный `/rls-verify` с17 не выполнен (матрица в
  чате, curl-половина доказана).
- **Дыры «клиенту не верим» (остаток):** brand/model позиций в document-RPC из
  клиентского JSON; UNIQUE серийника оборудования нет (одиночная форма — клиентский
  ilike-чек); количество не сверяется с остатком. У сотрудников дыр этого класса
  нет — уникальность в базе с рождения.
- **Сирота в бакете** (с17): упавший insert второй ступени оставит объект без
  строки; убирать — дашбордом. Развилка: Edge Function или периодическая сверка.
- **Отказ RLS на update сотрудника неотличим от ошибки полей** (PGRST116 →
  общий текст); разбирать, когда роли реально начнут ограничивать.
- **Не-staff видит кнопки записи** — клиент не знает роли (факт А/Б библии 03);
  прятать = доставить роль на клиент (claim/RPC) — отдельное решение.
- **Живой signed URL работает у любого держателя до истечения часа** — природа
  подписанных ссылок, для внутренней системы принято (с17).
- **Схема vs репозиторий (с2):** `users.id` без FK на `auth.users`; удаление
  списков по почте вместо роли; дубль FK + четыре триггера на `mount_points`;
  неиспользуемый GIN-индекс. `baseline.sql` ни разу не исполнялся на чистой базе.
- **Auth не для внешнего запуска:** пароль А из шести нулей, пароль Б в доках
  открытым текстом, защита от скомпрометированных паролей выключена.
  (Открытая регистрация — закрыта в с17.)
- **Доступность:** фокус-ловушек в drawer'ах нет (видов уже ЧЕТЫРЕ: единица,
  модель, списки, сотрудник); `AppSelect` не выполняет контракт listbox.
- **`styles.css` 1037 и `ListEditorPage.tsx` 813 — за порогом**; кандидаты — в
  `backlog.md`.
- Строка «Черновик · сохранён …» после перезагрузки показывает время создания.
- Экспорта в дровере деталей нет (R-F9); глубокие ссылки `?item=`/`?mbrand=`
  живьём не проверены (с15).
- `features/` в корне — untracked каталог прораба (xlsx/docx, источник импорта
  с17); `.gitignore` или унести.
- Мёртвые метки `issued`/`returned` в журнале движений; триггер журнала не пишет
  INSERT единицы (с16).
