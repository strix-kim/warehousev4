собрать список, сохранить, скачать документ.

## Каноны

- **База авторитетна.** Правило только в React — не существует.
- **`main` — прод; сливаем принятое** с зелёными `npm run check` и `npm run build`.
- **`git branch --show-current` ПЕРЕД `git add`** (с11) и **`git status` на двойники
  iCloud перед КАЖДЫМ `git add`** (с15: трижды за сессию).
- **Схема — только миграциями.**
- **Код в прод раньше схемы.** В том числе при смене ФОРМАТА ответа RPC: клиент,
  понимающий оба формата, едет первым (с15). Смена типа возврата функции —
  `drop` + `create`, гранты заново.
- **Код ошибки для клиента — из класса `PT`, не 40** (с14): `PT409` = 409 Conflict;
  `40001` для PostgREST — команда «повтори транзакцию» и бесконечный цикл.
- **`.contains()` в postgrest-js смотрит на тип ЗНАЧЕНИЯ** (с14): jsonb передают
  строкой `JSON.stringify`, иначе `{[object Object]}` и 400.
- **Гонку уникальности без UNIQUE-индекса закрывает `pg_advisory_xact_lock`
  по нормализованному значению, локи берутся отсортированно** (с15, партия
  серийников) — иначе два конкурента с пересечением ловят deadlock. Для «+N без
  номера» лок берётся по паре бренд/модель, неймспейс `equipment-model:` (с16).
- **`CASCADE` на политике RLS — не выход** (с10): зависимую политику пересоздают явно.
- **Необратимое объявляется и исполняется тем же ходом:** запрос, число строк,
  откат текстом. Каждая `create/replace function` — с `revoke from public, anon`.
- **`revoke all on public.users` держится на `security definer`** — «починка»
  уронит вход всем (`03-data-model`).
- **Роли `admin` в проде НЕТ** (с15): оба аккаунта `technician`; удаление списков
  держится на почте `argo@argomedia.uz`, удаление единиц оборудования недоступно
  через клиента никому — только мостом.
- **`reservation_start` / `reservation_end` — это ДАТА МЕРОПРИЯТИЯ, не бронь.**
- **Состояние каталога — в адресе** (с11): `q`, `type`, `subtype`, `status`, `page`,
  `item`, с с15 ещё `mbrand`/`mmodel` (открытая модель; два параметра, не склейка).
  Прогретый первый кадр — только для нетронутого каталога.
- **Каталог модельный** (с15): строка выдачи — модель, единицы — дровером модели,
  на экране в каждый момент один дровер (модели ИЛИ единицы), «назад» шагает
  карточка → модель → каталог. Поиск по серийнику находит МОДЕЛЬ.
- **Серийник — опциональный атрибут единицы, не её заголовок** (с16, решение
  прораба): дровер модели показывает информацию об оборудовании сразу,
  количественные записи — «N шт. без серийного номера», «+1 единица» добавляется
  из дровера модели с номером или без (`add_equipment_unit`, образец копирует
  сервер — см. библию 03 §5).
- **Переход между двумя ОТКРЫТЫМИ дроверами не играет анимацию появления** (с16):
  класс `drawer-layer--instant`, проп `instant` замораживается на маунте — иначе
  поздний ререндер родителя перезапускает анимацию.
- **Ячейку-константу на телефоне убирают ИЗ DOM, а не прячут `display: none`** (с11).
- **Значения в `.or(...)` PostgREST квотируются** (`quoteFilterValue`) ПОСЛЕ
  `escapeLikePattern`.
- **Тексты интерфейса — только `tr(ru, uz)`.**
- **Права — прогон под двумя аккаунтами** (`/rls-verify`); выполним: второй аккаунт
  живёт в проде, матрица и процедура — handoff с15. RPC мостом не проверить
  (`auth.uid()` пуст) — smoke идёт curl-ом через PostgREST под `rls-test` (с16).
- **Порог входа в библию (с12):** только то, что нельзя восстановить чтением
  `src/react`.
- **`security definer` в `private.*` цел** (с12): не менять владельцев, не включать
  `force row level security`.
- **Протокол с9 сокращён** (`workflow.md`): мост на старте не проверяем,
  `decisions.md` заморожен, handoff без списков файлов.
- **Тиры с9:** сессия — Opus, Fable — только `planner` по вызову, Sonnet — `scout`.

## Долги

- **Приёмка глазами — три слоя:** (а) блоки 4–5 чеклиста с10–с13 — широкий экран
  (30–32) и телефон 390 (33–45) + уборка тестовых списков (46);
  (б) `acceptance-s15-wave3.md` — U34-L, U29, тексты отказов rls-сценариев;
  (в) сессия 16 целиком — дровер модели, «+1 единица», анимация перехода.
  Код принят прорабом авансом — его решение (с15, с16).
- **Регистрация в Auth открыта всем** (`disable_signup: false`) — мусорные
  пользователи в `auth.users` доступны любому со знанием публикуемого ключа
  (членство это не даёт). Закрыть галочкой после заведения сотрудников (backlog).
- **Дыры «клиенту не верим» (остаток):** brand/model позиций в document-RPC
  по-прежнему из клиентского JSON (append с15 и `add_equipment_unit` с16 уже
  берут из базы); UNIQUE серийника нет — партия и «+1 из модели» закрыты
  advisory-локом, одиночное заведение ЧЕРЕЗ ФОРМУ по-прежнему держит клиентский
  ilike-чек; количество не сверяется с остатком.
- **Схема vs репозиторий (с2):** `users.id` без FK на `auth.users`; удаление
  списков по почте вместо роли (единственный «админский» рычаг — роли admin нет
  ни у кого); дубль FK + четыре триггера на `mount_points`; неиспользуемый
  GIN-индекс. `baseline.sql` ни разу не исполнялся на чистой базе.
- **Auth не для внешнего запуска:** пароль А из шести нулей, пароль Б назван в
  доках открытым текстом, защита от скомпрометированных паролей выключена.
- **Доступность:** фокус-ловушек в drawer'ах нет (их ТРИ вида: единица, модель,
  списки); `AppSelect` не выполняет контракт listbox; `aria-live` местами.
- **`styles.css` 1018 и `ListEditorPage.tsx` 813 — за порогом**; `EquipmentPage.tsx`
  605 и растёт. Кандидаты распила — строками в `backlog.md`.
- **Сокращённую библию прораб не читал** (с12).
- Строка «Черновик · сохранён …» после перезагрузки показывает время создания.
- Экспорта в дровере деталей нет (R-F9).
- Глубокая ссылка `?item=<id>` ходит через `fetchEquipmentByIds` всегда
  (модельная выдача) — живьём после с15 не проверялась; `?mbrand/?mmodel` на
  модель вне загруженной страницы — тоже.
- `features/` в корне — untracked каталог прораба (xlsx/docx), не код;
  `.gitignore` или унести.
- Мёртвые метки `issued`/`returned` в журнале движений — строка в `backlog.md`.
- Триггер журнала движений НЕ пишет строку при INSERT единицы — только
  `quantity_changed`/`status_*` при UPDATE (заметено в с16, поведение старое).
