## Каноны

- **База авторитетна.** Правило только в React — не существует.
- **`main` — прод; сливаем принятое** с зелёными `npm run check` и `npm run build`.
- **Схема — только миграциями.**
- **Код в прод раньше схемы.** Удаляешь колонку или таблицу — сначала выкати код,
  который её не просит, дождись READY и сверь хэши бандла, и только потом миграцию.
  Обратный порядок роняет живой прод (с10).
- **`CASCADE` на политике RLS — не выход.** Таблица без INSERT-политики под RLS
  запрещает вставку ВСЕМ; зависимую политику пересоздают явно (с10).
- **Необратимое объявляется и исполняется тем же ходом:** `DELETE`/`UPDATE` по
  живым данным — запрос, число строк, откат текстом, без паузы. Каждая
  `create/replace function` — с `revoke from public, anon` (gotchas §3).
- **`revoke all on public.users` держится на `security definer`** — «починка»
  уронит вход всем (`03-data-model`).
- **`reservation_start` / `reservation_end` — это ДАТА МЕРОПРИЯТИЯ, не бронь.**
  Имя осталось от удалённой подсистемы; на этих колонках стоят карточка реестра и
  фильтр периода. Не чистить «за компанию».
- **Значения в `.or(...)` PostgREST квотируются** (`quoteFilterValue`), и только
  ПОСЛЕ `escapeLikePattern`. Порядок слоёв некоммутативен.
- **Тексты интерфейса — только `tr(ru, uz)`.**
- **Права — прогон под двумя аккаунтами** (`/rls-verify`); пока **невыполним**:
  аккаунт один.
- **Протокол с9 сокращён** (`workflow.md`, шапка): мост и окружение на старте не
  проверяем, `decisions.md` заморожен, handoff без списков файлов, библия без
  номеров строк, current-state без журнала.
- **Тиры с9:** сессия — Opus (`"model": "opus"` в проектном `settings.json`),
  Fable — только `planner` по вызову, Sonnet — `scout`. Раздел «Тиры моделей»
  `CLAUDE.md` — источник правды; называть раскладку перед воркфлоу.

## Долги

- **Весь UI с10 выкачен в прод НЕПРОВЕРЕННЫМ глазами** — приёмка выдана авансом.
  Первым делом следующей сессии: чеклист из handoff с10.
- **5 тестовых списков в проде** (`ТЕСТ-с10-*`) — оставлены, чтобы было на чём
  проверять поиск и период. Удалить после приёмки:
  `delete from equipment_lists where name like 'ТЕСТ-с10%' or name like 'ТЕСТ_с10%'`.
- **Второй аккаунт в проде** — блокирует `/rls-verify` пересозданной RPC
  `update_equipment_model_and_unit` (с5), **пересозданной INSERT-политики
  `equipment_lists` (с10)**, волну 3 UX и ветки с8, видимые только второму
  аккаунту (отказ прав на удалении, пустой каталог без строки в `users`).
- **Дыры «клиенту не верим» (серверная часть):** brand/model позиций не сверяются с
  оборудованием; UNIQUE серийника нет. (Пункт про сверку количества с остатком снят
  в с10 вместе с выдачей — сверять больше нечего.)
- **Схема vs репозиторий (с2):** `users.id` без FK на `auth.users`; удаление списков
  по почте вместо роли; дубль FK + четыре триггера на `mount_points`; неиспользуемый
  GIN-индекс. `baseline.sql` ни разу не исполнялся на чистой базе.
- **Auth не для внешнего запуска:** пароль из шести нулей, защита от
  скомпрометированных паролей выключена (ждёт обновления Postgres).
- **Доступность:** фокус-ловушек в drawer'ах нет; `AppSelect` не выполняет контракт
  listbox; `aria-live` только на логине и в строке состояния редактора.
- **`styles.css` 888 строк за порогом** — распил чистым переносом.
- **Чеклисты приёмки с5/с6 по проду прораб не прогонял** (ссылки на артефакты —
  в хэндоффах с5/с6).
- `features/` в корне — чужой untracked каталог прораба; `.gitignore` или унести.
- Строка «Черновик · сохранён …» после перезагрузки показывает время создания
  (`updated_at` не в выборке списка).
- Экспорта в дровере деталей нет (R-F9): скачивание только с карточки.
