## Курс

**ARGO Warehouse** — внутренняя система учёта AV-оборудования ARGO Media.
Сотрудник собирает список оборудования на мероприятие, сохраняет и выгружает
Excel. Всё остальное подчинено этому сценарию.

- **Репозиторий:** `github.com/strix-kim/warehousev4`, ветка `main`. **Публичный.**
- **Весь живой код — `src/react`: 36 файлов, 6 748 строк** (после распилов с5;
  файлов за порогом ~800 строк нет, ближайший — `ListEditorPage.tsx`, 668).
- **Стек:** React 19 + TypeScript 5.9 + Vite 7 + Supabase (Postgres/Auth/Data API),
  хостинг Vercel. Версии — `docs/system/tooling.md`.
- **Граница с базой типизирована (с5):** `createClient<Database>`,
  `src/react/lib/database.types.ts` снят с прода; запрос к несуществующей
  таблице — ошибка компиляции.
- **Бандл (с5):** вендор отделён — `react-vendor` 230.8 КБ + `supabase` 113.1 КБ +
  собственный `index` **17.75 КБ (6.8 gzip)**; правка UI стоит пользователям
  5.6 КБ gzip перекачки вместо прежних 110. Sourcemaps собираются.
- **Локальный запуск:** `npm run dev` → `http://localhost:5180/` (strictPort).
  Локальная сборка теперь требует `.env` — гейт валит build при пустых `VITE_`.
- **Данные прода на 2026-08-20:** `equipment` — 1481, `equipment_movements` — 1391,
  `events` — 4, `mount_points` — 9, `users` — 1/1. Сохранённых списков — 0,
  аккаунт ровно один.

## Каноны (нарушать нельзя, не переспросив)

- **База авторитетна.** Правило, существующее только в React, не существует.
- **`main` — это прод; сливаем принятое** (подтверждённый чекпоинт, зелёные
  `npm run check` и `npm run build`). Работа идёт в ветке ради превью.
- **Схема — только миграциями.** Baseline (134 объекта, снимок 2026-08-20) +
  девять миграций после него (4 из с2 + 5 из с5) — всё в `supabase/migrations/`.
- **Прод открыт, необратимое объявляется:** `DELETE`/`UPDATE`/`DROP`/`TRUNCATE`
  по живым данным — текстом ДО исполнения. Новые правила из с5 (оплачены):
  каждый `create/replace function` — с явным `revoke from public, anon` и
  контрольной выборкой грантов (gotchas §3); worktree-агент срезается с `main`,
  а не с ветки — сверять базу до ревью (gotchas §13); перед `git add -A` —
  проверка на воскрешённые синхронизацией файлы (gotchas §10).
- **`revoke all on public.users` держится на `security definer`** —
  «починка» уронит вход всем (разбор в `03-data-model`).
- **Тексты интерфейса — только `tr(ru, uz)`**, оба языка обязательны.
- **Прогон под двумя аккаунтами обязателен** для всего про права — и он
  **по-прежнему НЕВЫПОЛНИМ**: в проде один пользователь. С с5 долг подорожал:
  RPC `update_equipment_model_and_unit` пересоздана (проверка роли сохранена
  дословно, сверено по живому телу), и `/rls-verify` для неё — обязательство
  при появлении второго аккаунта.

## Работает

Механики поимённо — `02-features`, схема и права — `03-data-model`, провода —
`04-architecture`. Здесь — то, что изменилось в с5, и то, о чём легко забыть.

### Продукт (новое/изменённое в с5)

- **Повторное «Сохранить» больше не плодит списки:** после создания редактор
  переходит на `/lists/<id>/edit`, источник правды — URL.
- **Списки: поиск/фильтр/пагинация серверные** (12/6 на страницу); «после 50-го
  списка ничего не найти» больше невозможно. Поиск — по названию.
- **Черновик `/lists/new` автосохраняется** (24 ч, scope пользователя) и
  восстанавливается с плашкой; F5 больше не теряет 40 позиций.
- **Карточка оборудования:** обязательная «Локация *», число задетых единиц из
  ответа базы, перечитывание при открытии, **оптимистическая блокировка** —
  конфликт версий (40001) предупреждает и не стирает ввод; правка описания
  серийной карточки больше не пишет фантомное движение.
- **Выборка редактора живёт на ключах групп** — свежие остатки каталога доезжают
  до панели и payload; позиция, исчезнувшая из каталога, помечается и уходит
  planned.
- **Отказы честные:** проверка дубля серийника при сбое блокирует (не разрешает);
  сетевой сбой/401 не превращает списки в черновики; логин различает «неверный
  пароль» и «приложение не настроено»; смена языка не делает сетевых запросов.

### Инфраструктура

- **Кэш `persistentCache` v4:** ключи со scope пользователя, очистка на выходе,
  TTL честный и на первом кадре, auth-ошибки пробрасываются, поколения
  инвалидации, `equipment:all` (1.4 МБ) не персистится. Возраст записи
  (`touchedAt`) лежит в каждой записи — заготовка индикатора для вехи 2.
- **Деплой из файла:** `npm ci` + `buildCommand` в `vercel.json`, дашборд больше
  не источник; гейт env валит сборку без ключей (поймал в бою: у Preview-окружения
  переменных не было никогда — включены прорабом в с5). Пропавший чанк — честный
  404; `/brand/`, `/illustrations/` пока под рерайтом (backlog).
- **RLS включён; пять миграций с5** — оборона локации, счётная RPC (+ отзыв
  `anon`), индекс `lower(btrim(brand)),lower(btrim(model))`, оптимистическая
  блокировка. Все совместимы со старым клиентом.
- **`styles.css` 779 строк:** мёртвые классы снесены с доказательствами,
  readability-хвост схлопнут с машинной сверкой каскада; каждое правило объявлено
  один раз.

## В процессе / долги

Полный список — `backlog.md` (раздел «Найдено в с5» — 15 свежих пунктов).
Здесь то, что меняет планирование.

- **Прораб не прогонял с5 руками.** Работа принята с формулировкой «что можем —
  сам протестирую»; чеклист приёмки действителен для прода. Главный сценарий
  (`/lists/new` → сохранить → поправить → сохранить → один список) человеческим
  кликом не проверен ни разу.
- **Отказоустойчивость (веха 2) — теперь узкое место №1.** ErrorBoundary нет,
  провал чанка = белый экран, канала ошибок нет, возраст кэша не показывается.
  С5 подготовил почву: честный 404 на чанк, `touchedAt` в кэше, sourcemaps.
  Принятый риск «immutable на 404» закрывается именно здесь (обработчик провала
  чанка с перезагрузкой).
- **Дыры «клиенту не верим» (серверная часть):** сервер не сверяет brand/model
  позиций с оборудованием; UNIQUE серийника нет (клиент починен в с5, но гонку
  двух вкладок держит только он; индекс — после физической сверки 11 дублей);
  количество не сверяется с остатком до `issued`.
- **`/rls-verify` невыполним** (один аккаунт) — блокирует приёмку пересозданной
  RPC и все задачи про права.
- **`baseline.sql` ни разу не исполнялся** на чистой базе (с2).
- **Пять расхождений схемы с репозиторием (с2) → осталось четыре:** typов-
  расхождение закрыто генерацией; открыты: `users.id` без FK на `auth.users`,
  удаление списков по почте вместо роли, дубль FK + четыре триггера на
  `mount_points`, неиспользуемый GIN-индекс поиска.
- **Node 24 локально против engines 22.x** — прод-сборку доказывает Vercel, не
  локальный build.
- **Безопасность Auth не для внешнего запуска:** пароль из шести нулей, защита от
  скомпрометированных паролей выключена, ждёт обновление Postgres.
- **Доступность:** фокус-ловушек в drawer'ах нет; `AppSelect` не выполняет контракт
  listbox; `aria-live` только на логине.

## Очередь целей (топ-3)

1. **Веха 2 — приложение перестаёт падать молча:** ErrorBoundary + обработчик
   провала чанка (закрывает принятый риск immutable-404) + канал ошибок +
   индикатор возраста кэша. Дважды перебивалась (с4 — чисткой, с5 — аудитом),
   не отменена; теперь ей ничего не мешает. **Почему первой:** единственный
   класс отказов, который до сих пор кладёт всё приложение молча.
2. **Дыры «клиенту не верим», серверная часть (веха 3):** триггер/констрейнт на
   brand/model из `equipment`, UNIQUE серийника (после сверки наклеек), сверка
   количества с остатком. Всё — миграции, `/rls-verify` обязателен → зависит от
   второго аккаунта.
3. **Второй аккаунт в проде + первый настоящий `/rls-verify`:** разблокирует
   веху 3, закрывает обязательство по пересозданной RPC и открывает дырам кэша
   (уже починенным в с5) живую проверку. Пять минут дашборда + прогон по скиллу.

Вне очереди, перед любым кодом: **прораб проходит чеклист приёмки с5 руками** —
и **`/doc-audit` в начале с6** (рубеж наступил).
