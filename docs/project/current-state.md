мероприятие + Excel. Расширение: сотрудники (с17), автомобили (с18), экспорт
«на мероприятие» (с19), распределение по залам (с20–с22). **Текущая фаза: три новых

  `styles.css` 1141, `database.types.ts` 1057 (генерируется + правки руками, не

  Пять рантайм-зависимостей, ни одного файла шрифта, ни UI-кита, ни state-менеджера,

## Каноны

- **База авторитетна.** Правило только в React — не существует.
- **`main` — прод; сливаем принятое** с зелёными `npm run check` и `npm run build`.
- **Тиры (с18): ведущего выбирает прораб**; код — `coder` (Opus), планы —
  `planner` (Fable), механика — `scout` (Sonnet). Раскладку называть перед
  воркфлоу.
- **Разделение проверок (с24, уточнение правила прораба):** механический прогон —
  работа агента через Playwright (тот же лист печати, ширина 390, консоль,
  контраст числом); вкусовая приёмка «красиво/понятно» — по-прежнему прораб.
- **Проверка без контроля чувствительности не проверка (с24).** Прежде чем верить
  «совпало», сломай образец нарочно и убедись, что метод это видит: сравнение
  потоков PDF через `get_contents()` давало «идентично» на заведомо разных файлах,
  потому что хешировалась пустота.
- **Цвет зала живёт в БАЗЕ (с24).** Правка `HALL_PALETTE` красит только НОВЫЕ
  залы; существующие планы перекрашиваются свотчами вручную. Любая правка палитры
  заканчивается вопросом «а живые планы?», иначе поломка остаётся на экране.
- **Аудит отвечает на тот вопрос, который ему задали (с23).** «Что нарушено» и
  «как сделать лучше» — разные жанры, и второй не содержится в первом. Формулировку
  прораба «сделать UI продакшн-уровня» читать вслух ДО запуска: список дефектов или
  предложение облика?
- **Перф-находку без объёма данных не принимать (с23).** Скептик со свежим чтением
  прода снял 18 находок из 20.
- **Гипотеза из чтения кода — не факт (с24).** `print-leak` был «обоснованной
  гипотезой» целую сессию, хотя доказательство стоило двух `Ctrl+P`.
- **Возражение агента против плана ведущего — не шум (с23).**
- **Кэш чтений — `persistentCache`, и он ЕСТЬ у equipment/lists и НЕТ у трёх новых
  модулей** (с23). Отсюда мигание на «сохранил → назад». Класс задач и порядок —
  backlog; **`fetchEmployees` кэшировать только `{ persist: false }`** (`select('*')`
  тянет паспорт, ПИНФЛ, адрес прописки — им не место в `localStorage`).
- **Кэш плана залов опасен:** список планов кэшировать можно, сам план и ТВ — нет
  (общий черновик, ТВ поллит каждые 30 с).
- **Прогон прав без второго браузера (с22):** мост read-only, `/rls-verify` гоняется
  по живому REST прода настоящим JWT второго аккаунта. Рецепт — gotchas §2.
- **`HTTP 200` + ноль строк = отказ политики,** а не успех (с22).
- **Залы — матрица (с20):** позиции — строки ВСЕГО мероприятия, залы — колонки,
  ячейка = максимум один человек ИЛИ слот «Наём» (UNIQUE `cell_key`); пустая
  ячейка и есть вакансия, слот — «решено: берём внешнего» (с21).
- **Слот «Наём» (с21):** `is_external` + CHECK «(employee_id is null) =
  is_external»; кнопка — только в операторских строках (правило в UI, backlog);
  FK на employees — `on delete cascade`.
- **Имена в расстановке — «Имя Фамилия»** (`employeeDisplayName`, с21).
- **Залы — общий черновик staff (с20/с21, подтверждено прогоном с22):** изоляции
  между staff нет по замыслу. **Один менеджер в работе (с23, прораб)** — гонок двух
  вкладок в расстановке можно не бояться.
- **ТВ `/halls/:planId/tv` (с21) — инструмент планёрки:** назначение кликом,
  структура только в редакторе; поллинг 30 с через `silentRefresh`; портал
  пикера — `fullscreenElement ?? body`.
- **Печать матрицы (с22, развязана в с24):** цвет зала — ЧЕРТА под именем; панель и
  шапка — `display: contents`; серые токены темнеют внутри `@media print`; поле
  сверху 14 мм. Проверять только по самому PDF, скриншот врёт. gotchas §14.
  **Весь блок под маркером `.hall-print` на `body`, `@page` — своей таблицей стилей:**
  правила ленивого чанка не удаляются при уходе со страницы.
- **Текст для чата (с22):** по залам, не матрицей; **без markdown** — Telegram не
  разбирает разметку во вставленном тексте.
- **`document.title` — владелец один** (`LanguageProvider`), страница называет
  себя через `useDocumentTitle` (с22). **Стоит ровно в одном месте** — три вкладки
  подписаны одинаково (с23, долг).
- **Директор не назначается на залы** (с21).
- **Safari: кнопка с `autoFocus` + `onBlur`-гашением обязана иметь
  `onMouseDown preventDefault`** (с21, gotchas §6).
- **Двухшаговые кнопки (`useArmedAction`) держат взвод 4 секунды** (с24) — в
  агентском прогоне жать двойным кликом, иначе взвод истекает между вызовами.
- **Справочник позиций (с20):** общий на всех; FK из планов НЕТ намеренно (снимок).
- **Один человек в нескольких ячейках — норма**; скрепка = несколько позиций
  в ОДНОМ зале, ×N = по всему плану.
- **Роль позиции: иконка без подписи** (с21, подтверждено для печати в с22).
- **`git branch --show-current` перед `git add`** — привычка остаётся.
- **Схема — только миграциями.**
- **Фото в xlsx: якорь `oneCellAnchor` + АБСОЛЮТНЫЕ координаты в `a:xfrm`** (с19/с20).
- **Фото для документов — `employees.document_photo_id`** (с19), NULL →
  последнее загруженное.
- **Язык документа ≠ язык интерфейса** (с19); **новые стили xlsx — только в хвост
  `styles.ts`** (с19); **руководитель для документов — константа `companyDirector`** (с19).
- **Госномер: канон в базе** (с18); **машина↔водитель — M2M** (с18);
  **сотрудники: уникальность по документам** (с17); **файлы — только добавление** (с17/с18).
- **Signed URL — только in-memory кэш** (с17); **фото ужимает клиент** (с17).
- **UX проектирует агент** (с17) — **включая визуальную концепцию (с23)**;
  **образец «как делаете сейчас» выпрашивать ДО проектирования** (с20).
- **Пачечный upsert/insert под RLS — `defaultToNull: false`** (с18).
- **Ошибки вставки разбирать по ИМЕНИ ограничения** (с14), код клиенту — из
  класса `PT` (с14); `.contains()` — тип значения (с14).
- **Состояние каталога — в адресе** (с11/с15); каталог модельный (с15);
  серийник опционален (с16).
- **Тексты интерфейса — только `tr(ru, uz)`.**
- **Права — `/rls-verify`;** RPC и Storage — smoke curl-ом.
- **Порог входа в библию (с12):** только невосстановимое чтением `src/react`.
- **`security definer` в `private.*` цел** (с12); `revoke from public, anon` на
  каждой новой функции. **Роли `admin` в проде НЕТ** (с15).
- **`reservation_start`/`reservation_end` — дата мероприятия, не бронь.**

## Очередь целей (топ-3)

1. **Визуальная концепция трёх новых модулей** — проектный заход, не дефектный:
   как выглядят экраны, если рисовать заново, оставаясь в пяти зависимостях и без
   UI-кита. Карточки или таблицы, где иллюстрации, плотность, главная как витрина,
   ТВ как отдельный жанр. **До неё сессии 2–6 из плана аудита не начинать** —
   полировать экраны, которые концепция заменит, значит выбросить работу.
2. **Первый кадр и кэш** (сессия 7 плана аудита) — `persistentCache` трём модулям,
   `DataAge`, `{ persist: false }` на `fetchEmployees`, гейт прогрева каталога,
   предзагрузка иллюстрации только там, где она нужна.
3. **PDF-выгрузка матрицы файлом** — отложена прорабом в с23; план в общих чертах:
   jspdf ленивым импортом, кириллический TTF в репозиторий.

Ниже очереди, не выпало: **дыры «клиенту не верим» оборудования** (веха 3),
**хвосты экспорта** (backlog с19).

Плюс постоянный долг: приёмка глазами (слои с19, ТВ на экране, печать в Safari) —
прорабом.
