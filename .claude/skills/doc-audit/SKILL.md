# Доко-аудит: библия 01–03 против кода

Зачем: правило «решение трогает 01–03 → патчи страницу тем же коммитом» соблюдается
не всегда. Доки, которые врут, хуже отсутствующих: агент им верит. Ссылки на код идут
именем файла и функции, без номеров строк, — адресный дрейф исчез, остался смысловой.
Поэтому аудит не по расписанию, а по поводу.

**Главная проверка с с12 — не «верно ли написано», а «должно ли это вообще быть в
библии».** Страниц стало три, потому что 02 и 04 пересказывали код, который сам себя
комментирует, и обязаны были стареть. Порог входа: **в библию попадает только то, что
нельзя восстановить чтением `src/react`** — связки через файлы и системы, объяснение
неочевидного выбора, отсутствие чего-то. Абзац, пересказывающий компонент или список
полей, — находка аудита, даже если он верен сегодня.

## Триггеры

- Команда прораба.
- Впереди крупная веха.
- Подсистема переписана или модуль распилен — дока о ней заведомо устарела.

## Шаги

1. **Скоуп.** Последний аудит — в `docs/handoffs/` (ищи «аудит библии»). Скоуп =
   страницы, затронутые кодовыми сессиями после него (по хэндоффам).

2. **Сверка по страницам.** Для каждой страницы сравни утверждения с кодом
   (`src/react/`), миграциями (`supabase/migrations/`) и current-state:
   - `01-product` — границы продукта («чего в нём НЕТ»), масштаб данных, где живёт;
   - `02-decisions` — решения и грабли: каждое утверждение проверить **дважды** —
     верно ли оно и не выводится ли из кода. Второе важнее;
   - `03-data-model` — таблицы, колонки, связи, RLS, индексы; **по живой схеме через
     мост**, а не по baseline: он описывает стартовую точку, а не сегодня.
   Проверять по коду, не по памяти. Тиры — CLAUDE.md «Тиры моделей»: сверки — Opus
   (high), механические прогоны — `scout`.

   Отдельно — **шапка `src/react/styles.css`**: инвентарь токенов и брейкпоинтов живёт
   там комментарием, а не отдельной страницей. Сверять её с самим файлом.

3. **Призрачные ссылки** (дёшево, механически). Все `путь/файл.ts` в `docs/project/`
   и `docs/system/` сверить с деревом: файла нет → призрак. Голый `api.ts`
   неоднозначен — их два (`equipment/`, `lists/`), различай по абзацу.
   Якоря `:строка` в `.sql` миграций не трогаем — миграции не меняются.

4. **Отчёт, НЕ правки.** Таблица `страница | написано | на самом деле (файл) |
   предложение`. Расхождение может быть намеренным (история, «как будет») — молча
   не патчим. Два агента разошлись — разбери сам до прораба: часто неверна дока.

5. **Приёмка.** Прораб отмечает, что чинить. Принятое — патч страниц, один коммит
   `доки: аудит библии — сессия N`; итог — строкой в handoff сессии.

6. **Уборка backlog.** Пункты, помеченные закрытыми (~~зачёркнуто~~ / «ЗАКРЫТО» /
   `[x]`), перенеси в секцию «Архив (закрыто)» в конце файла — не удаляя и не
   переписывая; живой хвост пункта остаётся сверху отдельной строкой. Выглядит
   сделанным, но не помечен → в отчёт шага 4, не самовольная уборка.

## Грабли

- Не переписывай страницу целиком «раз уж открыл» — только принятые расхождения.
- Блоки, помеченные историей («до переписывания на React»), — не расхождения.
- Атрибуцию сессии сверяй по `git log -S`, не по комментарию в коде.
- Кириллицу не править через perl — только Edit/Write или python3.
- `AGENTS.md` ↔ `CLAUDE.md` дрейфуют — сверь парность.
- Номера строк в библию не возвращать: имя файла + имя функции, этого достаточно.
