# Чекпоинт: приёмка шага

Git = приёмка работ (правило проекта: `CLAUDE.md` / `AGENTS.md`). Коммит существует
только для ПРИНЯТОГО прорабом чекпоинта. Чекпоинт не принят → не коммитим; сломано →
предложи откат к последнему коммиту, поверх непринятого не строим.

## Предусловие

Прораб явно подтвердил чекпоинт («работает», «принято», «ок, коммить»).
Подтверждения нет → остановись и спроси, не запускай шаги ниже.

## Шаги

1. **Ветка.** Убедись, что работа НЕ в `main`:
   ```bash
   git branch --show-current
   ```
   Оказался на `main` — уведи правки в `session-N-тема` и продолжай. Ветка нужна
   ради превью-деплоя и чистой истории, а не как защита от прода: осторожный режим
   снят в с3 (workflow.md, «Прод и ветки»).

2. **Гейты** — порядок строгий, каждый следующий имеет смысл только после предыдущего:
   ```bash
   npm run check            # = tsc -b, типы
   npm run build            # tsc -b && vite build
   git diff --check         # висячие пробелы, маркеры конфликтов
   ```
   Любой упал → чиним ДО коммита. Линтера и тестов в проекте нет — это записанный
   долг, а не повод их «сымитировать»; не ссылайся на `npm run lint`/`npm test`,
   их не существует.

3. **Схема базы.** В блоке правился SQL или менялась структура данных → миграция
   обязана лежать файлом в `supabase/migrations/` и войти в ЭТОТ коммит.
   Применено кликами в дашборде — всё равно фиксируется миграцией задним числом.
   `scripts/*.sql` — исторические скрипты, новые SQL туда не кладём.

4. **Коммит.** Только файлы этого чекпоинта (никаких `git add -A` вслепую —
   в коммит уедет всё лишнее, что оказалось в дереве).
   Сообщение — короткое, русское, формата «подсистема: что сделано»
   (история проекта до харнесса писалась по-английски — с этого момента ведём
   по-русски, старое не переписываем):
   `редактор: смешанный список сохраняет реальные id`,
   `каталог: пагинация не режет выборку на 1000 строк`.

5. **Push.** `git push` СВОЕЙ ветки — свободно: Vercel сделает превью-деплой,
   прод не тронется. Push упал — локальный commit сохраняется; доложить точную
   ошибку и повторить при следующей возможности.

6. **Слияние в `main` разрешено — но только ПРИНЯТОГО.** Осторожный режим снят в с3:
   это внутренняя система на несколько сотрудников, откат стоит `git revert`.
   Отдельной команды слияние не требует. Условие одно и оно про содержимое:
   в `main` едет чекпоинт, который прораб подтвердил в браузере, с зелёными гейтами
   шага 2. Непринятое не сливаем — не из страха прода, а потому что поверх
   непринятого не строят. Слил — скажи прорабу, что выкатил, и назови коммит.

7. **Правка была в проде мимо репозитория** (клики в дашборде Supabase, настройки
   Vercel, изменение данных) → зафиксируй в handoff, что именно изменено и
   подтверждено ли. Прод — второй источник правды, git его не видит.

## Грабли

- Коммить поимённо, а не `git add -A`: в дереве заводятся `dist/`, локальные
  скрипты и черновики, и вслепую они уедут в историю.
- `npm run build` собирает ТОЛЬКО `src/react` (`tsconfig.app.json`) — файл, положенный
  мимо этого каталога, гейт молча не проверит.
- Гейт `npm run check` (= `tsc -b`) кэширует результат; сомневаешься — `npx tsc -b --force`.
- `.env` в коммит не попадает и попасть не должен (`.gitignore`); проверь
  `git status` перед add.
