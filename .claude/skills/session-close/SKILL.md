# Закрытие сессии

Правила (прод, ветки, схема) — `docs/system/workflow.md`. Здесь — последовательность.
Принцип с9: **handoff хранит только то, чего нет в git** — списки файлов, перечень
проверенного и пересказ коммитов не пишем.

## Предусловие

Команда прораба «закрываем сессию» или его согласие на твоё предложение. Триггеры
предлагать самому: цель достигнута · контекст раздулся · переключение на другую
подсистему · 2+ незакрытых бага · прораб поправляет по второму кругу.

## Шаги (порядок строгий: номер → handoff → указатель)

1. **Номер сессии.** `N` = максимальный номер в именах `docs/handoffs/YYYY-MM-DD-N-…`
   + 1. Сквозной, только растёт; старые файлы не переименовываем. Живая параллельная
   сессия рядом → кто закрывается первым, берёт меньший `N`.

2. **Handoff** — `docs/handoffs/<сегодня>-N-<краткая-цель>.md`:

   ```md
   # Handoff: YYYY-MM-DD (сессия N) — <цель сессии>

   ## Сделано            <!-- по строке на чекпоинт: хэш + суть; детали — в коммите -->
   ## НЕ проверено       <!-- честно: пропущенный /rls-verify, невыкаченная ветка, чеклист без прогона -->
   ## Вне git            <!-- схема, данные, политики Supabase, Vercel; зафиксировано ли миграцией -->
   ## Следующий шаг      <!-- одно конкретное первое действие следующей сессии -->
   ## Грабли и решения   <!-- Симптом | Причина | Решение; общее правило → gotchas.md -->
   ```

   «Почему решили X» пишется здесь же — в «Сделано» или «Граблях»; отдельного
   журнала решений с с9 нет. Изменённые файлы — `git diff --stat main..ветка`,
   проверенное — гейты; перечислять не надо.

3. **current-state.md — перезапись, не дописывание.** Числа прода, инварианты,
   долги, «Очередь целей (топ-3)» (сделанное вычеркнуть, №1 = следующая сессия;
   перебитая прорабом цель сдвигается вниз, не исчезает), строка
   «**Актуальный handoff:**» → файл из шага 2. Блок «что изменилось в сессии» не
   заводим — это журнал, его держат хэндоффы; «как устроено» — библия 01–03 и код.

4. **Библия 01–03.** Решение изменило поведение, схему, права, числа, роадмап →
   патч страницы тем же коммитом. Ссылки на код — именем файла и функции, **без
   номеров строк**. Побочные идеи и баги → строка в `docs/project/backlog.md`;
   клиентская проверка без пары в базе — обязательный кандидат (правило 2).

5. **Гейты и коммит.**
   ```bash
   git diff --check                      # всегда
   npm run check && npm run build        # только если после последнего чекпоинта трогали код
   ```
   Незакоммиченный код в хвосте — сигнал спросить прораба, принят ли он.
   Коммит `доки: закрыть сессию N — <суть>`, затем `git push` своей ветки
   (упал — не блокер, строка в handoff).

6. **Слияние в `main`** — часть закрытия, если работа принята: сливаем и пушим, не
   переспрашивая, и говорим прорабу, что выкатили, с коммитом и состоянием деплоя.
   Непринятое или красное в `main` не едет — строкой в handoff: «ветка
   `session-N-тема` не влита, ждёт приёмки».

7. **Финал.** «Можно чистить чат» (/clear). Новая сессия — со `/session-start`.

## Грабли

- Забытый указатель «Актуальный handoff» — самый дорогой промах закрытия.
- Handoff-файлы никогда не удаляем и не переименовываем.
- `docs/project/decisions.md` заморожен с с9 — не дописывать.
- Кириллицу в доках не править через perl (`perl -CSD` даёт мохибейк) — только
  Edit/Write или python3.
