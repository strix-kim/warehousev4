# Закрытие сессии

Протокол-источник: `docs/system/workflow.md` (раздел «Финиш»). Здесь — исполняемая
последовательность. Расхождение скилла и workflow.md — баг: патчи оба файла.

## Предусловие

Команда прораба «закрываем сессию» (или его согласие на твоё предложение закрыть).
Триггеры предлагать самому: цель достигнута · контекст раздулся · переключение на
другую подсистему · 2+ незакрытых бага · прораб поправляет по второму кругу.

## Шаги (порядок строгий)

1. **Номер сессии.** `N` = максимальный номер в именах `docs/handoffs/YYYY-MM-DD-N-…` + 1.
   Номер сквозной и обязан расти; старые файлы не переименовываем.
   Рядом идёт ЖИВАЯ параллельная сессия другого агента → номер не «застолблён»:
   кто закрывается первым, берёт меньший `N`. Сомневаешься — спроси прораба
   до создания файла.

2. **Handoff** — `docs/handoffs/<сегодня>-N-<краткая-цель>.md` по шаблону
   (шаблон общий для всех проектов прораба, менять его в одиночку нельзя):

   ```md
   # Handoff: YYYY-MM-DD (сессия N) — <цель сессии>

   ## Сделано
   ## Проверка            <!-- что и как проверено; чего НЕ проверяли — тоже -->
   ## Файлы               <!-- изменены / созданы / вне git: схема БД, данные, хостинг -->
   ## Состояние           <!-- работает / не работает / известные баги -->
   ## Следующий шаг       <!-- одно конкретное первое действие следующей сессии -->
   ## Грабли и решения    <!-- таблица: Симптом | Причина | Решение -->
   ```

   Честно фиксируй непроверенное (пропущенный прогон под двумя аккаунтами,
   непринятая миграция, невыкаченная ветка) — следующая сессия начнёт с этого.

3. **current-state.md — перезапись, не дописывание.** Файл — сводка «как есть
   сейчас», НЕ журнал (хроника — в хэндофах):
   - итог сессии = 2–3 строки в нужных секциях («Работает», числа, долги…);
     устаревшие утверждения заменяй, посессионный блок «Сессия N» не заводи;
     файл перерос ~450 строк → предложи прорабу ужимку. Режь СТРУКТУРУ (слияние
     буллетов, вынос деталей в библию по ссылке), а не фразы; grep ДО реза — есть
     ли факт в `01–06`/`system`/скиллах, grep ПОСЛЕ — на месте ли числовые
     инварианты и имена модулей; порог — ориентир, останов по правилу «следующая
     строка уносит факт, которого нет больше нигде». Выгоднее всего сразу после
     `/doc-audit`. Подробно — workflow.md «Финиш»;
   - «**Очередь целей (топ-3):**» — обнови: сделанное вычеркни, №1 = цель
     следующей сессии. Прораб перебил очередь другой темой — не молча заменяй:
     перебитая цель сдвигается вниз, а не исчезает;
   - строка «**Актуальный handoff:**» → путь к файлу из шага 2 (по этому
     указателю стартует следующая сессия — забыть = сломать `/session-start`).

4. **Двойная запись решений** (если в сессии были продуктовые/архитектурные решения):
   - `docs/project/decisions.md` — строка на решение (журнал, append-only);
   - решение меняет содержание страницы `docs/project/01–06` → патчим её В ТОМ ЖЕ
     коммите. decisions = «что решили», 01–06 = «как есть сейчас»; расходятся —
     библия гниёт.
   - Побочные идеи/баги, не взятые в работу → строка в `docs/project/backlog.md`.
     Найденная клиентская проверка без пары в базе — обязательный кандидат
     (правило 2 `CLAUDE.md`).

5. **Гейты и финальный коммит:**
   ```bash
   npm run check
   npm run build
   git diff --check
   ```
   Коммит всего хвоста сессии, сообщение вида `доки: закрыть сессию N — <суть>`.
   Кодовые изменения в норме уже закоммичены чекпоинтами (`/checkpoint`);
   незакоммиченный код в хвосте — сигнал спросить прораба, принят ли он.
   После коммита — `git push` СВОЕЙ ветки (remote:
   `github.com/strix-kim/warehousev4`). Push упал — не блокер: зафиксируй в handoff.

6. **Слияние в `main` — часть закрытия, если работа принята.** Осторожный режим снят
   в с3 (workflow.md, «Прод и ветки»): `main` — прод, но откат стоит `git revert`,
   а система внутренняя. Прораб принял работу сессии → сливаем и пушим `main`, не
   переспрашивая, и записываем в handoff как выкатку с номером деплоя. Что-то в
   сессии осталось НЕпринятым или гейты красные → эта часть в `main` не едет, и в
   handoff строкой: «ветка `session-N-тема` не влита, ждёт приёмки».

7. **Прод вне git.** В сессии менялась схема, данные, политики Supabase или
   настройки Vercel → перечисли это в разделе «Файлы → вне git» и скажи,
   зафиксировано ли миграцией. Незафиксированная правка схемы — долг, а не мелочь.

8. **Финал.** Скажи прорабу: «можно чистить чат» (/clear). Новая сессия начнётся
   со `/session-start`.

## Грабли

- Указатель «Актуальный handoff» в current-state забыт → следующая сессия откроет
  старый handoff и потеряет контекст. Это самый дорогой промах закрытия.
- Слияние в `main` = выкатка в прод. Спрашивать разрешение больше не нужно, но
  СКАЗАТЬ прорабу, что выкатил, и назвать коммит с состоянием деплоя — обязательно.
- Дата в имени файла — реальная сегодняшняя; порядок задаёт номер `N`, не дата.
- Handoff-файлы никогда не удаляем и не переименовываем — на них ссылается история.
- Кириллицу в доках не править через perl (`perl -CSD` даёт мохибейк) — только
  Edit/Write или python3.
