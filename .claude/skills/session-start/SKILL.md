# Старт сессии

Протокол-источник: `docs/system/workflow.md` (раздел «Старт»). Здесь — исполняемая
последовательность. Расхождение скилла и workflow.md — баг: патчи оба файла.

## Шаги

1. **Контекст из файлов.**
   - Прочитай `docs/project/current-state.md` целиком.
   - Открой handoff, указанный в строке «**Актуальный handoff:**» current-state.
     Указателя нет → возьми файл с НАИБОЛЬШИМ номером сессии `N` в имени
     (`YYYY-MM-DD-N-…`); лексической сортировке не верь (`9` > `10` при сортировке строк).
   - `docs/project/backlog.md` отсутствует → создай пустой с заголовком.
   - Строка «**Последний doc-audit:**» в current-state отстаёт от текущей сессии
     на ~5+ кодовых сессий → включи в сводку пункта 5 предложение прогнать
     `/doc-audit` (первым делом сессии или отдельной целью).

2. **Состояние репозитория.**
   ```bash
   git log -5 --format="%h %ci %s"
   git status
   git branch --show-current
   ```
   - Незакоммиченные изменения при чистом закрытии прошлой сессии — сигнал обрыва:
     переходи в режим аварийного восстановления (ниже). Исключение: правки может
     держать ЖИВАЯ параллельная сессия другого агента — спроси прораба, прежде чем
     трогать; чужие файлы не коммитим.
   - **`main` считается продом** (допущение с1, не проверено — workflow.md,
     «Прод и ветки»). Оказался на ней — скажи прорабу и предложи увести работу
     в `session-N-тема` до первой правки. Допущение всё ещё не проверено — напомни
     об этом одной строкой: проверка занимает минуту в настройках Vercel.

3. **Рабочее окружение.** Свежий клон (нет `node_modules` или `.env`) — назови это
   сразу, до согласования цели: без них ничего не запустится.
   ```bash
   ls node_modules >/dev/null 2>&1 && echo "deps: есть" || echo "deps: НЕТ (npm install)"
   test -f .env && echo "env: есть" || echo "env: НЕТ (cp .env.example .env + ключи из дашборда)"
   ```
   `.env` заполняет прораб — ключи в чат не пересказываем и в git не кладём.

4. **Мост.** Проверь, видит ли агент прод:
   - Supabase MCP → `list_projects`: есть ли среди них база склада.
   - Vercel MCP → `list_teams` + `list_projects`: есть ли среди них деплой склада.

   Проекта нет в ответе → **мост слеп**, доложи это ОДНОЙ строкой и работай по коду.
   Не притворяйся, что видишь прод, и не выдумывай его состояние — это дороже
   любого молчания. Поднять мост может только прораб (подключить нужную организацию
   Supabase и аккаунт Vercel в настройках коннекторов) — предложи, но не настаивай.

5. **Следующий шаг прошлой сессии.** В handoff есть «Следующий шаг», в
   current-state — «Очередь целей (топ-3)» (№1 = кандидат на цель этой сессии).
   Если шаг начинается с проверки («убедиться, что миграция доехала до прода») —
   выполни её сейчас и доложи результат.

6. **Цель сессии.** Сформулируй ОДНИМ предложением, проверяемо («редактор списка
   сохраняет смешанный состав», не «поработать над списками»). Предложи прорабу
   вместе с краткой сводкой пунктов 1–5. **Без согласованной цели код не пишем.**
   Прораб может перебить цель своей — это нормально, его цель приоритетна.

## Аварийное восстановление (сессия оборвалась без хэндоффа)

1. `git log -5` + `git status` + `git branch --show-current` + current-state —
   восстанови картину: что закоммичено, что висит, в какой ветке.
2. Создай короткий handoff задним числом (что удалось установить).
3. Согласуй цель заново — не продолжай старую вслепую.

## Грабли

- Handoff-указатель в current-state обновляется при закрытии сессии — если он
  указывает на несуществующий файл, доверься максимальному `N` и скажи прорабу.
- `docs/handoffs/` никогда не чистим — это история проекта.
- Первая сессия проекта (нет current-state и handoffs вообще) → предложи прогнать
  болванку `docs/system/product-doc-guide.md`, код до неё не пишем.
- `git status` покажет мёртвую зону `src/` (легаси-Vue) как обычные файлы —
  это не работа и не долг, правило 7 `CLAUDE.md`.
